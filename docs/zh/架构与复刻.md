# 架构与复刻

[English](../en/architecture.md) · [返回 README](../../README.md)

这份说明回答三件事：六层各有什么、为什么这样分；要复刻需要准备什么；缺某一层时怎么降级。

## 一、六层架构

```
┌ 模型层 ─────── Claude Code 主理 │ DSH / Codex 执行（可选）│ Gemini 等证伪（可选）
├ 编排层 ─────── dsh_task.js 派工 │ Claude 子代理 │ 清单→执行→回读
├ 工具接入层 ─── Unity MCP │ Blender MCP │ agy MCP │ 编辑器脚本 │ Python/Blender 脚本
├ 知识层 ─────── SOP：总表 → 阶段页 → 子页 │ 工具索引 │ 工具链基准
├ 闸口层 ─────── Claude Code 钩子 ×4 │ git pre-commit
└ 记录与自学习层  施工记录＋状态头 │ ws_git │ 派工流水账 │ 待蒸馏标签 → 收尾蒸馏
```

### 1. 模型层

| 角色 | 默认 | 职责 |
|---|---|---|
| 主理 | Claude Code | 流程把控、审美评估、复杂兜底、维护 SOP、迭代执行代理、验收 |
| 执行 | DSH（DeepSeek Harness）/ Codex CLI，可选 | 改工程、写分析脚本、跑构建与测试、清点素材 |
| 证伪 | agy（Antigravity CLI，调 Gemini 等）；DeepSeek 视觉，可选 | 对主理的结论做反向评审 |

**为什么这样分**：主理额度最贵，而且会被自己的上下文锚定——复述过的结论越复述越确信。执行交给便宜的模型，结论交给另一条订阅池、另一家模型去挑错。代价不对称：派错了多花几分钟，不派则烧掉主理额度。详见 [DSH派工](../../开发工具/SOP/01_自动化执行与并行/DSH派工.md)、[Codex派工](../../开发工具/SOP/01_自动化执行与并行/Codex派工.md)、[05 · 多模型评审规程](../../开发工具/SOP/05_多模型评审规程.md)。

### 2. 编排层

| 组件 | 路径 | 作用 |
|---|---|---|
| 派工脚本 | `开发工具/通用工具/dsh_task.js` | 一个入口派 DSH 或 Codex（`--engine auto` 按时段选）；`--lock unity|blender` 交接编辑器；`--record <工程>` 让执行代理自己写施工记录并提交；派工前后跑 `--snapshot-cmd` 比对；事后从会话日志核验它到底做了什么（例：带图任务核对 `read_image` 次数，少一张判 FAIL）；内存与并发闸门 |
| 会话复盘 | `dsh_session.js`、`dsh_snapshot.js`、`dsh_usage.js` | 读执行代理的会话日志、快照差异、用量 |
| 编排原则 | [01 · 自动化执行与并行](../../开发工具/SOP/01_自动化执行与并行.md) | 并行产出清单 → 串行一次执行 → 回读校验 |
| 任务书写法 | [子代理提示词](../../开发工具/SOP/01_自动化执行与并行/子代理提示词.md)、[步骤模板与硬闸](../../开发工具/SOP/01_自动化执行与并行/步骤模板与硬闸.md) | 八段结构；让弱模型也照做得对 |

**为什么这样设计**：并行的边界不是依赖图，是 Unity 单实例——读取、判定、算位姿可以开几路，改场景、烘焙、进 Play 必须排队。所以工具做成「清单 / 执行」成对入口，清单可并行、可交弱模型，执行排一次队并紧跟回读。执行代理会静默失败（模型收图不报错却没看图、写完未落盘），所以核验靠会话日志和快照，不靠它自己的回报。

### 3. 工具接入层

| 组件 | 路径 / 来源 | 作用 |
|---|---|---|
| Unity MCP | `com.coplaydev.unity-mcp`（版本见 [建工程与首轮编译](../../开发工具/SOP/02_环境准备与人工介入/建工程与首轮编译.md)） | 读写场景、执行编辑器代码、跑测试 |
| Blender MCP | Blender 扩展（监听本地端口） | `bpy` 读顶点、骨骼、形态键 |
| agy MCP | `开发工具/通用工具/agy_mcp_server.js` | 把多模型证伪包成 `agy_review` / `agy_ask` 两个工具，主理与执行代理共用 |
| Unity 编辑器脚本 | `开发工具/通用工具/*.cs`、`审查/unity/`、`生成/`、`部件图鉴/` | 性能报告、PhysBone 清点与合并、参数审计、构建阻断扫描、菜单断言、部件图鉴拍照 |
| Python / Blender / Shell | `开发工具/通用工具/*.py`、`*.sh` | 形态键测量、贴图分档、解包、`unity_run.sh`（带内存上限起 Unity）、`unity_recover.sh`（崩溃后只读诊断） |
| 工具索引 | [00_总表/工具索引](../../开发工具/SOP/00_总表/工具索引.md) | 按事找工具 |

**为什么这样设计**：「证伪」做成 MCP 工具而不是手敲命令，是因为上下文一长模型就会忘了调它——摆进工具列表，每一轮都看得见。编辑器操作尽量走 `-executeMethod` 批处理，交互编辑器只做看与改，因为构建与预处理在交互编辑器里反复触发图形崩溃。

### 4. 知识层

| 组件 | 路径 | 作用 |
|---|---|---|
| 总表 | [00_总表](../../开发工具/SOP/00_总表.md) | 全流程阶段表、卡口、五条贯穿全程的硬规矩 |
| 阶段页 | `开发工具/SOP/10_…` 至 `90_…` | 每页开头是确定化步骤表＋可自动查的通过判据；深水区在同名子目录 |
| 问题定位 | [问题定位索引](../../开发工具/SOP/00_总表/问题定位索引.md) | 按症状翻 |
| 工具链基准 | [_工具链基准](../../开发工具/_工具链基准.md) | Unity、VRChat SDK、各插件冻结版本及理由 |

**为什么这样设计**：执行代理读不到主理的记忆，只读得到文件，所以技术经验一律进 SOP。单页 ≤10 KB，按需翻页，不一次全读，控制每次派工的上下文成本。每条规则写取舍（阈值来源、双向失败模式、达不到怎么办），让接手的模型在数字变了时能判断是否合理。

### 5. 闸口层

| 钩子 | 事件 | 做什么 |
|---|---|---|
| `.claude/hooks/rules-inject.js` | UserPromptSubmit、PostToolUse | 每轮用户发言注入 `CLAUDE.md` 里两行标记之间的强制准则；连续调用工具每 25 次再注入一次；顺带记录看图、证伪、派工的时间戳 |
| `.claude/hooks/delegate-check.js` | PreToolUse | 主理直接改工程（Write/Edit、Bash 写操作、Unity MCP 写动作、Blender 执行代码）时提醒；自上次派工起第 3 次 deny，除非用 `--exempt <类别> "<理由>"` 声明六类合法例外之一 |
| `.claude/hooks/stop-gate.js` | Stop | 回合结束前查：改了工程但施工记录没跟上或没提交；看过图之后没证伪；最后一段以问句结尾；有直接改动未记理由。不满足挡一次 |
| `.claude/hooks/session-start.js` | SessionStart | 会话开始、恢复、上下文压缩后跑 `baseline_recheck.sh`，注入只读的现实核对（内存、进程、锁、未提交改动、状态头） |
| `开发工具/通用工具/git-hooks/pre-commit` | git 提交 | 拦超过 5 MB 的文件与疑似密钥 |

**为什么这样设计**：准则写在 `CLAUDE.md` 里只在会话开头进上下文一次，长会话、无人值守连跑时会被挤远，「提一次用几次就忘」。缺的不是记性，是结构性触发器。钩子解析失败一律静默放行——钩子不该成为故障点。「挡一次」而不是一直挡，避免死循环。

### 6. 记录与自学习层

| 组件 | 路径 | 作用 |
|---|---|---|
| 施工记录 | 每个工程根的 `_施工记录.md` | 顶部状态头可整块改写，下面时间线只追加 |
| 记录入口 | `开发工具/通用工具/log_step.py` | 追加条目、维护状态头、`--distill` 打「待蒸馏」标签、`--commit` 一步提交；时间只取系统时钟，写后回读不一致不提交 |
| 提交入口 | `开发工具/通用工具/ws_git.py` | 工作区唯一提交入口，自动排除大资产 |
| 派工流水账 | `_DSH流水账.md` | `dsh_task.js` 每次派工自动追加，含执行代理的「应写进 SOP 的教训」段 |
| 蒸馏材料 | `开发工具/通用工具/distill_collect.py` | 汇总某时间点后的标签、教训段、被改过的 SOP 页 |
| 规程 | [收尾蒸馏与状态头](../../开发工具/SOP/04_施工记录与版本管理/收尾蒸馏与状态头.md) | 两层制的完整做法与验收 |

**为什么这样设计**：执行会话在疲劳上下文里随做随改 SOP，会产生跨页矛盾和「只拆不缩」；事后补记又会被合理化。所以现象当场记（只写事实与可查问句），规则由不带对话历史的代理在阶段收尾时合并进 SOP 原处。例外只留给「不改就会让下一次派工立刻踩坑」的判据。模型估计的时间不可信（多次写出比实际晚几十分钟的时间戳），所以时间只从时钟取。

## 二、复刻清单

### 订阅与 API

| 项 | 必需？ | 用途 |
|---|---|---|
| Claude Code（Claude 订阅或 API） | 必需 | 主理 |
| agy（Antigravity CLI）及其背后的 Gemini 等模型 | 进阶 | 证伪 |
| DeepSeek API ＋ DSH | 全量，可选 | 便宜的执行代理；视觉任务要走声明了图像输入的模型 |
| Codex CLI（ChatGPT 订阅） | 全量，可选 | 执行代理；`dsh_task.js` 读它的额度余量，超阈值停派 |

### 软件

版本以 [_工具链基准](../../开发工具/_工具链基准.md) 为准，作者环境：

- Unity 2022.3.22f1 ＋ VRChat SDK 3.10.x（通过 VCC / ALCOM / vrc-get 建工程）
- Modular Avatar、NDMF、Avatar Optimizer、lilToon、VRCFury 等 VPM 包（按基准表冻结，单子进行中不升级）
- Blender 5.x（加 MCP 扩展）
- Node.js（钩子与派工脚本）、Python 3（分析脚本）、git、bash
- 作者在 Ubuntu 上运行；`unity_run.sh` 依赖 `systemd-run` 与 `flock`，在 Windows/macOS 上要改写或跳过

### 硬件

作者机器是 30 GB 内存的 Linux 工作站，NVMe 放工作区。并发按内存算而不是按 CPU：一台交互 Unity 约 3–5 GB，批处理导入 2–4 GB，一个 DSH 会话连 MCP 子进程约 0.3–0.8 GB。内存小时把 `dsh_task.js` 的并发闸门（`DSH_TASK_MIN_GB`、`DSH_TASK_MAX_SESS`）调低。依据见 [内存预算与并发](../../开发工具/SOP/02_环境准备与人工介入/B850_Linux环境/内存预算与并发.md)。

### MCP 插件

`.mcp.example.json` 复制为 `.mcp.json` 后按需保留：

- Unity MCP：在工程里装 `com.coplaydev.unity-mcp`，面板 Transport 选 Stdio（排障阶梯见 [02 · 环境准备与人工介入](../../开发工具/SOP/02_环境准备与人工介入.md)）
- Blender MCP：Blender 扩展，偏好里开「在线访问」
- agy：`node 开发工具/通用工具/agy_mcp_server.js`（需要本机已装并登录 agy）

### `kit.env` 要改的项

`kit.env.example` 复制为 `kit.env`，填 SOP 与脚本里占位符对应的实际值：

| 占位符 | 含义 |
|---|---|
| `<工作区>` | 本仓库（工作区）根目录 |
| `<Unity安装根>` | Unity Hub 的编辑器安装根（其下 `Editors/<版本>/Editor/Unity`） |
| `<素材库>` | 你自己的已购素材库根目录 |
| `<存档目录>` | 存档与交付总包目录 |
| `<客户素材目录>` | 客户素材包存放目录 |

具体变量名以 `kit.env.example` 内注释为准。另外 `.claude/settings.json` 里的钩子命令路径、`.mcp.json` 里的服务器路径也要指向你的本机位置。

## 三、降级方案

| 缺什么 | 怎么办 | 失去什么 |
|---|---|---|
| 没有 DSH / Codex | 执行活用 Claude Code 的 `Agent` 子代理；任务书照 [子代理提示词](../../开发工具/SOP/01_自动化执行与并行/子代理提示词.md) 写，验收照旧（git show、回读值、复跑判据）。`delegate-check.js` 只在 Bash 里跑过 `dsh_task.js` 时清零计数——没有派工脚本时，要么用 `--exempt` 声明，要么改钩子把子代理派工也算作清零 | 主理额度消耗变大；没有会话日志核验与快照比对 |
| 没有 agy | 准则 1 的证伪改为：开一个不继承当前上下文的 Claude 子代理，只给材料与编号结论，要求逐条「支持 / 矛盾 / 看不出」（写法见 [05](../../开发工具/SOP/05_多模型评审规程.md)）。`stop-gate.js` 认的是 agy / DeepSeek 视觉调用，不认子代理证伪，需要在回复里说明或调整钩子 | 同一家模型的偏差无法对冲；同一订阅池额度 |
| 没有 Unity MCP | 编辑器脚本多数带菜单入口，可以手点或走 `unity_run.sh --batch --method <入口>` 批处理 | 交互式读写场景；部分审查脚本需要改成批处理入口 |
| 没有 Blender MCP | 用 `blender --background --python <脚本>` 跑 `bl_*.py` | 交互式探查 |
| 不接单、只想要方法 | 只读 SOP；钩子可以不装 | 准则不会被强制执行 |

## 四、已知限制

- **SOP 阈值按作者的素体与插件版本标定。** 接缝 0.3 mm、夹角 12°、距离分位数 1 mm 之类的数字，来自特定素体、特定版本的 Modular Avatar / AAO / lilToon / VRChat SDK。换素体或升级插件后要重新标定；规程里凡写「按工程标定」「未实测」的阈值，不能当通过判据直接用。
- **回归测试未完全验证。** 身体/脚部形态键适配服装一项，旧方法与旧脚本只当正反样本；现行入口 [70 · 回归测试](../../开发工具/SOP/70_回归测试.md) 里未实测的工具与阈值仍须按工程标定。
- **钩子与目录命名约定耦合。** 钩子把「工作区顶层含 `ProjectSettings/ProjectVersion.txt` 的目录」认作工程；认 `_施工记录.md`、`_任务账本.md`、`_长程任务_*`、`_DSH流水账.md`、`开发工具/SOP/`、`CLAUDE.md` 这些名字来区分「主理自己的地盘」与「工程」；`rules-inject.js` 按 `<!-- 强制准则:BEGIN -->` / `<!-- 强制准则:END -->` 截取准则。改任何一个名字都要同步改 `.claude/hooks/` 里对应的正则。
- **目录名是中文。** 脚本和钩子按路径引用它们，重命名目录需要全局替换并跑 `开发工具/通用工具/check_links.py` 查断链。
- **派工脚本绑定特定 CLI 的会话日志格式。** DSH 与 Codex 升级后日志格式可能变化，核验逻辑要跟着改。
- **作者环境是 Linux。** 路径、进程管理与 Unity 启动方式按 Ubuntu 写；Windows 上的差异 SOP 未系统覆盖。
- **案例已匿名。** SOP 中「工程A…G」与内部出处标记指向的原件不公开，引用的行号无法在本仓库核对。
