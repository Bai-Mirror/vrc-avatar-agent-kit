### 9.3 What I explicitly did **not** verify (do not treat as verified)

- Any actual behavior in Play mode (starting Unity was forbidden this round);
- The three things added by task G (defaults taken from startup values / sanity check / volatile detection / callback isolation) were only compiled offline,
  never run in Unity: the field names and event structure of `EditorApplication` were checked against a disassembly of 2022.3.22f1's `UnityEditor.dll`
  (§7); when switching Unity versions or projects, re-verify per items 14–16 of §9.2. Task Q changed “defaults taken from startup values” to “taken from the expression parameter's declared
  `defaultValue`”, only compiled offline; reading `defaultValue` via reflection and its not drifting across sessions must be measured in Unity per item 3 of §9.2
  (in particular confirm `reset_values_source="declared_default"`, `reset_fallback_params=[]`).
- GM versions other than 3.9.9 (line numbers in the README were all checked against 3.9.9; re-grep when the version changes);
- The effect of the rendering backend (OpenGL iGPU / Vulkan dGPU) on pixels — task B's conclusion is not in yet;
  before comparing `vanish_ratio` values across runs, confirm both used the same backend;
- Readback values under the project's actual Linear vs Gamma color space (logically consistent, but not measured);
- Task I's per-slot masks, C0/C1 transmittance, `model_error_p50`, ID rendering / `vanished_owners` were likewise only compiled offline,
  never run in Unity; whether `Shader.Find("Hidden/AvatarAudit/*")` hits under `Assets/Editor/`, and whether `SetVector` writes into a Linear RT
  really read back byte-exact, must be measured per items 10 / 17 of §9.2.
- Task R's four probes were likewise only compiled offline (`compile_audit_R.sh`, 6 `.cs` files, 0 errors / 0 warnings),
  **never run in Unity**: `BakeMesh` world-coordinate conversion, `Physics.queriesHitBackfaces` + temporary MeshCollider
  six-direction iterative rays, 2 mm grid nearest-point hashing, and `renderQueue` reading all need to be re-run on Project A per item 18 of §9.2
  (compare with the historical values in §3.2.5).
- Task T's three revisions to `containment` (GameObject-name token pairing, splitting Foot/Toes by `sharedMesh` weights, `body_region_verts_total`
  + `excluded`, `outside_centroid_local`/`outside_extent`) were **likewise only compiled offline** (`compile_audit_T.sh`, 6 `.cs` files,
  0 errors / 0 warnings). The token-pairing logic was verified with a small reflection test under mono (13 items `ALL PASS`); but “can the body mesh's
  `sharedMesh` weights separate the toes”, “are vertices deleted by `NaNimation` really non-finite coordinates or carrying `NaNimat` bone names at runtime”,
  and “are anchor-bone local coordinates usable” can only be confirmed by measurement in Project A per item 18 of §9.2.
- Task AN (T-13 T1 v4)'s **pure logic and format** all passed the offline self-check (40 PASS / 0 FAIL: V3 rule table, `SlotOf` / `InferGearSlotCount`
  / `CanonicalTuple` / `ReadbackMatch`, `GuessSourceName`, version hash determinism, 83-state request replay), but the following **can only be verified in Unity/Play**:
  whether the deployed-tree hash and `VERSION.hash` are byte-identical in a real project (`HashEntries` and `sync_audit.py` are two separate implementations,
  aligned by using the same method), whether the dll mtime obtained from `Assembly.Location` is the compile time, the size and time cost of `keys_all` over the 166 SMRs after AAO merging,
  the real value of `mesh.isReadable` in the project (decides whether V4 is null), whether V3 property reads hit on real lilToon variants,
  the interaction between sentinel hide restoration and GM, and whether the 83-state readback assertions really all pass under GM clamping / precision. Verify per items 19–22 of §9.2.
