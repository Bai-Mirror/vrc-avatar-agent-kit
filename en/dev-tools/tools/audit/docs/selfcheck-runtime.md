### 9.2 Runtime (can only be verified inside Unity)

| # | Item to verify | How to verify | What failure looks like |
|---|---|---|---|
| 1 | `ModuleHelper.GetModuleFor` + `GestureManager.SetModule` can really take over in Play mode and make parameters take effect | In `states.json`, `gm_controlled=true`, `driver="gesture_manager"`; the `A2_HeadAcc` entry has `diffs.*.any_change=true` | `gm_note` = `场景里没有可用的 GestureManager 组件` (no usable GestureManager component in the scene) → the Project A scene needs a GM object; or it took over but `any_change=false` → check whether it is an AAP parameter |
| 2 | Whether the GM component is enabled and running `Update()` | If `gm_note` contains `组件是 disabled 的` (component is disabled), parameters take effect only via the PlayableGraph | If parameters don't move at all, first check whether the GM object/component is turned off |
| 3 | `VRCExpressionParameters.parameters[].name` + `.defaultValue` can be read via reflection (after task Q, `defaultValue` is used again as the reset value) | `states.json.reset_param_count > 0`, `reset_values_source="declared_default"`, and `param_defaults[*].declared_in_expression` has true entries; `defaults_snapshot` shows the declared defaults of user parameters such as `A2_Outfit` | `reset_param_count=0` → the avatar has no `expressionParameters` attached (or all declared ones are built-in parameters), so no parameter gets reset; then either write parameters explicitly in every state or attach expression parameters first. If `reset_values_source="startup_value_fallback"` and `reset_fallback_params` is non-empty → reflection on the `defaultValue` field name/type failed (check against the SDK symbol table in §7); this batch's reset falls back to actual startup values and may still drift across runs |
| 4 | Snapshot determinism | Put only 2 states + `"repeat_check": true`, look at `determinism.*.identical` | When `false`, `first_difference` points to the specific line; if the differing line is in `blendshapes` and the key is in `volatile_blendshapes`, it is autoplay noise rather than nondeterminism |
| 5 | Whether parameter settings take effect immediately (PlayableGraph evaluated every frame) | Assert that blend shapes / visibility actually changed after `settle_frames=30` | If nothing changes, consider increasing `settle_frames` or confirm GM is running |
| 6 | Handling of two avatar roots with the same name | In the Project A scene, confirm the names and active state of both roots; the tool should pick the active one | Reports `找到 2 个且都 active` (found 2, both active) → turn one off first |
| 7 | Whether T3's rendered images are right (orientation, definition of straight ahead, FOV, size) | Open `Head_az0_el0.png`: it should be the character's **front face**; `az180` is the back of the head | Reversed → `avatar.transform.forward` points differently than expected; change the `az` reference base |
| 8 | Whether colors read back by `Camera.Render()` under the project's render pipeline/color space match the background | Render an empty scene; the mask should be 0; or check whether `mask_px` is noticeably too large (background misjudged as R) | `mask_px` ≈ whole image → background color in the RT differs from `_bg` by more than ε (color space issue); adjust `color_epsilon` or change `bg` |
| 9 | Pixel layout of `GetPixelData<Color32>` (vertical flip) | Is the saved PNG upside down; saving uses `SetPixels32`, same order as readback, so in theory consistent | If flipped: masks/stats are unaffected (same-order comparison), but images look wrong to humans; flip y in `SavePng` |
| 10 | Transparency sorting positive/negative samples (version 2, per slot) | Positive: Project A “hair accessory PixelBoot × hairstyle GoldenHour” turned on → PixelBoot's `sequence_code_BL_q3050` slot should be `flagged`, and the merged mesh of `Hair_GoldenHour` appears in `vanished_owners`; negative: hair accessory turned off → that slot's `vanish_ratio` is 0 or `null`; neither run should mark the hairstyle's opaque/silhouette slots red wholesale anymore | Positive sample not detected → check whether `candidates` contains that `(renderer, submesh)` (`renderQueue > transparent_queue_min`?) and mask pixels ≥ `min_mask_px`?; hairstyle slot still flagged → check whether that entry's `t_p50` ≥ `t_min` and whether `model_error_p50` is high |
| 11 | `Time.frameCount` increments normally in the editor Play loop and `EditorApplication.update` is called every frame | Time for number of states × settle_frames should roughly equal frames ÷ frame rate | Stuck → look at `progress` in `status.json` and `audit.log` |
| 12 | `auto_play` resumes across domain reload | Send a request with `"auto_play": true` while not in Play; it should enter Play automatically and start | Doesn't start → check whether `SessionState` and `[InitializeOnLoad]` are blocked by other scripts |
| 13 | Memory | In a 10 GB-class Play + bake scene, additionally open 1024² RT ×2 and 6 pixel buffers (about 4 MB×6) plus per-view PNGs | OOM → reduce `size`, reduce `azimuths`, turn off `transparency_check` |
| 14 | The sanity check really catches “scale 0 / collapsed skeleton” (task G) | Normal avatar `sanity_failed=false`, `status=done`; deliberately set the avatar root scale to 0 and re-run → `sanity_failed=true`, `status=error` | Avatar collapsed but `sanity_failed=false` → check whether `lossyScale` and Head/Hips are obtained |
| 15 | volatile detection (task G) | Check whether `states.json.volatile_blendshapes` lists things like `AAO_Merged_Blink`/`EyeWide`; re-running with `"volatile_probe": false` should give `[]` | Two snapshots still differ but the list is empty → check whether it's bones/visibility drifting rather than blend shapes |
| 16 | Callback isolation really detaches the old probes (task G) | `isolated_callbacks.json.isolated_callbacks` contains `AvatarGen.RuntimeProbe.OnPlay` / `EarPlayProbe.*`; during this round's Play, `Assets/_Work/运行期探针.md` and `耳朵Play诊断.md` are **not updated**; after exiting Play, `restored_at` is non-empty | List empty or probe files still written → the reflection path doesn't match (when switching Unity versions, first check field names per §7); if `_armed` is not frozen, RuntimeProbe may still write parameters every frame |
| 17 | Per-slot mask / transmittance model / vanished_owners (task I) | In flagged records, `submesh`/`material`/`render_queue` match `candidates`; `t_p50` for transparent slots is clearly > `t_min`, and opaque slots don't enter candidates at all; ordinary lilToon transparent slots have `model_error_p50` < 0.02; `vanished_owners[0].renderer_path` points to “the occluded mesh” that a human can confirm | `model_error_p50` generally > 0.05 → that slot is Refraction/GrabPass/custom Blend, vanished is not trustworthy; `vanished_owners` is `null` → the ID shader was not found or decoding of all vanished pixels failed (see `warnings`) |
