## 10. Known limitations

1. **T1 requires Play mode**. In edit mode there's no AE parameter driving, so running is meaningless; without `auto_play` in the request it writes an error directly.
2. **Parameter interlinking depends on GM taking over**. With `driver=animator`, neither `VRC_AvatarParameterDriver` nor `VRC_AnimatorLayerControl`
   executes, so the snapshot can only be used as “static visibility/blend shapes”, not as “the real combination in VRChat”.
3. **The Animator fallback is weak**. The `Animator` in VRChat projects usually has no `runtimeAnimatorController` (animator layers live in
   `VRCAvatarDescriptor.baseAnimationLayers`), so the fallback produces widespread `params_missing`. To make the fallback really usable,
   you'd have to build a PlayableGraph yourself — not done this round.
4. **AAPs (curve-driven parameters) can't be written**: GM's `PlayableParam.SetValue` returns directly on `_isAap()`
   (`Vrc3Param.cs:168/189`). Such parameters show up as `no_effect`; it's not a tool bug, and you can see it in the output, but it's **not**
   specifically marked as AAP — you need to cross-check the GM interface manually.
5. **`pose` only supports `tpose` / `ikpose` / `idle`**; `walk` / `sit` / `crouch` / `arms_up` need animation clips and aren't implemented this round
   (if written in the request, a warning is recorded and it's ignored).
6. **`no_effect_params` is not per-parameter attribution** (convention in §4).
7. **T3 criteria depend on a solid-color background**: the background color must be distinguishable from the avatar's colors (green hair + `bg=[0,1,0]` would misjudge the hair as “nothing behind”).
   Change `bg` or raise `color_epsilon`.
8. **The mask layer may be occupied**: `mask_layer` defaults to 31; the tool scans the scene for other renderers on the same layer and writes a warning, but doesn't switch layers automatically.
   Multiple candidate renderers on the same GameObject share a layer, so masks mix into each other (also warned; those `vanish_ratio` entries aren't trustworthy).
9. **T3 turns off MSAA** (`rt.antiAliasing=1`) to allow per-pixel comparison of A/C; PNG edges will be aliased, for review only, not as aesthetic delivery images.
10. **The A image is rendered once and reused for all candidates**: A doesn't depend on R, so this is logically equivalent to “render A separately for each candidate” in the task brief; it saves 3× rendering.
11. **Synchronous rendering stalls frames**: one viewpoint renders `1 + 2×候选数` (1 + 2×candidate count) images; with many candidates a single frame may stall for hundreds of milliseconds; overall it still advances across frames.
12. **Momentarily changing layer/enabled in edit mode may leave a scene dirty flag** (values are restored); don't save out of habit after running.
13. **Screen Space Overlay UI doesn't go into the RT** (Unity behavior), while world-space UI does; hide it yourself if you need a clean image.
14. Bone names that `HumanBodyBones` can't resolve fall back to “find by hierarchy name”; only if that also fails does it warn + skip that target.
15. **T1 doesn't reset parameters at the end** (for T3's use; but if GM was created temporarily by T1, when `Cleanup()` destroys it, `ModuleVrc3.ForgetAvatar` (`ModuleVrc3.cs:814-827`) will `Rebind()` + clear parameters, and T3 won't get that batch of states; see §3.1); if you want the behavior of “return to a clean state after running”, exit Play yourself afterwards.
16. **The temporary GM is exclusive to T1** (task F): when the scene has no GM originally, in Play mode T1 creates `__AvatarAudit_GM` to take over and `Cleanup()` destroys it. So when you see `driver=gesture_manager`, use `gm_created_by_audit` to tell whether it came with the scene or was created temporarily; T3 doesn't create a GM and can't reuse T1's temporary GM either.
17. **Only “user-controllable parameters” are reset, with reset values taken from declared defaults (task Q)**: only parameters declared in the expression parameters and not VRChat built-ins are reset between states, with values from `VRCExpressionParameters.defaultValue` (only if unreadable does it fall back to T1's actual startup value, warning for each). Parameters that appear in the request but aren't in the expression parameters aren't reset automatically — when chaining multiple states, either write them into the expression parameters or write them explicitly in every state. Built-in parameters are only changed when a state writes them explicitly. For switching-residue tests use `"reset":"none"` and list the sequence explicitly (§3.0.3).
18. **Callback isolation is version-dependent (task G)**: `EditorApplication.playModeStateChanged` isn't a field-style event; this tool gets subscribers by reflecting on `m_PlayModeStateChangedEvent`; when Unity changes its internals, isolation degrades to a warning (`isolated_callbacks.json` empty/incomplete), which doesn't fail the audit, but old probes may still run.
19. **Volatile detection only covers the first state (task G)**: volatile blend shapes are identified only from two samples of the first state in pass 0; if a key only starts auto-playing in another state/at another moment, it still goes into the diff. When necessary, increase `settle_frames` or use a different state as the probe baseline.
20. **Probes are supplementary information and have only been compiled offline (task R; `containment` revised in tasks T/U)**: when `probes` isn't requested, the output is byte-for-byte identical to the old version; when requested but a probe throws, it only leaves a trace in that state's `probes.<名>.error` and `warnings`, without marking the whole batch as error. The Unity runtime behavior of the four probes (`BakeMesh` world coordinates, ray parity, nearest-point hashing, `sharedMesh` weight region mapping) hasn't been measured yet; rerun per item 18 in §9.2.
21. **`containment` is unreliable on non-manifold meshes (task R)**: iterative ray parity assumes the mesh is a **closed, orientable** surface. When edges are shared by >2 triangles, the mesh self-intersects, normals are flipped, or there are inner and outer shells at the same position, parity breaks. The `nonmanifold_edge_ratio` in the output is there for this — when it's high, `inside_ratio` can only be used as a reference.
22. **Open pieces naturally have low containment ratios (task R; no longer used as a criterion since task U)**: for open pieces like sandals, open-toe shoes, and fingerless gloves, even at the correct size, toes/fingertips fall “outside”, so a low `inside_ratio` doesn't mean a defect. Since task U the criterion uses `crossing_edges` instead (body surface intersecting the fabric): the body passes through the opening without intersecting the fabric, so open pieces have crossing counts close to 0; `open_mesh_suspect` (boundary edge ratio) is still output, as a hint of “is this an open piece”.
23. **Skinning scale and unreadable meshes (task R)**: world coordinate conversion follows T2's convention — `BakeMesh(mesh, true)` first compensates for the SMR's own scale, then multiplies by `localToWorldMatrix`; renderers with negative/non-uniform scale may skew the results. `coincident` only compares `SkinnedMeshRenderer`s; if a `containment` clothing piece is a `MeshRenderer` whose mesh doesn't have Read/Write enabled, `sharedMesh.vertices` throws, and the probe records a warning and skips that piece. `containment` is the heaviest probe (vertices × 6 directions × up to 30 rays, plus several thousand edges per region × 2 segment rays); on large projects, first enable `containment_pairs` only for suspicious regions.
24. **`containment` pairing is a name heuristic (task T)**: it only looks at the renderer GameObject name. If an accessory's own name contains a standalone token (camel case in `PixelBoot` splits out `boot`), it will still be paired as a shoe/boot; exclude it with explicit `containment_pairs`. Conversely, a real shoe whose renderer name contains none of the keywords will be missed.
25. **Region totals are state-independent only when weights are readable (task T)**: `body_region_verts_total` depends on the skinning weights of `sharedMesh`; if the body mesh doesn't have Read/Write enabled or has no bones, the probe falls back to `NearestBoneIndices` (`body_region_source=nearest_bone` + warning), regions drift with pose and totals are no longer constant, and in that case they can only be used as a reference.
26. **“Deleted” vertices go into excluded, not into crossing counts (tasks T/U)**: toe/sole vertices deleted by MA ShapeChanger via NaNimation are in `excluded.deleted_nanimated`, and neither `verts` nor `edges` include them. So “toe `flagged` is 0 with socks on” doesn't mean they're enclosed, only that the region's geometry has been deleted; measuring containment / crossing must use states where the geometry exists (Project A uses `A2_Sok=0`).
27. **Threshold trade-offs for the crossing criterion (task U)**: `flagged = crossing_edges ≥ 20 且 crossing_ratio ≥ 0.01` (and). 20 edges blocks scattered/single-triangle-level grazing (numerical coplanarity, one vertex on the line produces about 2–4 edges); 1% blocks absolute counts being inflated in large regions (the foot has 3000–6000 edges). Skin-tight pieces (socks/bodysuits) grazing will have single digits to a dozen or so crossing edges; if a single genuinely skin-tight piece is falsely reported, first check whether `max_crossing_depth_mm` is only a few tenths of a millimeter and whether `crossing_midpoint_local` falls in the expected region, then raise `containment_min_crossings` per project. When `containment_ray_budget` is exhausted, it truncates in sorted region order with `truncated=true`; the count is then incomplete and can't be used as a negative sample.
28. **`pre_probe_blendshapes` only borrows the probes' readings (task U)**: blend shapes are set **after** the snapshot and restored **after** the probes, so `state_<id>.json.blendshapes` still holds the original values, and only `pre_probe_blendshapes_applied` records the overrides; without `probes` it doesn't take effect (warning). When multiple renderer substrings match, the first in path order is taken, and all AAO shards of a blend shape are set — both for reproducibility. The same goes for T3's `only_renderers`/`hide_renderers`: set before `collectCandidates` and restored in `Cleanup`, so hidden pieces don't enter the transparency candidates; matching is by substring, so writing `Glove` also matches `GloveBox`; verify via `shots.json.view_filter.only_matched`.
