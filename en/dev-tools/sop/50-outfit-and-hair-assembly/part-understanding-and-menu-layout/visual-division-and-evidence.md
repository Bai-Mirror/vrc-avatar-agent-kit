# Visual division of labor and evidence: what models look at, what data measures, who decides

The author on 09-22 wanted “photograph each part of every outfit separately and give them to a vision subagent (e.g. DeepSeek) to label and document” 〔explicit〕 (relayed in `lt/作业清单_全部未完成.md:965`). This page settles: which images to shoot, which numbers to take, which kinds of questions go to whom, and how conclusions are falsified.

## 1. Images and numbers needed for each part

Capture tool: `开发工具/通用工具/部件图鉴/PartAtlasCapture.cs` (overlay text by `part_atlas_overlay.py`), configured in the project's `_交付/部件图鉴_配置.json`, outputting to `开发工具/素材包说明/<商品名>/部件图/` and `部件清单.json`. **The output path doesn't distinguish base avatars** (`:316-318`): reshooting for another base avatar overwrites the original, so check the directory before reshooting. The tool only produces images and numbers; it **does not judge what a part is** (file header comment).
Progress: H-02 shot 4 sets, 36 parts, 222 images, acceptance partially passed (`A/_施工记录.md:913,931-932`); H-02b fixed side-view leakage and switched full-set comparisons to per-part framing, reshot as 300 images, acceptance passed at 06:35 (`:955,969`). Output naming and known limitations are in `开发工具/通用工具/部件图鉴/README.md`.

| Product (file name) | Content | Use |
|---|---|---|
| Image A `NN_<部件>_仅部件-正面.png` | Body off too, only this part | See shape, material feel; judge whether it's a sensitive item |
| Image B `NN_<部件>_在身上-正面/侧面/背面.png` | Only this part + base avatar body on, everything else off | See where it's attached/worn, which body segment it covers |
| Image C `NN_<部件>_整套-有/无-正面.png` (per-part framing from H-02b on), `整套全身-有/无-正面.png` (full-body framing, i.e. H-02's `整套-*`) | Full set with vendor default switches, with / without this part, same camera position; add a back view when the part is on the back | Judge visibility condition, what it contributes to the full set. **Can't judge weight on its own**: items covered by the outer layer look nearly identical in the with/without pair (Velour nipple covers, `A/_施工记录.md:935`); for small items and covered items, judge weight from the vendor showcase images and close-ups |
| Vendor showcase images | `<素材库>/*-<商品号>/images/` (set-level “vendor showcase images” in the list, config `vendorImageDir`); in-pack directories like `preview` `sample` `商品画像` ([General pitfalls](../../55-accessory-placement/common-pitfalls.md)) | Judge whether it's a selling point, which looks expose it |
| Product description and tags | `description_html`, `booth_tags` in `<素材库>/*-<商品号>/.booth-meta.json` (library structure in [10 Order intake and project setup](../../10-order-intake.md)) | Which parts the vendor names, style tags, whether a shrink mechanism is provided. Example: the Velour description names “ヌーブラやバッグなどのアクセサリー”, the tags include セクシーランジェリー, コルセット, and it also says to use the base avatar's blend shapes for body parts you want hidden |
| `部件清单.json` | Renderer path, mesh, triangle count, material + main texture, default activeSelf/enabled and parent chain, top 5 dominant bones, blend shapes, vendor switch references; set level: vendor menu tree, parameters, color-variant material differences | Geometry and mechanism judgments |

- **Text printed on images should only be numbers** (triangle count, hex): models read them accurately but can't measure them themselves ([DSH models and vision capability](../../01-automation-and-parallelism/dsh-model-and-vision-capability.md) section 2 rule ②). Identity information (product name, renderer path, material name) shouldn't be printed; the tool currently prints it and overwrites in place, so black it out before blind labeling ([Blind labeling and sensitive images](blind-labeling-and-sensitive-images.md) section 1). To-do after H-02b: also save text-free originals, or print only the view name and triangle count.
- **The tool doesn't compute difference pixels**; the algorithm and pitfalls are in Blind labeling and sensitive images section 4.
- **When the mesh isn't readable, the dominant bone degrades to “bone to bounding box distance”** (stated in the list's `口径` field; all 9 Velour items are like this, `A/_施工记录.md:926`). It then counts only as weak evidence; the list's “related body parts” is derived from it, **do not copy it**; write the covered parts from image B (sensitive items from geometry).
- **Our own stuff is mixed into “vendor switch references”**: the clip scan directories include our generator's `Assets/_Work/GenNew`; about one third of the switch curves for one accessory of an original outfit came from there, and the hit menu items also mixed in our `[场景]` menu items (source: the `pkg/` part list; still the case after the H-02b reshoot). Only curves under the vendor directory and `[厂商]` menu items go into the atlas ([Conflict checklist](conflict-handling-checklist.md) C03).
- `*.png` never goes into git globally (`.gitignore:45`); list JSON and atlas md go into git.

## 2. Who judges what

| Question | Goes to | Why |
|---|---|---|
| What's in the image, where it's attached/worn, what material feel | Vision models: DeepSeek blind-labels, agy (Gemini) falsifies | “Is there / is it / which is more X” can be dispatched ([DSH models and vision capability](../../01-automation-and-parallelism/dsh-model-and-vision-capability.md) section 2 rule ①) |
| Conspicuous or not, the protagonist of the showcase images or not | The vision model's set-level comparison round (Blind labeling and sensitive images section 2) + product description and tags | Looking at images one by one can't tell “which is more conspicuous”; they have to be asked together |
| Which body segment it covers, whether covered by the outer layer, distance to neighboring items, how many, whether aligned | Geometry and data: dominant bone, difference pixels, per-vertex distance | Measured exact counts 23→24, and a 6 px misalignment judged “perfectly aligned” — deterministic failures ([DSH models and vision capability](../../01-automation-and-parallelism/dsh-model-and-vision-capability.md) section 2 capability table) |
| Whom the vendor groups it with, whether parameter `true` means shown or hidden | Read the clips and menu assets in the vendor directory | [03 Assembly and conflict rules](../../03-assembly-and-conflict-rules.md) |
| Final visual weight grade, easter eggs, default values, menu wording | The user decides, Claude produces candidates | The author 09-22; `CLAUDE.md` mandatory rule 4 |

DeepSeek usage and limits:
- With images you must use `--model vision`; Pro is prohibited ([DSH models and vision capability](../../01-automation-and-parallelism/dsh-model-and-vision-capability.md) section 1).
- The capability limits were measured on 09-08 on the old model; the new model **hasn't been retested** (same page `:9-10`) — first-round labels are candidates only.
- Acceptance looks at the per-image verification PASS of `dsh_task.js --images`; rejected ones don't count ([DSH silent failures](../../01-automation-and-parallelism/dsh-silent-failure.md) ⑤); don't judge by whether the answer looks plausible.

## 3. How to write review submissions

- **State which things are intentional design** (outfit's own headwear, underwear + stockings look) and attach the vendor showcase images; otherwise the model counts adjacent protrusions into the declared category — LUNALICE's bow and Violet's hair clip were recognized as “a second pair of ears” ([Falsification task design](../../05-multi-model-review/falsification-task-design.md)).
- Ask “what is this / where is it / which is more conspicuous”, not “are there two X”.
- **Blind-label first, match names after**, dispatched as two separate rounds; the two rounds not matching is itself a finding to record ([Three axes and the naming trap](three-axes-and-naming-trap.md) section 3).

## 4. Falsification

- “What it is”, “visibility condition” and “visual weight” are all visual conclusions: before writing them into the atlas or building the menu on them, send them to agy for falsification; the review input is **our conclusion**, not “whether the tool works” (`CLAUDE.md` mandatory rule 1; procedure [05 Multi-model review procedure](../../05-multi-model-review.md)). Sensitive images may be sent externally (the user decided 09-22 13:3x, Blind labeling and sensitive images section 3). **Images sent to agy also use blacked-out copies with neutral file names, and the prompt doesn't include the product name**: H-03 batches A–C sent the originals, and the overprinted material name leaked into the judgment (Gemini's reasoning mentioned “corset line”, a phrase not in the prompt, `pkg/The Velour/_agy/H03_批B_部件图_结果.json`); the prompt said “The Velour”, and batch C's first run described the black miniskirt as “pink velvet (Velour)” (`H03_批C_部件图_结果.json`).
- Write the artifact paths of agy calls into the atlas's “evidence” column; DeepSeek and Gemini conclusions disagree → hand to the user to look at the images, don't arbitrate yourself ([60 Menu and animator layers](../../60-menu-and-animation-layers.md) step 3 STOP); but for questions in the “geometry and data” row of section 2 above (covered or not, present or not, what color), first arbitrate with pixels, materials and geometry; if that settles it, state the data and there's no need to hand it to the user (H-03 V6, V8, V10, `pkg/The Velour/部件图鉴.md` “falsification results”).
- **For patterns and prints (lace or leopard, printed or not), check the source texture first, then send to the model**: material `_MainTex` guid → texture `.meta` → png. In H-03 the front of the Velour boots is a white floral lace texture darkened to near-black by the material's `_Color`; DSH (P08, two rounds) and Gemini (batch C, two runs) both saw it as leopard print; one look at the texture settled it, then two agy runs confirmed (`pkg/The Velour/_agy/H03_批D_*`). **Trigger moment**: models' descriptions of a pattern conflict with each other, or don't match the material name. **Checkable question**: has the source texture for this pattern been looked at? Has the material `_Color` darkened it? **Trade-off**: reading two text files and looking at one image is cheaper than running models for more rounds; only when the texture can't be found (procedural texture, multi-layer blending) fall back to enlarged renders + model.
- **Prefer sending agy “part only” images or same-camera composites** (09-22 H-04): full-set images containing the character hit Gemini's permission wall 5/5; shrinking to a single-sentence claim and switching to part-only images usually gets through; if it still doesn't, record “hit the wall, not judged” and don't keep burning attempts.
- **Write the prompt header according to image type** (09-22 H-05): triptychs (A/B/R same camera), single part-only images, and vendor flat-lay product images each get their own header and schema, not shared; the H-05 Vend batch reused the “triptych” header and the whole batch was judged wrong, only correct after rerunning with the right header. **Checkable question**: how many images, of what kind, does this batch send? Does the image type written in the header match?
- **Three wording patches for set comparison (candidate, H-04/H-05)**: ① when the product ID is a **base avatar** product (e.g. Kaguya original outfit), first ask “in which showcase images is this outfit specifically featured”, and compare only those; ② “base layer = not visible in the showcase images” doesn't work for items **cropped out of frame but commonly worn**; candidate revision “focal 0 and visible in < half”, marked “candidate” when written into the atlas; ③ when the vendor images are only **flat-lay product images** (no character; H-05 NamaikiMaid backup library has only 1, no `booth_tags`), “focal / visible in how many” can't be applied: the comparison round doesn't rank focus, the atlas weight column is marked “showcase images unqualified”, and grading relies only on the product description and the user's decision; don't force it.
