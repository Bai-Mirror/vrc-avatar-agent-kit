### 2.1 `set` 取值怎么转（`gen-request` 与 `check` 同一套）

| 类型（`params.json` 的 `value_type_name`） | 规则 |
|---|---|
| `Bool` | 只接受 `0/1/true/false` → 请求里写 `0/1`。 |
| `Int` | 只接受整数。 |
| `Float`（`radial` / 轴 / 普通） | **数值原样透传，不做吸附、不做档中点改写**（要测 0.25 就发 0.25，不会悄悄变成 0.375 再称通过）；`suggested_values` 只用来校验范围。 |
| 显式槽号（任何 `Float`） | 只认字符串 `"slot:3"`：档数来自顶层 `coverage[参数].gears`（交付模式必须显式；研究模式可退回 `radial_labels` 个数），换算成第 3 档代表值 `(3+0.5)/N`。**整数 0/1 是端点数值，不是槽号**；整数 ≥2 若落在档号范围但超出连续区间，会明确报错并提示改用 `slot:`，不自动改写。 |

- `check` 与 `gen-request` 用**同一套** `resolve_value` 与**同一份有效约定**：
  `slot:3` 换算成同一代表值，不会因为 T1 里存的是换算后的数而被误判「缺失」；
  非 slot 的数值不会为了凑覆盖被改写。
- 参数名不在 `params.json`：**交付模式 = 输入异常（exit 2）**；研究模式降级为 warning 后按原值匹配。
- 取值非法（Bool 给 `maybe`、Int 给 `1.5`、Float 给 `true/on/NaN/Infinity` 或超范围）：两种模式都 exit 2。
- 参数存在但 `declared_in_expression=false` → 只提醒（T1 可能设不上），不阻断。

### 2.2 覆盖怎么建（交付模式：离散按证据，连续必须显式约定）

对 `params.json` 里每个「菜单参数」（`menu_value_kinds` 或 `referenced_by` 非空），按可达档位逐项要求覆盖：

| 参数类型 | 必测单元 | 来源 |
|---|---|---|
| `Bool` | `0` 与 `1` 两态 | 开关两态（离散、有证据） |
| `menu_values` 非空（`Bool` 除外，恒0/1） | 每个真实离散值；若同参数还被radial/轴引用，另需连续coverage约定，并集验收 | 按钮的值不能代替同参数轮盘/轴覆盖 |
| `Int`（`menu_values` 空） | 交付：必须在 `coverage` 显式声明；研究：`suggested_values` 兜底并标注 | T4 建议值 |
| `Float` + `radial`（有/无 `radial_labels`） | 交付：`coverage` 显式声明 `gears`/`units`/`boundaries` + 出处；研究：按 `radial_labels` 个数或 0/1 边界推测 | **人工审核的约定**（`radial_labels` 只是控件标签名，不保证真实档数） |
| `Float` + `axis2`/`axis4` | 交付：`coverage` 显式声明；研究：`-1/0/1` 边界推测 | **人工审核的约定** |
| 普通 `Float` | 交付：`coverage` 显式声明；研究：`0/1` 边界推测 | **人工审核的约定** |
| schema 与声明都定不出 | —— | `无法确定覆盖` → 交付模式 exit 2 |

- `coverage` 声明规则（严格）：
  - 数组形式 `[0, 0.5, 1]`：**仅研究模式**可用（无出处）。
  - 对象形式 `{"gears": 7, "note": "档位表：…:14"}`：`gears` 必须是 **≥2 的整数**（小数/字符串/布尔一律报错，
    不得 `int()` 截断）；`units`/`boundaries` 必须是非空、全为有限数值的数组（混入 `true`/`NaN`/`Infinity`/
    非法字符串即报错，**不静默过滤**）；未知字段、未知参数名、多重约定、交付模式缺 `note`/`source` 全部报错。
  - **坏约定不退成宽松默认**：解析失败即 exit 2，不会回落到端点边界。
- 覆盖只看期望 `set` 归一化后的取值，与 T1 是否找到该状态**分开计**（「缺失」另计），
  两类失败不会互相掩盖。
- 覆盖仍按「离散状态逐条」建立：**不代表参数全组合**，也不代表参数间相互影响。

### 2.3 实测怎么匹配（`check`）

- **状态匹配**：期望 `set`（归一化后）是 T1 `params_applied` 的**子集**（数值按 `1e-4` 比对）；
  命中多个时研究模式取「多写参数最少」的那个并列出歧义数，**交付模式判为检查失败（exit 2）**。
  `t1_state` 可钉死。
- **渲染器**：候选 = 快照里的 `path` / `key` / 叶名 / T5 还原名（路径段 `名$原物体$编号` → `原物体`）。
  模式含 `/` 时匹配整条路径，不含 `/` 时也匹配任一单段。`visible` 要求所有命中都可见，
  `hidden` 要求所有命中都不可见；**一个都没命中算 FAIL**（件不存在）。
- **形态键**：`keys_all`（全量）+ `blendshapes`（非零）合并去重；键名同时按原样名与 T5 还原名
  （`AAO_Merged_<原名>_<n>` → `<原名>`）匹配。命中多个时要求值都等于期望（`1e-4`）。

### 2.4 退出码与四类结果

| 码 | 含义 |
|---|---|
| `0` | 全部期望状态都找到、每一条比对都 PASS；交付模式还要求覆盖无缺口 |
| `1` | **业务失败**（比对不一致）/ **缺失**（状态未在 T1 找到）/ **未覆盖**（缺档/缺态） |
| `2` | **检查失败**：输入不合法 / `params.json` 重名或名单冲突 / `coverage` 声明解析错误 / 交付前置缺失 / 检查结果为空 / 歧义匹配 / 无法确定覆盖 |

报告把四类分开记：`业务失败`、`缺失`、`未覆盖`、`检查失败`（外加 `无法确定覆盖` 与 `歧义匹配`）。
**检查失败不进入正常差异判定**。研究模式下「未覆盖 / 无法确定 / 歧义」只记录、不影响退出码；
交付模式下全部非零；`coverage` 解析错误与 `params.json` 输入错误在**两种模式都非零**。

## 3. 报告长什么样

`--out 报告.md` 是人读版；`--json 报告.json` 是结构化版。Markdown 分节：

1. **汇总**：模式、四类计数表、退出码、结论（交付模式通过时写「菜单行为断言通过（约定覆盖）」，
   失败写「不通过」；研究模式写「局部通过 / 局部不通过」）；
2. **检查失败**：输入/前置/无法判定项逐条列出；
3. **逐条比对**：`状态 | 项 | 期望 | 实测 | PASS/FAIL`；
4. **未在 T1 里找到的状态（缺失）**：连同 `note` 出处列出；
5. **匹配到多个 T1 状态（歧义）**；
6. **覆盖**：逐参数列出未覆盖的档/态、无法确定覆盖的原因、已完整覆盖的参数数；
7. **局限**：明确没证明什么（全组合、游戏端、透明度、出处真实性等）。

JSON 里保留旧字段（`rows` / `per_state` / `not_found_states` / `uncovered_menu_params` /
`fail_row_count` / `not_found_count` / `exit_code`），并新增：
`mode`、`business_fail_count`、`missing_count`、`uncovered_count`、`undetermined_count`、
`ambiguous_count`、`check_failure_count`、`check_failures`、`uncovered_units`、
`undetermined_coverage`、`coverage_requirements`、`warnings`、`limitations`。
