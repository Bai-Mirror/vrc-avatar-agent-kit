# 导出规格：《VRChat 改模作业指南》

把项目内部的 SOP 与经验笔记，改写成**可以公开分享、能教会别人改模**的一套文档。

---

## 一、这次要改变的是「表述方式」，不是内容

源材料是**第一人称的项目笔记**：「我踩过」「客户 X 要求」「2026-09-0X 实测」。
目标是**客观的教学材料**：读者不认识你、不知道你的客户、也没有你的工程。

### 改写规则

| 源材料的写法 | 改成 |
|---|---|
| 「我踩过 / 我误判了三轮」 | 「这一步的常见错误是…」「症状是…，原因是…」 |
| 「客户 2026-09-02 要求」 | 「若需求是…」或直接写成规则，去掉时间与人 |
| 「工程A 上出现过」 | 「在多套服装的头像上会出现」 |
| 「用户提级为硬卡口」 | 「这一步建议设为强制检查点，原因是…」 |
| 「工程F / 工程G / 工程D 的那单」 | 删掉，或改成「某个案例中」 |

### 保留不动的东西

- **所有可证判据**（阈值、公式、字段名、API 名、判断顺序）—— 这是全部价值所在
- **失败症状的描述** —— 读者靠症状对号入座
- **因果链** —— 「为什么会这样」比「该怎么做」更耐用
- 具体的商业产品名（lilToon、Modular Avatar、Avatar Optimizer、GoGo Loco、VRChat SDK
  以及素体/服装品牌）—— 教学需要具体，这些是公开商品

### 语气

- 陈述句，不用「我」。可以用「你」指读者。
- 不写成流水账。**每一节都要能独立读懂**：先说症状或目标，再说机制，最后给判据。
- 不确定的地方明确标出来（「这一条只在 X 情况下验证过」），不要装作全都验过。
- 保留 ⚠ 之类的强调标记，但别滥用。

## 二、必须剔除的内容（隐私与安全）

**逐字检查，不能靠印象。** 出现以下任何一项就删掉或改写：

1. **客户名与订单号**：`COMM-` 开头的任何编号；客户代称（工程D / 工程G / 工程F / 工程E 等）
2. **本人身份**：作者本人的账号名与代称
3. **私有基础设施**：内网服务器代号、`/data/...` 之类的服务器路径、私有素材库的规模与位置
4. **任何密钥/令牌**：本项目的评审 API key 存放在工程目录之外，**绝不能出现在导出物里**，
   也不要写它存在哪
5. **内部工具的私有细节**：评审工具的具体模型编成与订阅档位属于内部配置，
   改写成「用第二个模型做反向评审」这类做法层面的描述即可
6. 具体日期（`2026-09-0X`）—— 一律删掉，改成条件句

## 五、README 要说清楚的四件事

1. **适用范围**：VRChat 头像改装（换装/配饰/菜单/性能），Unity + VCC 工作流；
   不涉及建模与贴图绘制本身。
2. **前提**：读者需要有的基础（Unity 基本操作、VRChat SDK3 的可播放层概念）。
3. **怎么读**：先看总览的阶段表；做到哪一步翻哪一篇；卡住了翻问题定位；
   `经验条目/` 是横向的，建议通读一遍再开工。
4. **可信度声明**：这些结论来自实际交付项目，多数附有可复现的判据；
   但 VRChat SDK 与各插件版本更新很快，**用之前先在自己的工程里验一次**。
   明确写出这套材料成文时的主要版本（Unity 2022.3、VRChat SDK3、
   Modular Avatar、NDMF、Avatar Optimizer、lilToon）。
