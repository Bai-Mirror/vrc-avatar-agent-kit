## 人工卡口总表

记号同总表：👤 用户拍板 · 🔒 必须用户亲手做 · 🎨 审美卡口（Agent 出候选 → 评审 → 有分歧才上报）。

### A · 流程上的卡口（在关键路径上，排期见 [01](../01_自动化执行与并行.md) 第三～五节）

| 卡口 | 记号 | 为什么不能自动 | 能拆出来的自动部分 |
|---|---|---|---|
| **15 开工定方向** | 👤 | 需求确认要委托方点头 | 建档、素材清点、缺件检索都能先做完 |
| **30a-2 捏脸定形** | 🔒 | 审美结果，且键值是委托方亲自定的、必须可复现；「这张脸对不对」只有本人能判，返工代价最高 | 30a-1 出候选、**30b 烘焙/导出/校验全自动**（[01](../01_自动化执行与并行.md)「30 应该拆成 30a / 30b」、[30](../30_捏脸.md)） |
| **40 配色定案** | 🎨 | 审美；作者 2026-09-01 授权下放给评审模型，**只在评审有分歧时上报** | 出候选、跨模型评审（[40](../40_贴图配色.md)、[05](../05_多模型评审规程.md)） |
| **95 上传与终审** | 🔒 | VRChat SDK 上传必须人操作 | 打包、校验、写交付说明全自动 |

关键路径上真正停下等人的只有 **15 → 30a-2 → 95**；40 定案与 70 真机验证可与 AI 的工作重叠。

### B · 必须用户亲手做的操作（遇到就按 [02](../02_环境准备与人工介入.md) 第三节的话术求助）

| 事项 | 为什么不能代做 | 何时 / 注意 |
|---|---|---|
| 首次在 `Window → MCP for Unity` 面板里选 Stdio | 面板是 Unity 内的 GUI，**进程起来了也点不到** | 选过一次就持久化 |
| 改面板 `Client Project Dir` 并 Configure | 同上 | 改完要重启会话 |
| **重启 Claude Code 会话** | 客户端配置改完必须重启才加载 | — |
| 退出**用户正在用的** Play 模式 | Play 期间不编译，且人可能正在里面测试 | 自己开的审查用 Play 可自理（09-18 授权） |
| 往 `Packages/` 加包之后重启 Unity | 刷新与解析包都不够，dll 不会出现 | — |
| VRChat SDK 上传 | 必须人操作 | = A 表 95 |
| **面捕（FT Addon）安装** | 安装器**会克隆整个头像**，场景里变成两个、原件被停用；**所有按名字找头像的工具都会改错对象** | **最后装**，排在全部作业之后 |
| **指甲（HoroNail 等）的 GUI Execute** | 厂商组件走 Play-模式-触发+自毁，不能持久化；GUI 内部是 UIElements 树，无法安全脚本化点击 | 装配阶段 |

**面捕装完之后**：核对场景里**只有一个活的头像根**。发现两个就停下报告，不要自己删。
面捕那份是**下游产物**：模型修改一律做在**原件**上，面捕根可以**重新生成**。

### 不算卡口、不用先问的（已授权）

- Unity、Blender 没开就**自己起**（2026-09-06）；审查用的 Play 进出、崩溃后重启自己开的 Unity 也自理（09-18，结束后还原 Play 改掉的 ProjectSettings）。
- 反过来，**不可逆动作**（删存档、覆盖交付包、丢弃场景改动、强退 Play）即使技术上能做，也先问（工作区 `CLAUDE.md`）。
