## 防穿模的身体收缩键

> ⚠ 2026-09-18：身体形态键适配服装在现有工程里都没做好，本节流程**测试不完全**，只当正反皆有的样本，待按新回归规程重写（见 [70](../70_回归测试.md) 页首）。


**挂 MA Shape Changer 在衣服部件上，别留在厂商的换装动画里。**
Shape Changer 是 ReactiveComponent，衣服物体失活即不生效，**天然跟着衣服走**；
而写在动画里的收缩键跟着「参数为真」走 —— 会出现「明明穿着别的衣服，肩膀也被衬衫的收缩键收掉」。

> 实测：某厂商的上衣开关动画直接把身体网格的肩部收缩键设满来收掉肩膀，
> 只要参数为 1 这条动画就一直在播。

## 穿模与收缩键：可执行的检查流程

> ⚠ 2026-09-18：身体形态键适配服装在现有工程里都没做好，本节流程**测试不完全**，只当正反皆有的样本，待按新回归规程重写（见 [70](../70_回归测试.md) 页首）。


**厂商给不给收缩键是不一定的，必须逐套查。**
> Kaguya 单实测：MMN 三套和 ANEMONE 两套**自带** `ModularAvatarShapeChanger`；
> 而 Kitty Crop Shirt 和 Re-Poppin' Cat **只有 MergeArmature，一个收缩键都没有** —— 这两套要手挂。

| # | 动作 | 判据 / 产出 |
|---|---|---|
| 1 | 列出素体网格的**收缩键候选** | 遍历直挂头像根下的 SkinnedMesh，筛形态键名含 `OFF` / `hide` / `shrink` / `消` / `非表示` |
| 2 | 列出每套服装**已有的** ShapeChanger | `GetComponentsInChildren<ModularAvatarShapeChanger>`，dump 出 `ShapeName / Value / referencePath` |
| 3 | 差集 = **候选补挂清单** | 有服装覆盖该部位、但没有对应收缩键的，就是嫌疑 |
| 4 | 逐套截图判定**真的需要哪些** | 见下「别想当然」 |
| 5 | 挂 `ModularAvatarShapeChanger` **在衣服部件本身上** | 它是 ReactiveComponent，所在物体失活即不生效，天然跟着衣服走 |
| 6 | 厂商动画里打在素体网格上的 `blendShape.*` 曲线**全部归零** | 改值不删曲线（更安全、可回滚） |

```csharp
var sc = Undo.AddComponent<ModularAvatarShapeChanger>(part.gameObject);
sc.Shapes = shapes.Select(s => new ChangedShape {
    Object = new AvatarObjectReference { referencePath = "Body" },
    ShapeName = s, ChangeType = ShapeChangeType.Set, Value = 100f }).ToList();
PrefabUtility.RecordPrefabInstancePropertyModifications(sc);
```

**别想当然，逐套实测。**
> 工程G四套衣服**都不需要脚部收缩键** —— 素体靴子完全包住脚 / 露趾凉拖（脚趾本就该露，加了反而错）/
> 另两套赤脚。`Body_Base` 备着完整的 `Foot_OFF` / `Toe_OFF` 却一个没用上。

**静态渲染只能查 T-pose。** 袖口、裙摆、腋下这类地方要在 Gesture Manager 里**过动作**才看得出来。

**代价要知道**：收缩键从动画搬到 ShapeChanger 后**粒度变粗** ——
厂商原本能在「短袖」模式下把 `Upper_arm_OFF` 单独设回 0，整体绑定后短袖时上臂仍被收掉。
要保精细度得再挂一层反应式条件。

## 收缩键分两族：**姿态类**随便用，**删除类**要先量鞋的包覆范围

### 触发

**给一套鞋选脚型键时**，尤其是候选里出现 `Shrink_*` / `*_OFF` / `hide` 这类名字。

### 问

**「这只鞋**包住**了脚的哪些部分？露出来的部分，我这个键会不会把它删掉？」**

素体的脚部键其实是两族，代价完全不同：

| 族 | 典型键名 | 干什么 | 用错的后果 |
|---|---|---|---|
| **姿态类** | `Toe_heels` `Toe_highheels` `Foot_heel_OFF` | 改脚的**角度**，几何量守恒 | 姿势不贴合，看得见但不致命 |
| **删除/收缩类** | `Shrink_Foot` `Shrink_Ankle` `Foot_OFF` `Toe_OFF` | **删顶点 / 把体积缩到 0** | 鞋一旦不是全包，**露出来的地方是空的** |

删除类的前提是**鞋完全包住那个部位**。靴子、高帮鞋成立；
**船鞋 / 乐福 / 露趾凉鞋 / 露脚背的任何款式都不成立**。

### 答错了怎么办

删除类换成姿态类。**姿态类可以叠加**（本单最终用的是 `Toe_heels=100` + `Toe_highheels=100`），
调的是脚掌与脚趾的角度，几何一根不少，露出来的部分照常渲染。

真的还穿模，就往「把**鞋**改大 / 加内衬」的方向走，不要回头去删脚。

### 判据（⚠ 别用"看着干净"）

**不能用像素方差 / 边缘数 / "画面整洁度"这一类的整体统计量** ——
**把脚删掉会让这些指标全部变好**，判据会稳定地推荐最坏的那个选项。
（这条踩过，见 [变量判据的自检问句](../问题定位/观测口径.md)：
「如果我把被测物**删掉**，这个指标会不会变好？」会 → 判据是坏的。）

要量的是**几何本身**，用 `BakeMesh` 出实际网格：

| 量 | 期望 |
|---|---|
| 脚部顶点包围盒**长度** | 施加键前后变化 < 5%（姿态类会变角度，不该变长度） |
| 脚部**体积 / 顶点数** | 同上；**掉一半就是被删了** |
| 脚最低点 vs 鞋最低点 | 脚在鞋内（差值为负） |

### 证据（2026-09-08 工程C · Outfit_VioletNocturne）

作者指出「鞋子是一个船袜，为什么把脚背和脚尖都缩为 0 了」。
量下来：`Shrink_Foot=100` 让脚**缩短 32%、体积近乎减半**，
而这只鞋是**开口露脚背**的款式 —— 鞋口里直接是空的。

我当时选这个键，是因为跑了「五档形态键 × 五套服装」的离屏扫描、拿**像素方差**当判据。
**方差最低的那一档正是"把脚删掉"的那一档** —— 判据不是量错了，是**方向就是反的**。

- 胸型跟随：衣服带身体同名胸型键却没人同步（胸型拉满时穿出）→ `50_服装发型装配/胸型跟随_同名键无人同步.md`
- 衣物缺身体某个键（乳贴没有 `Breast_small`）→ Unity 里给原网格副本加帧，不经 FBX → `50_服装发型装配/给衣物补形态键.md`

## MA ShapeChanger 的六条语义（MA 1.18.1，按源码核过 · D-22）

| # | 语义 | 可查问句 / 后果 |
|---|---|---|
| C1 | `ChangeType` 只有两个值：**Delete=0、Set=1** | 序列化 JSON 里就是 0/1，别按面板文字猜 |
| C2 | **Delete 删的是顶点**，不是把键设成 100 | 面板 Set=60、**同物体同键**还有一条 Delete —— 两个字段各自合法，但 Set 作用的顶点已被删/隐藏，等于白设 |
| C3 | 多写者按**层级先序**（`GetComponentsInChildren` 的顺序），**后注册者覆盖** | 两件压同一个键的衣服同开时，胜负由先序决定：先按先序预测胜者，再渲图对账 |
| C4 | **Set 随宿主物体停用自动恢复**（ReactiveComponent 特性） | 所以「脱衣后身体不恢复」只可能出在**动画层直接写形态键**那几处，不会出在 Set |
| C5 | **常驻 Delete 构建期物理删顶点**（`RemoveVertices`）；随开关变化的 Delete 走 **NaNimation**（删除生效时骨骼 scale=NaN） | 量删除区只能读**编辑模式**的原网格 —— Play/构建后那批顶点要么没了、要么是 NaN。可查问句：「我量的这批顶点，在 Play 里还是原来那批吗？」 |
| C6 | 删除区按写者自己的 `m_threshold`（默认 0.01，**网格局部单位**）＋图元级选择算 | 不是世界坐标 0.1 mm，也不是「delta>0 就算」 |

### 三条硬规矩

1. **禁止同一物体同一键同时 Set 和 Delete**（C2）——扫到就报，别想着"两个都留着更保险"。
2. **常驻 ShapeChanger 单独声明**，不要和随开关的混在一张表里：前者构建期就把顶点删了，**不可回退**。
3. **滑块/轮盘抢键时先查层权重**：动画层与 MA 反应层谁赢，只有构建产物或运行态知道；
   层默认权重 0 又没人抬权的层，拨了也没反应 —— 先读烘焙后 FX 每层的 `m_DefaultWeight` 并对照全部 LayerControl。

### Set / Delete 的取舍：先问「能不能退回去」

| | 能回退吗 | 什么时候用 |
|---|---|---|
| **Set** | 能（宿主物体停用即恢复） | **默认选它** |
| 随开关 **Delete** | 能（NaNimation，运行时隐藏） | 顶点必须真的消失：镂空、透视布料下面 |
| 常驻 **Delete** | **不能**（构建期物理删除） | 确定这套永远用不到那批顶点，**且和用户确认过** |

### 袜子 Delete 脚部键：必须对照**同穿的鞋款**

袜子把 `Toe`/`Foot`/`Ankle` 删掉，在默认包脚鞋下看不出问题；换**露趾 / 镂空**鞋就缺趾、空洞。
做法：列出全部对脚部键的 Delete → 按厂商展示图把可同穿的鞋分成**露趾 / 镂空 / 包脚**三类 →
每类各渲一次脚（低机位 ＋ 俯视）。归属本身怎么定见 [脚型与收缩键归属](脚型与收缩键归属.md)。
