# 50 · 厂商变体：什么时候只能再装一份实例

> ← [50 · 服装与发型装配](../50_服装发型装配.md)

这页解决的问题：厂商给了同一套衣服的**两个变体预制体**（兜帽上/下、带帽/不带帽、长袖/短袖…），
客户要求「某些档位用 A、某些档位用 B」时，该怎么实现、代价多大。

---

## 一 · 先量差在哪，再决定怎么做

### 触发
**发现厂商目录里有 `Hood_Off/` `NoCap/` 这类同名变体，且需求要在运行时切。**

### 问
**「两份到底差在网格、材质、激活状态，还是骨架姿态？」**

按代价从低到高，四种可能：

| 差在 | 判据 | 实现 |
|---|---|---|
| 只是**激活状态**不同 | 逐路径比 `activeSelf` | 一个 Toggle 就够，不用第二份 |
| 差**材质** | 比 `sharedMaterials` | 动画换材质数组 |
| 差**网格**（各有各的件） | 比路径集合 | 两组件各自开关 |
| 差**骨架姿态** | 逐骨比局部变换 | **必须第二份实例**，见下 |

### 判据（脚本，不看图）
逐路径 dump 两份预制体的 `(网格名, 顶点数, activeSelf, 组件列表, 局部变换)`，
只打印**有差别**的行。⚠ 按**完整路径**比，不按名字 ——
服装里 `Jacket` / `Tops` 常常既是网格名又是 PhysBone 节点名。

### 证据（2026-09-08 工程B_Milfy · LopEarMine）
441 个物体逐路径比：网格集合完全一致，**唯一的差别是骨架**——
`Hood_Root` 及其子骨 23 根里有 **5 根局部变换不同**
（兜帽根 rot 0.13° → 286.07°，即往后倒 74°；两侧耳朵与缎带根都重摆过），
父骨还从 `Head` 换成了挂在 `Chest` 下的新骨 `Hood1`。

## 二 · 差在骨架姿态时：约束复现不了

### 问
**「差的只是父骨，还是子骨的局部姿态也不同？」**

- **只差父骨** → 可以只加一个可切换父级的约束，不必复制
- **子骨局部姿态也不同** → **作者是摆过姿势的**，约束复现不出来，只能上第二份实例

### 答错了怎么办
硬拿约束去凑，静态站姿看着对，**一动就不对**（尤其头部跟着转）。
别在这上面省事 —— 复制实例的代价其实很小，见下一节。

---

## 三 · 但**不必整套复制**：只复制真的蒙在那些骨上的网格

### 判据（逐顶点算骨权重）
1. 取变体差异所在的骨链（例：`Hood_Root` 及其全部子骨）；
2. 对每个 `SkinnedMeshRenderer`，找出 `bones[]` 里落在该骨链上的索引；
3. 数**权重 > 0 命中这些索引的顶点数**。>0 的才需要复制。

⚠ 不能只看 `bones[]` 里有没有 —— 挂在骨数组里但权重全 0 的不算。

### 证据（同上）
23 个网格里只有 3 个需要复制：

| 网格 | 顶点 | 蒙在兜帽骨上的顶点 | 占比 |
|---|---:|---:|---:|
| `Jacket` | 14165 | 796 | 5.6% |
| `Jacket_Ear` | 6862 | 6862 | 100% |
| `Jacket_Ear_Pin` | 3056 | 3056 | 100% |

其余 20 个（裙、上衣、袜、鞋、背包…）不受影响，共用现有那份。
代价从「整套 ×2」降到 **+3 蒙皮网格约 24k 顶点 + 24 根骨**。

## 四 · 第二份实例怎么装

### 结构：容器门控
```
_Outfit/<容器>                    ← 整套轮盘管这一层
  ├ <原件>                        ← 全部网格 + 全部 MA 组件
  └ <变体>                        ← 只留受影响的网格 + 骨架
```
容器关着时子物体是什么状态都无所谓 —— 这样部位层/饰品轮盘才能自由写子物体，
不会在别的整套档位下把这套衣服放出来。详见
[60 · 属性归属与写法](../60_菜单与动画层/属性归属与写法.md)。

### 变体那份要删什么、留什么

| 组件 | 处理 | 为什么 |
|---|---|---|
| `MA MergeArmature` | **留** | 新骨链要靠它并进头像骨架 |
| `MA MergeAnimator` | 删 | 否则厂商的层会合并两遍 |
| `MA Parameters` | 删 | 否则厂商参数会声明两遍 |
| `MA MenuInstaller` / `MenuItem` | 删 | 否则厂商菜单装两遍 |
| 不受影响的网格 | 删 | 白占性能预算 |

⚠ 要删预制体实例的子物体，**必须先 `UnpackPrefabInstance`** —— 直接删会报
「Cannot delete GameObject that is part of a Prefab instance」。

### 接线：厂商的层管不到第二份

厂商参数（如 `LEM/Jacket`）只写**原件**的路径。所以：

- **部位开关**要自己写变体那份的显隐（用完整路径 —— 容器下两份里有同名网格，按叶子名解析会二义）
- **饰品轮盘**只负责在两份之间**压掉一份**：
  自己档不写原件（让厂商与部位开关决定）、其余档写 false；变体那份反过来。
  两边都由部位开关放、由轮盘压，**没有任何一层去 force-on** ——
  这样「关了上衣还挂着兜帽」不可能发生。

### 回读判据（装完必查）

| 判据 | 期望 |
|---|---|
| 容器下的子物体数 | == 2 |
| 变体那份的网格 | == 上面第三节算出来的那几个 |
| 变体那份的 `MergeArmature` | == 1 |
| 变体那份的 `MergeAnimator` / `Parameters` / `MenuInstaller` | == 0 |
| 与原件**逐完整路径**比局部变换 | 只在变体骨链上不同，其余 0 处不同 |
| 只在变体里的路径数 | == 新增骨链的根数（本例 24 = `Hood1` + 23 根） |
| 所有权审计 | 变体那份的网格「有层写过 1」 |

⚠ 不要用「最长骨段 < 500 mm」这类绝对阈值查骨架 ——
骨架根下的 `Hips` 局部坐标就是胯高 760 mm，**每次都误报**。
用原件当**对照样本**逐路径比才对。见
[判据的形状](../问题定位/观测口径/判据的形状.md)。

## ⚠ 实例化厂商预制件时别动根 Transform：厂商把「适配缩放」烘在根上（09-22 工程A）

**触发**：用脚本把厂商服装预制件实例化到头像下（`InstantiatePrefab` 后又设 `localPosition/Rotation/Scale`）时。
**问**：**实例根的 `m_LocalScale` 有没有被覆盖？厂商原值是多少？**（`PrefabUtility.GetPropertyModifications` 里查 `m_LocalScale`）
**证据**：Velour 的 Kaguya 版预制件用的是另一素体（Mizuki）的网格，厂商在根上烘了一个小于 1 的适配缩放（各素体版各不相同）；我们的实例根被覆盖成 1 ⇒ 整件大一圈、上移约 0.23 m，袖子悬在手臂上方。
MA 合并**保留网格世界外观**（`MeshRetargeter.cs:239-240` 改 bindpose 不改位姿），所以根缩放错了，合并后照样错位，主干骨照样「全部吸附」。
**同体系不同尺寸的素体**（IKUSIA 的 Mizuki / Rurune / Kaguya 同一身体、尺寸不同）：厂商只给 Rurune 包时（PuNyaNya 标「Rurune/Kaguya」的变体只附 Rurune 版），
原样套 Kaguya 会上移 13–18 cm；按同家族厂商自己给各素体版烘的根缩放求比值（目标素体版 ÷ 包内所附素体版）缩根即可对齐——这不是自创数值，要在施工记录写出比例的出处，并先问用户。
