# 给衣物补形态键（厂商没给某个胸型/体型键时）

> 上级：`../50_服装发型装配.md`。2026-09-19 工程D Esmera 乳贴补 `Breast_small`，第一次走 Blender 失败、第二次在 Unity 里直接做成功。
> 复跑脚本（C-12）：`开发工具/通用工具/审查/unity/Editor/NipplePatchFrames.cs`，菜单 `Tools/AvatarAudit/Nipple Patch Frames (Edit Mode)`；请求 `Library/AvatarAudit/nipple_patch_frames_request.json`，示例 `审查/unity/examples/nipple_patch_frames_request.json`（工程D两帧原件数值）。

## 触发
身体某个键会被驱动（胸型轮盘、脚型档），而某件贴身衣物/饰品**没有这个键**，于是身体一变它就浮起或陷进去（乳贴在 `Breast_small=38` 时外浮 4–8 mm）。

## 首选：Unity 里给原网格副本加一帧（不经 FBX）
1. 编辑模式，场景真实骨骼下：身体该键取 0、100 各 `BakeMesh` 一次 → 世界空间位移场。
2. 件 `BakeMesh` 一次；每个件顶点取身体最近 4 个顶点的位移做反距离加权 → 世界位移。
3. 用件的蒙皮矩阵 `Σ wᵢ·(worldToLocal·boneᵢ.localToWorld·bindposeᵢ)` 的逆把世界位移换回网格空间。
4. `Instantiate(原网格)` + `AddBlendShapeFrame(键名, 100, 位移, null, null)` → 存成 `.asset` 放 `Assets/_Work/…`；渲染器只换 `sharedMesh`（骨骼、材质不动，**不 Apply 到厂商预制体**），再加 MA BlendshapeSync 绑身体同名键。
- 好处：基础几何、骨骼权重、bindpose 与原件**逐位相同**，不存在导出空间问题。脚本即上面四步，约 40 行 `execute_code`。

## 为什么不先走 Blender
Blender 里做完、在 Blender 里往返核对是「0.000 mm」，但**导回 Unity 后蒙皮结果偏了 71 mm**：导出的网格空间与 bindpose 和厂商原 FBX 不同（顶点差到 1 m 级、bindpose 差 1.27、位移被缩了 100 倍），而渲染器用的是场景里原来的骨骼。
- **可查问句**：「换上新网格后，身体键为 0 时件的 `BakeMesh` 世界坐标和原网格逐顶点差多少？」—— 必须 ≈0，否则别往下做。
- 真要走 Blender（比如要雕细节），验收一律在 Unity 里做上面这条比对，不认 Blender 内部的往返数字。

## 验收
编辑模式量件到身体最近距离分位数：新件在身体键 0 / 默认 / 100 三档都应与「0 档原件」同量级（工程D：p50 1.33 → 1.28 → 1.13 mm；原件在 38 档 5.74、100 档 14.48）；0 档新旧逐值相同。Play 里只读回键值（件的键跟身体走），**不要**在 Play 里换网格做对照（见 `收缩键可见后果_渲图对照.md` 末节）。
- 跨工具核对键时注意：Unity 的形态键索引不含 Basis，比 Blender 的 shape_keys 索引小 1；按名字对，不按索引。服装自带骨架导入后骨骼改名/合并时，按骨骼名兜底匹配。

## 改「已有」键的帧（09-23 舌钉链 L6-A）
Unity `Mesh` 没有改某个形态键帧的 API：只能 `ClearBlendShapes()` 后把**全部**键按原顺序（或新顺序）重新 `AddBlendShapeFrame`。重灌后键的下标可能变，渲染器上的 `SetBlendShapeWeight` 与动画绑定都要**按名字**回填，不能按下标。
