## 一、装配方式：先分类，再决定

**分类的依据是「它自己带什么」，不是它叫什么。**
动手前一律先跑一次组件探测（列出预制体上所有组件类型名），
按下表对号入座。**跳过探测直接加组件是本阶段最贵的错误。**

| 类别 | 怎么认 | 装法 | 最容易犯的错 |
|---|---|---|---|
| **整套服装 / 发型**（人形同构） | 有 `Armature`，骨名与素体人形主干对得上 | MA **MergeArmature** | 比文件名判兼容 → 应比骨骼 |
| **自带 BoneProxy 的件** | 预制体上已有 `BoneProxy` | **原样用**，别再加 MergeArmature；自己新加时不用 BoneProxy，见 [55 铁律三](55_配饰装位.md#铁律三不用-ma-boneproxy--编辑期不生效) | 加了 MergeArmature 实测**映射 0 根骨**；且 BoneProxy **编辑期不生效**，看着没动是正常的 |
| **环状件**（戒指 / 腕饰 / 头环 / 颈环） | 有孔，要套在肢体上 | 算孔轴与孔心 → **直接父子挂骨** | 位姿靠手填 → 应当**全算出来** |
| **带骨架配饰**（耳尾这类，非人形） | 自带 `Armature` 但骨名与人形对不上 | 挂厂商的转接节点 | 挂完**不查骨段长度** → 静态全对、动骨一跑就甩飞 |
| **悬浮 / 贴面件**（发饰、面板、光环） | 无骨或单骨，贴着表面放 | 按参照面摆 | 参照面取错：**是渲染出来的那个面**，不是骨骼位置 |
| **抱持类**（怀里抱的东西） | 需要手臂姿势配合 | 物体挂胸前 + 手臂姿势**走 Additive 层** | 手臂放 Gesture → 关掉时手臂被写死（见 [人形手臂与手指](60_菜单与动画层/人形手臂与手指.md)） |
| **骨架内部的静态挂件** | `MeshFilter` + `MeshRenderer`，塞在 `Armature/…` 下面 | 跟着它所属的那组走 | **最容易整个漏掉** —— 衣服是 SkinnedMesh，这类是静态网格，按渲染器类型捞才找得到：`find_gameobjects(by_component: MeshFilter)` 一把捞出所有静态网格（实测：鱼玩具塞在 `armature/…/Bag/ContentsPosition/` 下，关掉包之后它留在原地飘着）（本条正本） |

### 三条跨类别的通则

**① 位姿是算出来的，不是填出来的。**
能写成闭式判据的（是否套住、偏心、夹角、骨段长度）**根本别喂图**，直接在脚本里断言。
图只用来看细节纹理与穿模。

**② 参照面是渲染出来的那个面，不是骨骼或包围盒。**
「埋进去多少」要就地量渲染面，别拿颅骨中心或包围盒边界当基准。
且多数是**顶端对齐**，不是中心对齐。

**③ 通用包换素体先判尺寸，再判位置。**
面向别的素体做的通用配饰包，装到新素体上**先按素体尺寸等比缩放**。
先调位置会得到「位置对了但大小离谱」，返工两次。
比例从厂商渲染图上量。

## 二、冲突处理：先分清是哪一类

**三类冲突的语义完全不同，用错做法的后果也完全不同。**
分类问题只有一个：**「用户之后还能不能自己把 B 打开？」**

| 类 | 语义 | 做法 | 用错的后果 |
|---|---|---|---|
| **甲 · 切换时顺手关** | 关一次，用户之后**还能再开** | `VRCAvatarParameterDriver` **改 B 的参数** | 写成属性 → B **永久打不开** |
| **乙 · 开着期间压制** | A 开着就一直压 B，A 一关 B 自动回来 | **单独一层**写 B 的属性 | 用 Driver → 用户手动开回来就又穿模了 |
| **丙 · 同位置互斥** | 两件同位置的东西不能同时出现 | 定**优先级链**，只压低优先级那一侧 | 两个方向都压 → **两边一起消失** |

> **一句话记法：改参数 = 关一次；写属性 = 一直按着。**

### 乙类的写法（关键在「关闭档必须什么都不写」）

```
层：<配饰>_Suppress        排在部位开关层与整套层之后
  ├─ Empty     默认状态，clip 无任何曲线   ← WD=OFF 下未写的属性从前面的层原样透传
  └─ Suppress  条件 <配饰参数> == true，clip 写 <被压物体>.m_IsActive = 0
```

**判据**：关掉配饰后那件衣服子内容**能自己回来** = 对；回不来 = 你把它写死在别的层了。

### 丙类：一对冲突只能压一个方向

两条方向相反的压制规则同时成立时会**互相把对方压没**，
用户看到的是「这个位置什么都没有」，而不是「某一个没显示」——
因为不是任何单条规则出错，**逐条检查规则也查不出来**。

**规矩**：
- 先定一条**全局优先级链**（例：头饰 > 服装头部小件 > 耳朵），冲突一律按链子压
- 冲突表里出现「A 压 B」和「B 压 A」两条就是错的，不管是不是同一批加的
- 表里每一条都要能说出**它在优先级链上的位置**；说不出来的那条就是多余的

**验收要遍历「组合」，不是遍历「单项」**：跑遍 `档位 × 冲突开关` 全组合，
对每一格断言「这个身体位置上至少有一件是开的」，死锁格 == 0 才算过。
断言必须用**真动画数据**驱动，手动开关物体证明不了动画层会怎么写。

### 互斥接线：三层分工，别都堆在一层

「A 与 B 互斥」不是一个动作，是三件事分给三个地方：

| 写在哪 | 写什么 | 为什么 |
|---|---|---|
| **被控层自己** | B 的层 On 写 `A=false`、Off 写 `A=true` | 互斥的另一半属于 B 自己的职责 |
| **后面的层** | **只在需要强制时**写，其余档位**两个属性都不碰** | WD=OFF 下不动的属性会从前一层原样透传 |
| **切换动作** | 用 Driver 改参数 | 「顺手关」是一次性动作，不是持续压制 |

**反例**：把 `A=false` 无条件写进排在后面那层的每个 clip →
等于把 A **永久压死**，菜单里再也打不开。

## 三、症状 → 该查哪里

| 症状 | 第一嫌疑 | 去哪查 |
|---|---|---|
| 某个开关**怎么点都没反应** | 排在它后面的层**无条件写了同一个属性**（WD=OFF 下后写的盖掉前面；菜单参数确实变了，参数面板看一切正常，只有物体不动） | 扫所有层，找写同名属性且无条件的 clip |
| 某个位置**一件都不显示** | 两条方向相反的压制规则互压 | 本页第二节丙类 |
| 网格**在**，但形状 / 位置不对 | 厂商参数层还在按旧值摆骨骼 —— 只写了网格显隐 | [60 主页](60_菜单与动画层.md) 一句话铁律 |
| 关掉某件后**有东西留在原地飘着** | 骨架内部的静态挂件漏掉了 | 本页第一节最后一行 |
| 外套 GameObject **在但完全不渲染** | 换过 FBX，骨架锁把外套骨架同步坏了 | 拆装一次即恢复；见 [50 · 换 FBX 之后必然错位](50_服装发型装配.md#换-fbx-之后必然错位) |
| 配饰静态全对，**一动就甩飞** | 转接节点的骨段长度异常 | [带骨架配饰](55_配饰装位/带骨架配饰.md) |
| 编辑期看着没装上 | BoneProxy **编辑期本来就不生效** | 不是缺陷，别去"修" |
| **上传选错根**、或报告里根数互相打架 | 场景里有多个根，「几个」有四种口径（场景根 / 全场景 descriptor / **活跃根** / 含备份 prefab） | [头像根口径](03_装配与冲突通则/头像根口径.md)；[10](10_接单建档.md) 步骤 6、[90](90_交付打包.md) |
| 开了配饰只见**光秃秃的本体**，装饰不见了 | 把「装饰」当成「变体」接成了互斥 | 本页第五节 |
| 两件长得很像的东西**互相穿插** | 把「色变体」当成「装饰」接成了同开 | 本页第五节 |
| 换了材质却**渲成实心 / 不透明** | 换 shader 没跟着换渲染状态 | [素材与材质排查 · 七](问题定位/素材与材质排查.md) |

## 四、开工前的两个提醒

**厂商自己的分组就是权威答案。**
扫一遍厂商动画里所有 `m_IsActive` 曲线的路径，就知道哪几样是一组的 ——
比按名字猜可靠得多（实测：那个「包」实际是三件 —— 包体 + 名牌 + 包里的鱼玩具）（本条正本）。名字经常骗人：同一个名字可能既是参数又是 GameObject，
而它们管的**根本不是同一件事**。

**能用厂商参数直驱就别自建层。**
菜单控件直接挂厂商参数：不占新 bit，厂商的联动（互斥、骨骼姿势、摆动动作）全都白拿。
默认值不合适就改厂商的参数资产 + 控制器**两处**。

## 五、**装饰**还是**变体**：接线方式相反，判据不能用包围盒

### 触发

**厂商一个配饰目录下有几件长得很像、位置几乎重合的东西**
（`Ears` / `Rose_Ears`、`Tail` / `Roses_Tail`），要决定菜单怎么接。

### 问

**「这两件是"同一个东西的两种样子"，还是"一个东西 + 挂在它上面的装饰"？」**

两者的接线**完全相反**，选错必然出错：

| | 变体（A 或 B） | 装饰（A 带着 B） |
|---|---|---|
| 接线 | **互斥**：开一个必须关另一个 | **同开**：B 的开关跟着 A 走 |
| 选错的症状 | 两件互相穿插（白耳里插着粉耳） | 只显示光秃秃的本体，装饰不见了 |

> → [装饰与变体的判据](03_装配与冲突通则/装饰与变体的判据.md) —— 为什么包围盒答不了、逐顶点最近距离中位数判据（<2mm 变体 / >5mm 装饰）、一正一反两个样本。
