# 「骨段 <0.5 m」判据要分两步，不然会产生假阳性 STOP

> 从 [`55_配饰装位.md`](../55_配饰装位.md) 拆出的子页。接手自主页该判据一节；步骤 3 的「每段骨到父骨距离 ≤ 30cm」判据仍留主页。

## ⚠ 「骨段 <0.5 m」这条判据要分两步，不然会产生**假阳性 STOP**

**判据的目的是抓「动骨一跑就甩飞」**，而不是抓「层级上有个长偏移」。
VRCPhysBone 的**根节点本身不参与模拟**，只有子节点动 ——
**落在 PhysBone 根之上的长骨段是静态的，不会甩飞。**

### 两步

1. 量所有新增骨段，标出 ≥0.5 m 的
2. **逐条查它在不在某个 PhysBone 的模拟链里**（父节点是不是某 PhysBone 的 `rootTransform` 或其后代）
   - **在** → 真问题，必须修
   - **不在** → 静态偏移，**这一条判据放行**

### ⚠ 但「不甩飞」≠「位置对」

长偏移的第二个风险是**把配饰推到离挂点很远的地方**。这要**另用世界坐标判**：

| 件类 | 判据 |
|---|---|
| 头饰 / 兽耳 | `‖配饰根.world − Head.world‖ < 0.15 m` |
| 腰饰 / 尾巴 | `‖配饰根.world − Hips.world‖ < 0.20 m` |

**骨段长度判不出位置对错，世界坐标才行。** 两条判据分开做，别混。

### 怎么读 PhysBone 的根（不必开 Unity）

`VRCPhysBone` 按 GUID 引用脚本，**预制体文本里搜不到类名**。
搜字段名 **`rootTransform` / `ignoreTransforms` / `endpointPosition`** 定位组件块；
`rootTransform: {fileID: 0}` 表示**根是组件所在的那个节点自身**。

### 实例（2026-09-07 工程C · GOTHIC ROSE 狐耳）

```
Head → Armature(Place in Head) → Ears_Root → Ears.001~004
                                 ↑ 1.2579 m      ↑ PhysBone 挂这，root=自身
```
55 那一路按原判据触发了 STOP —— **行为完全正确**（它撞上了字面条件就停下、没有自己发挥）。
**是判据写得不够精确**：没说清「超标的骨段要看在不在模拟链里」。
