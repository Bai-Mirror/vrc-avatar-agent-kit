# 14 · 选型图鉴　🤖

> 给客户挑素材用的**图鉴**（又叫选材图鉴）：图 + 中文名 + 风格标签 + 可勾选，
> 客户在聊天工具里挑完、把清单发回来。
> 排在 [10 接单建档](10_接单建档.md) 之后、[15 开工定方向](00_总表.md) 之前；
> 与 [12 参考图解读](12_参考图解读.md) 互不依赖，可并行。
> **产出**：`<订单目录>/选型图鉴.html` + `选型图鉴.pdf`，以及客户回传的清单。

## 为什么是两份、各自不能承诺什么

客户看不懂文件夹名，也不会翻 Booth；**给图 + 中文名 + 风格标签才挑得动**，勾选回传比截图省一轮来回。
只发一份的代价是客户打不开或勾不了、多一轮来回（按天计）；两份都做的代价是 PDF 管线多花的时间（按小时计）。

| | 单文件 HTML（**主推**） | 可勾选 PDF（兼容件） |
|---|---|---|
| 缩略图 | WebP **480px / q74**，base64 内嵌，零外链 | 换 **320px** 重建一版压体积 |
| 交互 | 品类筛选、搜索、点图放大、勾选计数、**「复制清单」**把勾选拷成文本 | `/Btn` 勾选框 + 一个 `/Tx` 多行备注框 |
| 做不到 | — | **一键复制清单**：要 PDF 内嵌 JS，只有 Adobe Reader 执行，Chrome / Edge / WPS / 手机端都不跑 |
| 微信 / QQ 内置预览 | 能开 | **只能看不能勾** |

**两份的文案分开写**，PDF 版不许承诺网页版才有的功能。

**体积从哪来**：187 项 ≈ 5.5 MB，约 30 KB/项，是「转发得动、又看得清风格」的实测点。
图再大 → 单文件超出聊天工具的转发上限；再小 → 蕾丝、花纹这类风格细节看不清，客户挑不动。
条目远多于 187 时体积线性涨：先把 WebP 降到 320px（PDF 版验证过的那一档），再考虑按品类拆文件
（拆了客户容易漏看一份）；拆之前先量目标聊天工具的单文件上限。

**零外链是硬约束**：国内不依赖任何 CDN，**不能用 Google Fonts，字体只走系统栈**。
违反的症状是客户那边页面空白或字体卡几十秒 —— 而你自己机器上一切正常。

## 确定化步骤

### 步骤 1 · 汇合候选池　🤖

**前置**
- [ ] [10](10_接单建档.md) 的「开包核兼容」已做完，每件都有「支持 / 不支持 / 待骨骼比对」结论

**执行**
1. 客户素材包里**支持本素体**的件
2. 加上自有库（本机 `<素材库>`）里兼容的：按 `.booth-meta.json` 的结构化字段筛，**不要全文 grep** ——
   `avatars[]`（`{name, source, confidence, status}`）为主判据；`files[].avatars[]` 是最强信号（包里真的带该素体分包）；
   `variations[]` / `booth_tags[]` 补充。管道里商品名带空格、全角括号和 emoji，`xargs` 全程要 `-0`
   （漏一个 `-0` 目录名被切成多行，实测 164 vs 真值 56）
3. 每张卡标 **「她的库 / 我的库」**（客户自备 vs 我方追加 —— 交付时要分开打包，[90](90_交付打包.md)）

**后置判据**

| 期望 | 怎么读 |
|---|---|
| 条目数 == 客户包兼容件数 + 自有库命中数 | 三个数相加 |
| 每条来源标签 ∈ {她的库, 我的库} | 卡片数据列非空 |
| 10 判「不支持」的件在图鉴数据里命中 == 0 | 逐条 grep |

**STOP**
- 有件是「待骨骼比对」→ 先按 [50](50_服装发型装配.md) 比完再进图鉴，不要先放进去再说

### 步骤 2 · 出缩略图　🤖

**执行**
1. 每项取 `images/` 下的商品图，WebP 480px / q74，base64 内嵌；批量取图
   直接读本机 `<素材库>/*/images/`，按商品号通配定位

**后置判据**

| 期望 | 怎么读 |
|---|---|
| 每项图数 ≥ 1 | 数一下 |
| 总体积 ≈ 30 KB × 条目数（同数量级） | `os.path.getsize` |

### 步骤 3 · 生成 HTML　🤖

**执行**
1. 单文件：品类筛选 / 搜索 / 点图放大 / 勾选计数 / 「复制清单」

**后置判据**

| 期望 | 怎么读 |
|---|---|
| `src="http` / `href="http` / `@import` / `fonts.googleapis` 命中 == 0（步骤 4 的 PDF 用变体除外，它故意带 `x.pick` 链接） | grep 文件 |
| 勾 N 项后「复制清单」输出 N 行 | 浏览器里点一次 |

### 步骤 4 · 生成 PDF　🤖

**执行**
1. 用 320px 缩略图重建一版 HTML，**每个勾选位渲染成 `<a href="https://x.pick/<id>">`**
2. Chrome `--headless --print-to-pdf` 出片 —— 它会把链接原样输出成链接注释
3. pypdf 遍历各页 `/Annots`，把这些链接**就地替换**成 `/FT /Btn` 勾选框：
   给足 `/AP` 的 `Yes` / `Off` 外观流 + `/MK`；AcroForm 开 `NeedAppearances`
4. 另加一个 `/FT /Tx` 多行备注框
5. 验证用 pymupdf：`widgets()` 逐个置 True 后 `get_pixmap`，看勾选真的画出来

> 绕这一圈是为了**让 Chrome 替你算坐标**：链接注释的矩形就是元素在页上的真实位置。
> 自己算勾选框位置要跟排版硬对齐，版式一改全废。

**后置判据**

| 期望 | 怎么读 |
|---|---|
| `/FT /Btn` 数 == 条目数；`/FT /Tx` 数 == 1；残留 `x.pick` 链接 == 0 | pypdf 遍历 `/Annots` 计数 |
| 置 True 与置 False 的渲染图有像素差 | pymupdf `get_pixmap` 两张相减 |
| PDF 文本里「复制清单」命中 == 0 | 抽文本 grep |

**STOP**
- 勾选框数 ≠ 条目数 → 先列出哪些 id 没出现在 `/Annots` 里，回去改版式；**别手补坐标**

### 步骤 5 · 发出与回收　🤖

**执行**
1. 两份一起发；HTML 说明写「勾完点复制清单发我」，PDF 说明写「勾完存档发回」
2. 回传的清单原样存进 `<素材包>/客户需求/`，选中项回填 `_素材应用表.md` 的用途列（[20](20_素材清点导入.md)）

**后置判据**

| 期望 | 怎么读 |
|---|---|
| 回传清单每一项都能在图鉴数据里找到 id | 逐条 grep |
| 应用表里选中项「用途」列非空 | 表 |
