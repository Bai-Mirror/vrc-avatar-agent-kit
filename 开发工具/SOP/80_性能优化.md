# 80 · 性能优化　🤖

**顺序是固定的，别反**：
```
① 出基线报告 → ② 逐张列贴图找异常 → ③ 改导入设置 → ④ 挂 AAO → ⑤ 再出一次报告对比
```
**每步都留报告文件**，前后两份放进交付。

> → [PhysBone 压到 256](80_性能优化/PhysBone压到256.md) —— 256 是硬上限不是评级，构建期会 throw；面板数的是构建**前**的数所以 AAO 构建期合并减不掉它；场景内合并必须把非源链加进 `ignoreTransforms`（漏了会把 Spine/Upper_leg/LeftEye 变成物理骨）；空的 AAO MergePhysBone 会让预处理直接返回 false。

### 步骤 4 · 贴图：查格式 → 清死槽 → 分档　🤖

**前置**
- [ ] 步骤 3 通过（先找死重再分档）；已读子页「先查格式」「三个坑」「红线」

**执行**
1. **用脚本读运行时真值 `Texture2D.format`**，不要解析 `.meta` 的 `textureFormat`
   （⚠ 见下「为什么不能读 `.meta` 判格式」），同时读 `maxTextureSize`，不看平台覆盖
2. 只清「除死槽外没人引用」的贴图
3. 分档用 `tex_tier_plan.py` → 审核CSV → `tex_tier_apply.py`（只降不升，留回滚）；压缩格式另按运行时读数处理。旧 `TexOptimize.cs` 只作格式处理参考
4. `FixMipStreaming.cs` 开 Mip Streaming
5. 要降的显眼图先 A/B，图交 `agy_panel.py` 审（判据见子页红线），观感结论不自己下
6. 回读校验 + 骨架高度自检

**后置判据**

| 期望 | 怎么读 |
|---|---|
| 未压缩格式（`RGBA32` / `ARGB32` 这类）张数 == 0 | **脚本读 `Texture2D.format`**，不是读 `.meta` |
| `streamingMipmaps: 1` = 全部 | 重读 `.meta`（这个字段确实在 `.meta` 里） |
| 审核CSV逐条有处理结果，零失败 | apply报告及回滚记录 |
| 主图 `maxTextureSize` ≥ 2048（例外写占比依据）；其余 ≤ 原值 | `.meta` 前后对比 |
| A/B：≥2 模型无可见差异指认 | `agy_panel.py` 输出 |

**STOP**
- 贴图内存反涨 → 回子页「三个坑」；A/B 被 ≥2 模型指认看得出 → 不降

> → [为什么不能读 `.meta` 判贴图格式](80_性能优化/为什么不能读meta判格式.md) —— `.meta` 里 `textureFormat` 多是 -1（Automatic），按它数 RGBA32 恒为 0；要写探针读运行时 `Texture2D.format`；法线图的 DXT5nm 不能当普通 DXT5 转 DXT1。

## AAO

默认设置就很有效，但 `allowShuffleMaterialSlots` 和 `optimizeTexture` **默认是开的**，
回归时要**专门看材质错位和贴图接缝**。

配错会**直接中止构建** → [问题定位/构建被中止](问题定位/构建被中止.md)。

## PhysBone / AABB 上限

| 项 | 上限 | 工具 |
|---|---|---|
| PhysBone 总数 | 256 | `PhysBoneTools.cs`·PhysBoneCensus 按顶层子物体清点，找下手点 |
| 碰撞检查开销 | — | `PhysBoneTools.cs`·DumpPhysBones 列每根影响骨数 × 碰撞体数 |
| 重复 PhysBone | 0 | `PhysBoneTools.cs`·DedupePhysBones（**逐字段比对**确认冗余后才删） |
| AABB | 5×6×6 m | `AvatarDump.cs`·DumpBounds 找撑爆的渲染器（**粒子系统尤其容易**） |
| APS 手柄把 AABB 顶到 9.6 m | — | `FixAPSBounds.cs` |

合并 PhysBone 的四个入口（都在 `PhysBoneTools.cs`），按精确度递增选：
MergePhysBoneGroups（找可合并的兄弟组）→ MergePhysBoneExplicit（点名）→
HardMergePhysBones（编辑期真合并，五道闸门）→ ShedPhysBones（改目标表）

## 验收

| 项 | 判据 |
|---|---|
| 贴图内存 | 优化后 < 基线；且没有 RGBA32 的默认平台条目残留 |
| PhysBone | ≤ 256，且无重复 |
| AABB | 在 5×6×6 内 |
| 材质 | AAO 跑完后**逐件复检错位与接缝**（`allowShuffleMaterialSlots` 的代价） |
| 报告 | 前后两份都在，差异逐项可解释 |

### 四项必查（挂完 AAO、出优化后报告之前）

1. **阈值写成取舍，个人号也要过**：贴图阈值（主图 2048 / 遮罩 1024 / 小件 512）不是「商用才要」，个人号同样按这个降（多套服装必然 VeryPoor）；降前先 A/B。
2. **装了 AAO ≠ 挂了组件**：`Trace And Optimize` 必须在活跃根上；装了包但 0 组件是反复踩的坑。
3. **粒子 bounds**：粒子 `bounds` 撑爆 AABB（历史 Milfy 9.60 m），用 `AvatarDump.cs`·DumpBounds 列，别只看静止包围盒。
4. **无效 `MergePhysBone` 会中止构建**；**AAO 后必须重跑死参数检查**（AAO 删/改名 clip 路径）。

判据与实例 → [AAO 实际做了什么](80_性能优化/AAO实际做了什么.md)、[贴图](80_性能优化/贴图与动骨.md)。

⚠ **平台覆盖类改动编辑器验不出来**，见 [观测口径](问题定位/观测口径.md) 口径①「平台覆盖 vs 默认档」（现行审查方法见 [70](70_回归测试.md)）。
