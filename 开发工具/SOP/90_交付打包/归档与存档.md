# 归档与存档

> ← [90 · 交付打包](../90_交付打包.md)。触发：交付后归档，或用户要求把工程收纳起来。

```
7z/zip 直接打到 $ARCHIVE_ROOT/<个人存档|交付文件>/ → 对那一份跑 7z t → 删本地 → 更新 ../../_服务器备份名册.md
```
`ARCHIVE_ROOT` 是仓库根 `kit.env` 的配置项（存档目录，样例见 `kit.env.example`）；本机盘或网络盘都行，下文只认这个变量。
**删本地源之前必须验存档目录里那一份**，不是验打包前的源。
**分工**：打包、清理、Windows 专项检查、解包编译验证可以派 DSH；**拷进 `$ARCHIVE_ROOT/` 这一步由 Claude 做**——DSH 的沙箱里存档目录挂成只读（09-22 它据此误报「OS 级 ro、提权也改不了」，Claude 侧 `mount` 实为 rw）。Windows 可用性判据见工程B 09-22 施工记录（非法名/大小写重名/路径≤259/符号链接/file 与 git 依赖全 0，解包 batchmode 编译 0 错）。
菜单、动画器、材质这些制作成果**没有第二份权威副本**。

**归档用 7z/LZMA2，不用 zip/deflate** —— 同一份源实测多省约 **8.5%**（deflate 对 Unity 工程几乎无能为力）。

**先区分产物用途**：上一句指工程文件的存档件；客户拿到的“工程zip＋素材zip＋说明”交付总包仍按[90步骤5](../90_交付打包.md)用store ZIP。放在服务器`交付文件/`目录不自动变成存档件，不仅因路径就改扩展名。09-23 F08派工混淆两者，验收时改回客户ZIP；7z试产只作中间件。

**并发上限由内存定，不是 CPU** —— LZMA2 每线程约 **500 MB**，线程数 ≈ 可用内存 ÷ 0.5 GB；再往上加会换页，吞吐断崖式掉。
