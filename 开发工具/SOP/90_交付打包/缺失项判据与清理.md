# 90 · 缺失项判据与清理清单

**「解出来能编译」不够**——`MissingScript`、`InternalErrorShader`、断开的菜单引用**都不影响编译**，能编译的包照样在客户那边洋红/静默失效（F §4、K #1）。打包前必须过这组判据。

| 判据 | 怎么读 |
|---|---|
| 零 `MissingScript` | **两种都查**：`m_Script == {fileID: 0}`，以及「GUID 无对应脚本」；**源 prefab 里也要查**（常藏在 prefab） |
| 零 `InternalErrorShader` | 文件层：shader GUID 对照 `.meta` 与内置 ID（它在 `.mat` 里 grep 不到）；运行层：烘焙克隆逐 Renderer 读 shader 名 |
| 引用全能解析 | GUID 反查，断链 == 0（[20 步骤 3](../20_素材清点导入.md)） |
| 本次选定进构建的根恰好1个；全Assets及备份的descriptor另记清单 | 按 [03 头像根口径](../03_装配与冲突通则/头像根口径.md) 核根名/用途/blueprintId；保留有意交付的多根并逐根验，不把备用根数量当失败 |
| `blueprintId` 已核 | 与线上那份一致；多根共用 ID 要报 |
| **说明与工程一致** | 逐条对交付说明 / `来源说明.txt` 里的 `Assets/` 路径与用途，与工程实际相等；**事后补归档的只写归档说明，不编造当时的设计意图**（见 [90 主页「交付说明」](../90_交付打包.md)） |

- **达不到怎么办**：有命中就不交付，回对应阶段处理；判据查不了的写「未核」，不要默认通过。

## 订单专用脚本与中间产物（从90主页移入，规则不变）

### 触发
**当你要打包交付时。**

### 问
**「`Assets/Editor/` 下有没有带订单号的脚本？`Assets/` 下有没有中间日志和诊断截图？」**

```bash
find Assets -maxdepth 3 \( -name "*<订单号>*" -o -path "*Screenshots*" \) -not -name "*.meta"
find Assets/_Work -name "*.txt" -not -name "*.meta"
```

### 答错了怎么办
删掉。**删之前跑一次编译**，确认没有别的东西引用这些类。

### ⚠ 要分清「中间产物」与「交付物」——它们混在同一个目录里

以 `Assets/_Work/` 为例：

| 留 | 删 |
|---|---|
| `*.unity` 工作场景 | `_50装配/` `_55装位/` 下的 `*.txt` 探针日志 |
| `_60菜单/*.anim` `*.asset` `*.controller` —— **这些就是交付物** | `_60菜单/*_probe.txt` `*_verify.txt` |

**菜单资产与动画 clip 是生成结果，不是脚本运行时产物** —— 删脚本不影响它们。

### 证据（2026-09-07 工程C）
一晚做下来，`Assets/Editor/AvatarGen/` 里堆了 **5 个订单专用脚本共 243,639 B**
（最大的一个 106 KB），外加 7 张诊断截图、19 个中间 `.txt`。
**它们会跟着工程打包发给客户。**

**成因**：多路子代理各自往同一个目录加菜单方法，没人负责清。
→ **规矩**：订单专用脚本应当放 `Assets/Editor/<订单号>/`，
不要混进放通用工具的 `Assets/Editor/AvatarGen/`；打包前整个目录删掉即可。
