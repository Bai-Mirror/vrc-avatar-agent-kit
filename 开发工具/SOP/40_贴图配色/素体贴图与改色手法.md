# 素体贴图与改色手法

这页解决的问题：素体贴图（眼睛 / 妆容 / 身体）怎么换、怎么改色、怎么做渐变，以及改服装配色时不改坏不相干部件、不动厂商材质、不把小件刷成一块布的手法。主页步骤 2~4、6 引用的判据与踩过的实例都在这里。

---

## 素体贴图（眼睛 / 妆容 / 身体）—— 与服装配色是两件事

服装配色改 `_Color`；**素体贴图是换整张图**，走的是另一条路。
需求问卷里的「眼睛颜色」「头发颜色」多半要靠素体贴图包落实，
漏了就是一条已下单需求整个没做（輝夜这单差点漏掉一个 203 张贴图的包）。

### 先分清叠加层与整张底图

按 **alpha 不透明占比** 判，一眼就能分：

| 类型 | 不透明占比 | 用法 |
|---|---|---|
| 整张底图 | 与素体原图相当 | 直接换 `_MainTex` |
| 叠加层 | 明显更低 | 挂 `_Main2ndTex`，或**离线合成**进底图 |

**优先离线合成**：眼色层覆盖整个眼睛 UV 岛（岛内大部分不透明），本来就是整眼替换。
走 `_Main2ndTex` 要伺候 `_Main2ndTexBlendMode` / `_Main2ndTexAlphaMode` / `_Color2nd` 一堆开关，
结果依赖 shader 版本；离线 alpha-over 出来是什么就是什么，能直接开图核对，也不多占一层采样。

例外：**厂商说明书指定挂哪个槽的，照做。** forelise 的乳头层写明「メインカラー2nd」，
还写明作画时 `Nipple_On`/`Nipple_Up`/`Nipple_Big` **都是 100**——
只开 `Nipple_On` 的话，画上去的乳晕和几何凸起对不齐。

```bash
python 开发工具/通用工具/eye_composite.py <工程> --level 5 --pair blue yellow --pupil off
```

### 异色瞳：先证明两眼在 UV 上是分开的

眼色层的左右眼通常是**两个完全分离的 UV 岛**（先量出两岛各自的列范围，
确认两岛不重叠、不透明像素数相同）。确认之后按中缝列切开、左右各取一色即可，不需要手描蒙版。
**合成后必须回读校验两半确实不同色**，掩膜要用**眼色层自己的 alpha**——
用合成图的 alpha 会选到一堆肤色，量出来两边都是 #D8AE9D，看着像"没生效"其实是判据错了。

### 按掩膜改色（睫毛 / 眉毛这类没有现成配色的）

素材包给了 12 个色系的睫毛，却**没有银白**（最浅的 ashgray1 线条也才 #AEA2A3）。
这种只能改色，两个掩膜的来源都要可证、不能手描：

- **包里自带的**：部分包附带眉毛遮罩贴图，其某一通道就是两道眉弓（先逐通道看清再用）
- **两个色档相减**：`|black3 − ashgray1| > 12` 的像素就是睫毛（实测落在独立 UV 区，掩膜很干净）

改色用**保亮度着色** `new = target × (lum / mean_lum)`，直接填单色会得到一坨没有笔触的色块。

## 共用材质（不查会改坏不相干部件）

一件服装的一个材质槽常被多个网格共用。实测例子：
`Outfit01` 被 衬衫/短裤/袜子/马甲/靴子 五个网格共用；`Outfit02` 被 包/内衣/帽子/眼镜/猫尾 共用。
**直接换共用材质会改掉不相干的部件。** 覆盖图只能挂到具体网格的材质槽上。

## 渲染时还有一层放大

贴图上看着闷的红，渲染出来可能是艳的 —— 实测 `_MainTexHSVG` 饱和 1.75 + `_EmissionColor` 1.414。
**调色要按贴图值调，用模拟或实际渲染验收，不要看贴图缩略图下结论。**

**别直接把 `.mat` 里的数字当颜色读。** 工程若是 Linear（`m_ActiveColorSpace: 1`），
文件里存的是 linear 浮点、Inspector 显示的是 sRGB，照着文件数字描述颜色会错得离谱。

## 批处理改材质必须幂等

带「向目标色混合 50%」这类相对运算的脚本，重跑一次就二次漂移。
- 用**状态文件**记录已处理项，**不要往 `.mat` 里塞标记注释**（有被 Unity 序列化器改写的风险）
- 先 `dry-run` 出改动明细表，确认分寸后再 apply，**且只跑一次**

## 我说错过的（v1.1 留存）

第二层贴图看着没生效，我推断是 lilToon 的 `LIL_FEATURE_MAIN2ND` 功能开关被关了。
去查 `ProjectSettings/lilToonSetting.json`，**是开的**。真实原因是那张图的原始像素本来就是闷的棕色，
鲜艳来自饱和度与 Emission 参数。
→ **「我猜某个开关关着」在查证之前不能当结论说出口。**

## 非破坏性配色：改 `_Color`，不改厂商材质

lilToon 的 `_Color` 是**乘在 `_MainTex` 上**的。所以整体压暗、偏冷、做撞色点，
都可以只改 `_Color`，不动贴图、不动厂商材质：

1. 复制厂商材质到工程自己的目录（**不要放进任何会被整目录重建的文件夹**）；
2. `copy.SetColor("_Color", 原色 × 色调)`；
3. 把副本指给目标渲染器；
4. **落一份台账**：`渲染器路径|槽号 → 原材质 GUID`，还原全靠它。

三条硬规矩（每条都踩过）：

- **台账只记第一次触碰时的原件。** 规则表后覆盖前，第二条规则读到的已经是第一条的副本，
  照记的话下一轮还原会指向一个已被删掉的资产 → 材质槽 null → 洋红。
- **每条规则都要从原件起算。** 先整套乘 0.26 压黑、再把撞色件乘 0.78，会叠成 0.20，
  撞色点比周围还暗，等于没做。
- **配色改完必须重跑菜单生成。** 配色层（多配色合并成一份实例时）的材质曲线是从场景里
  当前的材质采集的，不重跑就会被旧曲线盖回去。

## 有 PSD/CLIP 源文件时，优先改源文件

厂商常把分层源文件一起发（部分素体会附 PSD 源文件，按部位分文件；
有的还自带默认隐藏的**渐变映射图层**，先打开图层列表看一遍）。

**改源文件要用可控的传统方式**（`psd-tools` + numpy 读图层、算渐变映射、合成导出），
**不要用生成式模型重绘**贴图 —— 生成模型控不住 UV 对齐、控不住配色一致性，
改完的图往往接缝对不上、跨部件颜色不统一。

真要用生成模型（比如补一小块图案），必须：提示词严格限定、多模型交叉查证、
并且**只用在不影响 UV 接缝的小块区域**。

`psd_tools.composite()` 可能对不上厂商导出的成品（实测 RGB 平均差 17.97），合成前先拿成品 PNG 对照。

PSD 图层 alpha 就是覆盖率，在源图层上改色天然干净；找源文件的地方：包内 `PSD/` `CLIP/` `原本/` 目录、素体包 `Textures/` 分色变体、同素体其他妆容商品。

源文件可能是另一种画风（扁平硬边 vs 厂商柔边），换之前先跟用户确认；确实没有源文件才回到压平图，算法是把墨色当覆盖率重新合成，不是色相平移。

> **来源登记与许可**：源文件按「哪个包 / 哪张图 / 版本」集中登记；模板带来的私有 shader、付费贴图逐单查来源，Patreon shader 不进交付（[40 主页](../40_贴图配色.md)「许可与可迁移性」）。

## 配色按件，不按通配

**2026-09-01 作者指认**：「不要死板的将所有配饰都改为单一颜色，比如说这个玩偶熊、
还有腿上的绷带。」根源是配色规则表里写了 `("Outfit_XXX", "*", tint)` 这种通配 ——
便宜，但它把整套衣服当成一块布。

判据：**这件东西换个颜色还认得出是什么吗？认不出就别刷。**

| | 例子 | 为什么 |
|---|---|---|
| **能刷** | 外套、裙、上衣、袜、鞋、手套、腰带、包 | 大面积布料，颜色属于「配色方案」，换了还是同一件衣服 |
| **不能刷** | 玩偶熊、绷带、纱布、血袋、输液管、徽章、贴纸 | 有独立叙事身份的小件，颜色**就是造型元素本身**，刷成单色等于把它从画面里抹掉 |

实现上要注意：**材质是跨渲染器共享的**（本工程 `Shoes` 材质同时用在 绷带/鞋/袜 上）。
逐件列规则是唯一能「只染袜子不染绷带」的办法 —— 染色器为每个被点名的槽单独复制一份材质，
没点名的槽原封不动。

### 撞色点要**主动提**，不能指望「压暗周围自然浮出来」

一度想省事：血袋和输液管本来就是血红的，把周围压到 0.26 撞色自然就有了。
渲染出来是错的 —— 厂商原色偏灰粉，在纯黑底上根本跳不出来，读成一块灰片。
**小面积撞色点必须主动提亮提饱和**，而且只给一两件（面积小、且是叙事核心）。
大面积换色只会毁掉暗色基调。
