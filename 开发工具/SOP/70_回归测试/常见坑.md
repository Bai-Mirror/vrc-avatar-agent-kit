# 70 · 常见坑（实测踩过的）

> ← [70 · 回归测试](../70_回归测试.md)。触发：审查跑到一半工具行为异常、或 T1 回读整批 aborted 时。

- **`execute_code`/菜单超时重发、锁的计时、单次 >20 s 的重活怎么写、构建中原生崩溃** → [编辑器调用与重发](常见坑/编辑器调用与重发.md)（09-21/22 多次实测）。

- **进 Play 不是构建入口**：T1/T4 只在已构建产物、全部 Play 预处理入口已隔离的自开会话中跑；具体前提与未具备项见 [Play 入口与阻断项](常见坑/编辑器调用与重发.md#play-入口与阻断项)。旧记录「进 Play 等 NDMF 构建」只描述旧流程，不能照做；CPU 高位/能轻量调用均不能证明没有重触构建。出现新预处理日志就停止本次测量、记未测，按环境页恢复；不能靠反复进 Play 碰运气。
- 退 Unity 前读 `scene.isDirty`，否则可能卡在保存对话框（[本机(Linux) 环境](../02_环境准备与人工介入/B850_Linux环境.md)）。
- T1 v4 回读断言：被钳位/驱动器合法改写的参数会让整批 aborted，读 `audit.log` 看是哪一参数。
- 产出 JSON 里的参数值按 6 位小数回显（`AuditIO.cs` `0.######`），从产出反推请求要重算精确分数；逐档核「值 < i/n？」，别一句「整体错位」。写样例前先查该工程菜单文档定档位含义，不从扫描取值倒推。
- **接手工程第一次进 Play 看着不对，按这三处顺序排查**（09-18 前旧版实测，仍有效）：① FX 层参数默认值把场景里的设置覆盖了 —— `ExParameters.asset` 与 controller **两处默认值都要改**；② 常驻的高优先级 MergeAnimator 层（`layerPriority: 999`＋无条件常驻）把用到同名键的表情全压平；③ 表情外推超出 0–100（改过的表情要查，判为「安全」的也复检，[烘焙与补偿](../30_捏脸/烘焙与补偿.md)）。
- 认身体按蒙皮权重，不按名字（[判据的形状](../问题定位/观测口径/判据的形状.md)）。
- **Play 读回通过 ≠ 上传后能用**（2026-09-20 工程A）：GestureManager 直接驱动 FX 里的任何参数，参数没进构建后的表达参数表也照样「读回正确」。生成器只往原件根的 `_Menu` 写 MA Parameters，面捕克隆根那份停在旧表，`A2_HairColor`/`A2_HoleHeel`/宠物 6 个全缺——09-19 发色轮盘 Play 验收全过却是坏的。凡加了新参数：Play 里读描述器 `expressionParameters`（构建后的 Clone）确认名字在表里，或跑 T4 看 `menu_params_undeclared`=0。多根工程里生成器写的**值**（不只引用）也要同步到克隆根。
- **默认复位会把「开关残留」洗掉**（2026-09-20 工程B）：状态请求默认 `"reset":"declared"`，每个状态前把用户可控参数复位成声明默认再施加 —— 这能隔离状态，但也擦掉了上一步的残留，**而残留正是要测的东西**。实测：默认口径下 43% 档「关鞋子」读回脚部键全 0、看着没毛病；用户在 GestureManager 里**顺序点菜单**却看到键还开着。用户报「关掉 X 之后 Y 还留着」「切回来就不对」时，改用 `"reset":"none"`，把一条**点击顺序**写成一个 state 步里的多个 states（首状态列全量参数，其后每状态只列变的那一个），按真实点法走一遍、每步读回。两种口径都要跑：`declared` 判「这个状态本身对不对」，`none` 判「从别的状态切过来对不对」。
- **poke 的 `patch_count: 0` 先看 `pairs` 是不是空的**（2026-09-20 工程B）：配对只认**请求级** `poke_covers`（或 `poke_decl` 指到 decl.json），写进 `poke.covers` 会被**静默忽略** → `pairs: []` → `patch_count: 0`、`total_patch_area_cm2: 0`。这时的 0 是**没测**，不是"没穿出"，看着和通过一模一样。可查问句：**「这个 0 背后有几个配对？」** 配对数为 0 就当 `undecidable` 处理，别写进结论。（R9 `candidates` 走的是候选自带的 `garment`+`covers`，不受这条影响，`pair_confidence=high` 可信。）
- **`covers` 要按这件**实际**盖住的部位给**（2026-09-20 工程B）：给低帮运动鞋的 covers 里塞了 `LeftLowerLeg/RightLowerLeg`，于是"小腿露在鞋外面"被当成穿出 —— `leftlowerleg` 段 p50 = +119 mm、outside = 305 个顶点，还凑出一个 0.85 cm² 的斑块。鞋盖不到小腿，这些数全是我自己造的。可查问句：**「covers 里每一根骨头，这件衣服真的盖得住吗？」** 反过来，covers 给少了会漏测（这次脚踝就是一开始没进去）。
- **复制旧请求当模板，必须逐步改写 `out`**（2026-09-20 工程B）：`sequence` 的每个 step 自带 `out`，顶层 `out` 不会覆盖它。我把 `seq_play_0920.json` 复制成新请求、只改了顶层 `out`，跑完发现 6 个步骤把**早上那批 R9 产物原地覆盖**了（新目录里只剩 `audit.log`/`sequence_status.json`，真正的产物写回了旧目录）。靠 `git checkout --` 才还原。可查问句：**「这个请求里每个 step 的 `out`，是不是都指向我这次要写的新目录？」** 取舍：宁可每次现生成请求（脚本里拼 `out`），也别手改旧 JSON。
- **构建超时不等于失败**（09-21 工程B旧流程，09-23 更正入口）：旧 MCP 构建超时后仍在运行，并生成约 445 MB 资产。现行完整构建/预处理一律批处理、全机串行；仍须将阶段、错误、最终判据写文件。超时先查日志/完成文件，不重发、不在交互编辑器补跑。`ProcessAvatar` 单独跑 NDMF 不等于完整 SDK 链。临时克隆在测量/持久化完成后销毁，`legacyClampBlendShapeWeights` 与本次改动的设置按会话前快照还原并读回；引用临时生成目录的克隆不能直接当作可跨会话复用的成品。
- **构建产物是「谁压得住谁」的唯一可信答案**（2026-09-21 工程B）：
  两个 MA MergeAnimator 谁的层在后面，别去猜 `layerPriority`、也别按物体层级推。
  跑一次构建，把 FX 的 `ctrl.layers[i].name` 连同「这层的 clip 写了哪些 path」打出来，
  序号大的在后、后写的赢。工程B的袜子就是这样确认 `Slot_Sok`(93) 确实排在
  厂商 `LEM/LooseSocks`(84) 之后，方案才成立。

- **后台等待用 `pgrep -f "<关键字>"` 判断对方结束，会永远等下去**（09-22 两次）：`-f` 匹配整条命令行，而等待脚本自己的命令行里就含这个关键字，于是总能匹配到自己。
  **写法**：关键字里放一个字符集，如 `pgrep -f "[d]sh_meteor33"`（正则匹配 `dsh_meteor33`，但自身命令行里是 `[d]sh…` 不匹配）；或直接等对方的 PID（`while kill -0 <pid>`）。
  > **可查问句**：我这条等待命令的文本里，是否也包含它要找的那个字符串？
- **截图/测量工具在内存里关渲染器，恢复核对要含 `Renderer.enabled`**（09-22 工程A）：只比层级 md5（路径/activeSelf/位置）会漏掉没恢复的 `enabled=false`，下一个存盘的任务就把 735 条 `m_Enabled=0` 写进场景。**做法**：只读类任务收尾前重新 `EditorSceneManager.OpenScene(路径)` 从磁盘重载；改场景的任务开工第一步也先重载，再动手。
