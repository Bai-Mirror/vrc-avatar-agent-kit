# 65 · 感知机制（形态键与显隐适配的数据化）　🤖

> ← [00 · 总表](00_总表.md)。触发：要判「这件衣服开着时，身体/别的件的键和显隐该是什么」，或写声明、复核情景归类时。

**目的**：把「衣服穿上后身体该怎么缩、脚型跟哪双鞋、谁盖住谁该隐藏」从**看图判断**改成**声明＋读值对账**。看图最贵且最不可靠（作者 09-18 判定）；各工程形态键适配没做好，靠的正是逐图肉眼。

**做法一句话**：每单写一份**声明**（哪件可见时、哪个键该取什么值 / 哪个件该隐藏），校验器拿 [70 回归测试](70_回归测试.md) 跑出的读值（T1 状态、写者图、几何量距）逐条对账，输出 `pass / violation / no_data / undecidable` 等判定；看图只复核数据挑出的候选。

## 情景怎么分

对外统一说 **9 种**依赖（D1–D8，D4 分 a/b）；内部复核、找漏用 **12 类形态键＋4 类只管显隐**。两套口径的对照、各类在 工程A 的生效条数、F/C2/C3 这类对不上单一依赖时怎么归 → [情景分类对照](65_感知机制/情景分类对照.md)。

取舍：宁可多一列复核类，也不为凑 9 种把对不上的情景硬塞进已有依赖；要进 schema 先补依赖种类。

## 与 70 回归测试、审查工具的分工

| 谁 | 管什么 |
|---|---|
| [70 回归测试](70_回归测试.md) | 审查流程：准备单、T1 全量扫描、真序列、同名键跟随、候选定点看图。它产出读值 |
| `通用工具/审查/perception/`（[README](../通用工具/审查/perception/README.md)） | 离线 Python 工具，只读工程、不启动 Unity：写者图 `writers_static.py`、声明草案 `decl_draft.py`、声明校验 `decl_validate.py`（schema `perception-0.2`）、校验器 `verdict.py`＋通用规则 `rules_universal.py`（含同名键失配 U-KF）、阈值 `thresholds.yaml`、姿势库与姿势×状态计划 |
| `通用工具/审查/`（[README](../通用工具/审查/README.md)） | Unity 侧取数（T1/T3/T4、部件盘点）；部署到工程用 `perception/sync_audit.py` |
| 本章 | 情景口径与归类判据；声明对账落地后并入 70 步骤 5 |

**现状与边界**：`verdict.py` 的声明对账尚未并入每单必跑流程（见 70「覆盖记录」）；阈值未标定的项（如 T-33 `shrink_cover`）只作线索、不当「通过」，见 [脚型与收缩键归属](50_服装发型装配/脚型与收缩键归属/两类键与写者.md)。**`skipped`/`no_data`/`undecidable` 都不是 pass**：依赖输入缺席时校验器降级，报告里要照实写「没测」。
