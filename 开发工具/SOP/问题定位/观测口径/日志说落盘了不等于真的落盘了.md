# 日志说落盘了 ≠ 真的落盘了（2026-09-21 工程B 80 贴图分档）

## `JsonUtility` 会**静默**写空：元素类型没有 `[Serializable]` 的 `List<T>`

**触发**：任何用 `JsonUtility.ToJson` 落盘「回滚日志 / 备份 / 清单」的工具。

**自检问句**：

> 我打的那个「已写入 N 条」，读的是**内存里的 Count**，还是**把文件读回来数的**？

踩过（工程B 80 贴图分档，2026-09-21，代价是一次没有还原路径的批量改动）：
`OrigList` 有 `[Serializable]`，里面的 `List<Orig>` 的**元素类型 `Orig` 没有**。
`JsonUtility.ToJson` 对这种情况**不抛异常、不打警告，直接把该字段整个略掉**。
盘上只剩：

```json
{ "savedAt": "2026-09-21 08:49:55", "updatedAt": "2026-09-21 08:49:55" }
```

而日志照样打「原设置已追加 **127** 条…（共 127 条；改动前已落盘）」——
那个 127 是 `data.entries.Count`，内存里的真数。**日志说落盘了，其实没有。**
随后 127 张贴图被改，工具自带的「还原」菜单从此形同虚设。

**改法**（两条一起上，缺一不可）：
1. 元素类型补 `[Serializable]`；
2. **落盘后立刻读回来数一遍，对不上就抛异常中止**，绝不在没有还原路径的前提下继续做破坏性改动：

```csharp
File.WriteAllText(path, JsonUtility.ToJson(data, true));
var verify = JsonUtility.FromJson<OrigList>(File.ReadAllText(path));
int onDisk = verify?.entries?.Count ?? 0;
if (onDisk != data.entries.Count) throw new Exception("原设置没写全，不改。");
```

**取舍**：第 2 条看着冗余，但它是唯一能挡住「序列化静默失败」这一整类的护栏——
`[Serializable]` 漏标只是其中一种，字段是 `property` 而非 `field`、类型是 `Dictionary`、
嵌套超过 7 层，都会得到同样的「无声空文件」。

**兜底**：这类批量改导入设置的步骤，**做完立刻单独提交一个 commit**，
真正的还原路径是 `git revert 那一个 commit`，不要把身家性命押在工具自己的备份上。
