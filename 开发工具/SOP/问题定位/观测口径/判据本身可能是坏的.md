# 判据本身可能是坏的（四类坏法与自检）

> 从 [`问题定位/观测口径.md`](../观测口径.md) 拆出的子页。接手自同名一节及其后各节；「时刻不对」「口径不对」「脚本有 bug」仍留主页。姊妹页：[判据的形状](判据的形状.md)、[渲染与取景](渲染与取景.md)。

## 判据本身可能是坏的

除了「时刻不对」「口径不对」「脚本有 bug」，还有第四类：
**观测通道根本渲染不出目标现象。**

典型：用脚本建相机渲到 `RenderTexture` 出验收图时，`GrabPass` 不工作，
靠抓屏合成透明的材质会被渲成**实心色块**。
拿这种图判断，会把渲染管线的限制当成模型缺陷 —— 而且看起来非常像「复现成功」。

**规矩**：换一种观测方式之前，先确认**这条通道能忠实还原目标特效**。
做不到就承认判据只能到某一层（例如「队列表」），
剩下的交给能还原的通道（Play 模式 Game 视图）。

## 「看不到」未必是头像的问题

先问一句：**你是在 Scene 视图看，还是 Game 视图看？**
Scene 视图工具栏 **Effects 下拉**里有两个开关会把东西藏起来：

- **Always Refresh** 关着时 Scene 视图只在有交互时重绘，粒子不会持续推进；而**选中粒子系统会强制持续重绘** →
  现象就是「粒子只有选中才可见」，编辑期和 Play 期一致。**这不是头像的问题。**
- **Particle Systems** 关着时，Scene 视图里所有粒子干脆不画。

**判据（先做这个，别先查头像）**：进 Play 切到 **Game 视图**看一眼（不受这两个开关影响）；
或用离屏相机渲一张，能渲出来就说明材质 / 着色器 / 尺寸 / 层 / 剔除都没问题。

> 踩过（工程A 目元粒子）：曲线绑定、路径重映射、动画层、材质空槽、粒子尺寸查了一整轮全部正常，
> 运行期探针一直报着 `渲染器=True 可见=True 12 颗粒子在发射` —— 数据是对的，错的是观察手段。
> 「数据说正常、眼睛说不正常」的冲突，先怀疑观察手段，再怀疑被观察物。

## 判据的边界画错了 → 另页

失败整齐地只在一边、绝对阈值被结构性偏移误报（每个统计判据都要带一条能否定自己的自检项）、对照按名字配错、差分判据分不清设计与装错、复现交付态要整层模拟厂商层 → **[判据的形状](判据的形状.md)**；写判定脚本时认身体、判不了、豁免、标签、计数、读产物的口径 → **[判定脚本的口径](判定脚本的口径.md)**。

## 「没用」不等于「无害」

发现某个改动无效时，最省事的处理是「留着算了，反正没用」。这是错的。

**踩过的实例**：把渲染器包围盒改大，后来发现构建期会被覆盖、等于无效。
留着没撤 —— 而包围盒的**中心决定透明排序**（按中心到相机的距离排），
中心一挪，原本时前时后的偶发现象就变成了恒定。

**规矩**：想留一个「无效但无害」的改动时，停下来 ——
**「无害」是需要证据的论断，不是默认值**。说不出为什么无害就撤掉。
撤的时候用精确回退（按属性 revert），不要用撤销栈（会连别人的操作一起撤）。

## 探针不能让「缺失」静默变成一个合法值

上一节说的是「脚本算错了」。这一节是更隐蔽的一种：**脚本没算错，但它把"我不知道"报成了一个具体答案。**

| API | 查不到时返回 | 会被读成 |
|---|---|---|
| `AssetDatabase.LoadAssetAtPath<T>()` | `null` | 「这个字段是空的」 |
| `material.GetTexture(p)` | `null` | 同上 |
| `transform.Find(路径)` | `null` | 「这个物件不存在」（实际是**名字被烘焙改了**） |
| `material.GetFloat(不存在的属性)` | `0` | 「这个开关是关的」 |
| `GameObject.Find(名字)` | `null` | 「场上没有」（实际**没查未激活对象**） |

这类 bug 特别贵，因为**输出看起来信息量很大**：
本单探针报「44 条属性都命中 glass_*」，比"什么都没查出来"更容易让人下结论。

**规矩**：探针里任何一个 `null` / `0`，都要能回答「这是**真的没有**，还是**我没查到**」。
做不到就把这两种情况分成两个结果打印出来。

**判据**：探针写完，拿**一个已知存在**和**一个已知不存在**的输入各跑一次
（同 [20 · 实施坑 第二节「出数前的反查」](../../20_素材清点导入/实施坑.md) 的做法）。前者不该出现「查不到」，后者必须出现。

> 实测两例（工程C）：
> ① 跨工程 diff 材质，Wendy 素体的贴图不在本工程 → `LoadAssetAtPath` 全 null → 报成「字段是空的」；
> ② 烘焙体里 `root.Find("_Acc/…/Ears")` 返回 null（AAO 把路径拍平改名了）
> → 后面那句 `SetActive` **静默不执行**，六张验收图里四张逐字节相同。

## 分辨率不够就把参数推到极端

**「没生效」和「效果反了」在低对比度下长得一模一样。**
淡色叠在肤色上、5% 的形变、微弱的高光差 —— 这些情况下看图只能得到"好像没什么变化"，
而这个观察对两个假说是**等价**的，再看十张图也分不开。

**手法**：把被测参数推到**物理上最夸张**的取值，让两个假说产出**肉眼可分**的不同结果，
拍一张，定案，再调回正常值。

> 实测（工程C · lilToon 叠色层）：
> 玻璃颜色染到了躯干。我先后猜了两次（「遮罩 RGB 是全白」「读的是 alpha 通道」），
> **都是猜的，两次都错**。最后把 `_Color2nd` 设成**纯红、alpha = 1** 渲一张 ——
> 躯干整片猩红、腿一点没染，**极性反了**这个结论一眼就出来了。
> 前面用 α=0.45 的淡蓝紫渲了好几张，一张都没能区分。

**取舍**：这是**诊断手法**，不是验收手法。
极端值下成立的结论，回到正常取值仍需**再验一次**（非线性混合、钳位、后处理都可能只在某个区间生效）。
代价只有一次渲图，而"靠猜"的代价是每猜一次就改一版代码。

**适用范围**：凡是「有一个连续强度旋钮」的机制 —— 遮罩、混合权重、形态键、
Additive 层的幅度、PhysBone 刚度。**先把旋钮拧到底，再谈机制对不对。**

## 判据的方向可能是反的：先问「把被测物**删掉**，指标会不会变好」

前面几节讲的都是「判据量错了」。还有一类更坏的：**判据量对了，但它奖励的是错误答案。**

**触发**：凡是把三维形状/画面压成**一个标量**来择优的判据 ——
像素方差、边缘数量、"整洁度"、包围盒体积、平均亮度。

**自检问句**（一句话，出数前问）：

> **如果我把被测的那个东西整个删掉，这个指标会变好还是变坏？**

**变好 → 判据是坏的**，无论它量得多准。因为最优解会收敛到"什么都没有"。

**为什么容易中招**：这类判据在**大多数样本上排序是对的**，只在极端样本上翻车 ——
而扫描类实验（"五档 × 五套"）恰恰就是去找极值的，**必然会走到那个极端样本上**。

> 实测（工程C）：选脚型键时用「像素方差最低」当判据，
> 选出来的是 `Shrink_Foot=100` —— 它把脚**删掉了 32% 的长度、近一半体积**，
> 于是画面里边缘变少、方差最低，得分第一。而那只鞋是**露脚背的船鞋**，鞋口里直接是空的。

**改法**：**覆盖类 / 贴合类的需求，判据必须成对** ——
一个量"该盖住的盖住了没"，一个量"不该动的还在不在"。单边判据一定会被"把东西删掉"骗满。

| 单边（坏） | 成对（好） |
|---|---|
| 画面方差最低 | 穿模顶点数 == 0 **且** 脚部体积变化 < 5% |
| 露出毫米数最小 | 露出 ≤ 0 **且** 脚部顶点数不变 |

> 第二例（2026-09-08 工程B_Milfy · 高跟凉鞋，差分判据）：
> 正解 `Foot_highheels` 得 **12755**，比「什么都不写」的 9531 **还差**；
> 判据选的 `Foot+Toe`（2468）渲出来是「**有鞋没有脚**」。
> 三次不同的实现都会得到同一个错答案 —— 因为错的是**判据的方向**，不是实现。
> **自查**：候选集合里有没有「把被测物藏起来」的选项？有就说明这个差分判据对它有系统性偏向，
> **必须配逐候选特写**，不能只看排名（差分判据的其余假阴性见 [判据的形状](判据的形状.md) 第四节）。

见 [遮挡不等于占用](../../55_配饰装位/重挂骨架与占用.md)：那是同一个陷阱的另一面 ——
"鱼嘴鞋能把占用判据骗满"。

## 「0」和「都一样」都不等于通过

**候选之间度量完全相同** → 多半是没清零、或者键没写进去，不是「候选等价」；
**一个 0** 可能是「没有」，也可能是「有，但没够到门槛」——尤其当阈值是在**另一具身体**上标的时候。
两条都栽过真实的漏报，触发时刻、自检问句与改法 → **[零和相同都不等于通过](零和相同都不等于通过.md)**
