# 排障记录规程

这一页解决的问题：**记了却照犯。**

作者 2026-09-06：「遇到障碍和排障需求的时候，要记得**多进行记录和分析**，
避免出现**知道但继续犯错**的情况。SOP 文档和记忆都需要**随做随更**。」

## 先承认失效模式

同一天两个实例，两条规矩**都已经白纸黑字写在记忆里**：

- `gemini-check-every-visual-claim`（硬性关口，**第四次**被提醒）→ 仍漂了一整轮
- `prove-cause-before-fixing` → 仍从 300 字符的日志尾巴推病因，写了个白写的补丁

**「有没有记」不是瓶颈，「记成什么形状」才是。**

## 四个失效原因 → 四条写法要求

| 为什么记了没用 | 写法要求 |
|---|---|
| 记忆在**决策那一刻不在场**——排障跑到第三层时不会回头读 | 把关口挂在**动作**上：「**正要写补丁之前**先问…」，不要挂在主题上 |
| 记的是**原则**不是触发器。「病因没证实别动手」拦不住人 | 每条要有 **① 触发时刻 ② 一个可当场回答的问句 ③ 答错时的具体动作** |
| **事后补记会被合理化**——障碍过去了再写，写出来是叙事不是判据 | **随做随记**：还没解决就先记「现象 + 我当时的假设」 |
| **判据本身可能是坏的**，坏判据比没判据更糟（给虚假安心） | 写完问：「**什么情况下它会不通过？**」答不上来就是假判据 |

## 模板

```markdown
### <一句话现象>
**触发**：当你正要 <具体动作> 时
**问**：<一个能当场回答的问句>
**答错了怎么办**：<具体动作，不是「注意一下」>
**证据**：<实测数字/日志原文，不是复述>
```

## 落到哪里

> **2026-09-23 起改两层**（用户拍板）：本页「随做随记」只管**现象层**——当场把「现象＋当时假设＋证据」记进施工记录并打「待蒸馏」标签（`log_step.py --distill`）；**规则层**（写进 SOP）由收尾时的干净上下文代理做，规程见 [收尾蒸馏与状态头](../04_施工记录与版本管理/收尾蒸馏与状态头.md)。理由：事后补记会被合理化（本页），但执行会话当场改 SOP 会写出矛盾与碎片（`_工作流审理_20260923.md` §2.5）。两层各拿一半。

| 内容 | 去处 |
|---|---|
| 通用规律、跨订单复用 | **记忆**（`~/.claude/.../memory/`）+ `MEMORY.md` 索引一行 |
| 阶段性的做法与判据 | 先打「待蒸馏」标签，收尾蒸馏进对应的 **SOP 分页**（判据永远留主页，机制解释下沉子页） |
| 本单的具体经过与数字 | 订单目录下的 `建档.md` / 报告 / 台账 |
| 工具的坑 | **写进工具自己的 docstring** —— 用工具的人一定会看到它 |

## 收尾动作：每个阶段结束时数一遍

「随做随更」在压力下会掉。2026-09-06 那一轮做完自查，**漏记了三条**
（Bash 打不开日文路径、渲染产物渲进 `Assets/`、日志全 PASS 但图是纯色）。

> **每个 SOP 阶段结束时固定问一次：这一阶段撞过几次墙？记了几条？**
> 数不上来就是漏了。

## 实测有效的两条做法

1. **把前几次编造的具体实例写进子代理任务描述的「报告纪律」段** ——
   比抽象地写「不要编造」有效得多。加了之后后续几路都主动在没把握处标了「未验证」。
2. **写判据时先问「它扫到的范围够不够」**。同类错误本轮出现两次：
   `Assembly-CSharp-Editor.dll` 时间戳对**厂商自带 asmdef** 的编译错误恒真；
   只扫 `Assets/` 建 GUID 索引会把 `Packages/` 里的组件 GUID 全报成断链。
