# 问题定位 · 素材与材质

> 这一类的共同特征：**不报错、不崩溃，只是效果默默不对**，客户验收时才发现。
> 所以必须主动扫，不能等报错。

## 一、厂商包只导入了一部分

### 症状与实例

| 实例 | 表现 | 根因 |
|---|---|---|
| 某发型包的渐变色材质 | 客户点名的发色一直用默认设定渲染 | 是 Material Variant，**父材质从没随包发出**（包作者打包失误）。父级缺失时只序列化了少数几条覆盖属性，其余 lilToon 设定**全部回落到 shader 出厂默认**；逐属性对比（如 `_ShadowColor`）能看出它是 shader 默认值而不是素体调过的值 |
| 眼部包 Berrixy | 换了贴图但没有发光/反光/遮罩 | 贴图文件夹被手工拖进 Assets，但关键材质（`.mat`） 一直躺在**没解开的 26 MB `.unitypackage`** 里 |
| 发型包只有 2 个文件 | 发型没材质 | 材质在配套的 `Materials_*.zip` 里，没导 |

### 四查

1. **有没有没解开的包** —— 素材目录里剩下的 `.zip`/`.unitypackage` 都要打开看看
2. **有没有漏公共/材质包** —— 文件名含 `material`/`shader`/`common`/`core`/`dlc` 的
3. **材质行数体检** —— 完整 lilToon 材质 **700+ 行**；只有几十行的多半是父级缺失的变体
4. **断链 GUID 扫描** —— 全工程 GUID 索引 vs 所有 `.mat`/`.prefab`/`.unity` 里的 `guid:` 引用做差集

### 甄别假阳性

- 断链 GUID 大多落在 lilToon **可选槽**（`_OutlineTex` `_BumpMap` `_ReflectionColorTex`
  `_EmissionBlendMask` `_GlitterColorTex`），对应 **`_UseXxx` 开关关着时是惰性的，不是缺陷**
- `0000000000000000f000000000000000` 是 **Unity 内置资源**，不是缺失

### 修法

就地断开变体链 + `Material.CopyPropertiesFromMaterial` 从素体同类材质取完整设定 +
盖回包作者真正有意义的那几条覆盖。
**绝不能换 GUID** —— 渲染器按 GUID 引用。

### 看包内的说明图

作者常在 `導入.jpg` / `README` 里写明哪个材质装到哪个槽。
> 实测：「主贴图放头像自带图、第二层放眼睛颜色」就是从说明图上看来的 —— 一开始装反了，眉毛整个没了。

## 二、文件夹 `.meta` 的 GUID 被重新生成

→ [构建被中止 ④](构建被中止.md)

**根治**：素材一律走 `.unitypackage` 解包，不拖文件夹。
`通用工具/unpack_unitypackage.py` 保留原始 GUID。

## 三、白模的两种典型成因

1. 材质是 URP/Lit 但 `_BaseMap` 为空、`_BaseColor` 是默认 0.8 浅灰
2. FBX 的 `materialImportMode: 0`（不导入材质）且无重映射，走 Unity 默认材质
   —— **槽位名会显示为 `Lit`，是很好的判据**

两种都与构建/压缩无关，**编辑器里就能看出来**。

## 四、找材质别读 YAML 猜，写探针

> 实测连续判错三次：误判成贴图压过头 → 误判成另一个名字相近的材质（实际是带前缀的同名材质）
> → 误判成描边层（本体是另一个 renderer）。

**探针脚本要报出**：每个 Renderer 的实际 `sharedMaterials`、shader 名、
各贴图槽是否为空、`mesh.colors.Length`。一次就定位准。

**prefab 常有多个 Renderer**（本体 + 描边/光晕层），按材质名匹配去替换很容易打到装饰层 ——
**按 renderer 名或逐个打印确认**。

## 五、共用材质槽

一个材质槽常被多个网格共用（实测：一个槽被 衬衫/短裤/袜子/马甲/靴子 五个网格共用）。
**直接换共用材质会改掉不相干的部件。** 覆盖图只能挂到具体网格的材质槽上。

## 六、批处理改材质必须幂等

带「向目标色混合 50%」这类相对运算的脚本，重跑一次就二次漂移。
- 用**状态文件**记录已处理项，**不要往 `.mat` 里塞标记注释**（会被 Unity 序列化器改写）
- 先 `dry-run` 出改动明细表，确认后再 apply，**且只跑一次**

## 七、自己配一份透明材质：**`mat.shader = x` 不重置渲染状态**

### 触发

**要"照着厂商那份做一个同款"** —— 复制素体材质、换成透明 shader、挂上遮罩。
典型场景：厂商只发了给别的素体的样例材质，本单素体那份要自己配。

### 问

**「除了 shader 资产，我还有多少东西没跟着换？」**

`material.shader = lts_trans` **只换 shader 引用**。留在原地不动的至少有四类：

| 留下的 | 后果 |
|---|---|
| `_SrcBlend` / `_DstBlend` / `_BlendOp` | `_DstBlend = 0 (Zero)` → 混合公式退化成纯覆盖，**渲成实心** |
| `_ZWrite` / `_ZTest` / `renderQueue` | 透明件写深度 → 挡住自己身后的部件 |
| **shader keywords**（`m_ShaderKeywords`） | 从 Standard 带过来的 9 个残留关键字，lilToon 不认但也不清 |
| `_TransparentMode` 之类的**模式枚举** | 我按语义猜了 `2`，厂商实际是 `0` |

### 答错了怎么办

**别逐条猜，去 diff 一份确定能用的对照件。** 厂商给别的素体发的那份就是对照组：
逐属性比「我配的」vs「厂商的」，**只看渲染状态类属性**（上表四类），
颜色 / 贴图 / 遮罩这些本来就该不同的跳过。

```csharp
// 只比渲染状态，别比全表 —— 全表会被"本来就该不同"的贴图淹掉
string[] RenderState = { "_TransparentMode","_ZWrite","_ZTest","_Cull",
    "_SrcBlend","_DstBlend","_BlendOp","_SrcBlendAlpha","_DstBlendAlpha",
    "_AlphaToMask","_Cutoff","_AlphaMaskMode","_AlphaMaskScale","_AlphaMaskValue" };
// 再单独比 renderQueue 和 m_ShaderKeywords（不在 ShaderUtil 属性表里）
```

**最稳的写法**：不要「复制素体材质再改 shader」，而是
**复制厂商那份对照材质，再把颜色/贴图槽换成本单素体的** —— 渲染状态天然是对的。

### 判据

渲一张**背景是纯色**的图（本单用了 `RGB(0.20,0.45,0.30)` 绿底）。
透明件后面能看见背景色才算透了；**光看"颜色变浅"不算** —— 不透明的浅色和半透明长得一样。

### 证据（2026-09-08 工程C · Aquaglass）

我配的两份 `Shinano_body_ClearLeg_{half,full}.mat` 渲出来是**实心肤色**。
`_DstBlend` 我的是 `0`、厂商是 `10 (OneMinusSrcAlpha)`；`_TransparentMode` 我猜 `2`、厂商 `0`；
外加 9 个从 Standard 继承来的死关键字。三处全是"换 shader 没跟着换"的东西。

## 八、跨工程比材质：**解析不到的引用 ≠ 空**

### 触发

**拿一份「引用了本工程里没有的资产」的材质去做 diff** ——
厂商发的别的素体的样例材质、旧工程搬来的材质、只解了一半的包。

### 问

**「这个 `null` 是"字段是空的"，还是"guid 解析不到"？」**

`AssetDatabase.LoadAssetAtPath<T>(path)` 和 `material.GetTexture(p)` 在
**引用存在但目标资产不在本工程**时，一样返回 `null`。
两种情况在探针输出里长得一模一样，而结论完全相反。

### 答错了怎么办

探针要么读 **`.mat` 的 YAML guid**（`m_Texture: {fileID: 2800000, guid: xxx, type: 3}` ——
guid 全 0 才是真空），要么把两种情况**分成两个结果报**：

```
_MainTex  = <空>                      ← m_Texture.guid 全 0
_MainTex  = <解析不到 guid a1b2…>      ← 有 guid，本工程里查不到
```

### 判据

写完探针，拿**一个已知在本工程里的材质**和**一个已知不在的材质**各跑一次：
前者不该出现「解析不到」，后者必须出现。同族规矩见
[观测口径 · 校验脚本本身有 bug](观测口径.md)。

### 证据（2026-09-08 工程C）

我拿厂商给别的素体的样例材质逐属性 diff，探针报
「`_MainTex = null`，44 条属性都像 `glass_*`」，我据此断定「它本质是个玻璃材质」。
**全错。** Wendy 素体没装进本工程，那些贴图引用**全部解析不到**；
`.mat` 的 YAML 里 guid 写得清清楚楚。

**代价不对称**：这个错误让探针输出**看起来信息量很大**（44 条命中！），
比"什么都没查出来"更容易让人下结论。**缺失被静默替换成一个合法值，是最贵的一类探针 bug。**

## 补充

- **画面一片洋红 = `Renderer.sharedMaterials` 里有 `null`**，不是 shader 出错。
- 空槽**没有 material 就取不到 shader**，按 shader/材质列的清单**列不出它**；必须单独数槽位：`r.sharedMaterials.Count(m => m == null)`。
- 成因之一：还原逻辑写了 `if (mats[i] == null) continue;`，会让**已经变 null 的槽永远修不回来**。
- 修法：`开发工具/通用工具/FixNullMaterials.cs`，菜单「Fix - 查空材质槽」/「Fix - 修空材质槽（从预制体源头取回）」。
