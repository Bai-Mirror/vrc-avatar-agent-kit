# 问题定位 · 场景损坏与恢复

> 这一页讲**把场景改坏之后怎么办**，以及几个已经真的把场景改坏过的调用。
> 2026-09-03 立，起因是同一个坑在 工程A 上踩了第二次。

---

## ⛔ 绝不要对头像调 `clip.SampleAnimation`

```csharp
clip.SampleAnimation(avatar, t);   // ← 人形头像上等于按下自毁按钮
```

头像是 **Humanoid 绑定**。`SampleAnimation` 不是「只写 clip 里那几条曲线」，
它会把这段动画**过一遍 Animator 做重定向**。clip 里没有肌肉曲线时，
**整具骨架被写成零姿势塌掉**。

实测（Kaguya 素体）：`eye.L` 世界 y 从 **1.0551 → 0.339**，`Hips` 从 0.7306 掉到接近 0。

三个让人上当的地方：

1. **clip 里只有 `m_IsActive` / `m_Enabled` 这种布尔曲线，一样塌。**
   判据不是「这条 clip 是不是人形 clip」，是**头像是不是人形绑定**。
   （我第二次踩就是因为用错了判据，还把错的判据写进了工具头注释。）
2. **它直接写场景，不走 Undo。** `finally` 里只还原 clip 碰过的那几个对象是救不回来的。
3. **塌了之后如果又存了盘，磁盘上的场景也坏了。**

### 想验曲线绑定，正确做法

- **首选：根本不采样。** 只读 clip 数据 + 查对象是否存在，够回答 99% 的问题：
  ```csharp
  foreach (var b in AnimationUtility.GetCurveBindings(clip))
  {
      var curve = AnimationUtility.GetEditorCurve(clip, b);
      var tr = avatar.transform.Find(b.path);        // 路径对不对
      var cmp = tr == null ? null : tr.GetComponent(b.type);  // 组件在不在
      // curve.Evaluate(t) 就是这一档应该写的值
  }
  ```
- 非采样不可就用 `AnimationMode.BeginSampling()` / `SampleAnimationClip()` / `EndSampling()`
  —— 它有自己的还原机制。
- **运行时行为一律进 Play 用探针取数**，不要试图在编辑期"模拟"。

## 常备一个骨架高度自检，改完就跑

比对几个已知世界坐标，一眼判生死。放在工装里，**每次改完场景、存盘之前跑一次**。

```csharp
var eye  = avatar.transform.Find("Armature/Hips/Spine/Chest/Neck/Head/eye.L");
var hips = avatar.transform.Find("Armature/Hips");
bool ok = Mathf.Abs(eye.position.y - EYE_L_Y_已知good值) < 0.02f;
```

每个工程开工时把 `eye.L` / `Hips` 的世界 y 记一笔进工程状态文档。
参考实现：工程A 的 `Assets/Editor/AvatarGen/SceneRecover.cs`。

**顺序纪律：先自检，后存盘。** 不确认状态就存盘，等于把可恢复的错误变成不可恢复的。

## 场景已经坏了怎么救（按代价从小到大）

### ① 还没存盘 → 重载场景

```csharp
EditorSceneManager.OpenScene(path, OpenSceneMode.Single);
```
从脚本调**不会弹保存提示**，直接丢弃内存里的改动。
（`EditorSceneManager.ClearSceneDirtiness` 在 2022.3 不是 public，别找了。）

**重载会清空 Undo 栈** —— 未保存的用户改动重载后撤不回来，动手前先确认该存的都存了。

### ② 已经存盘了 → `Temp/__Backupscenes/0.backup`

Unity **每次进 Play 时**会把场景快照写到这里。二进制格式，但 Unity 能直接打开。

```
cp Temp/__Backupscenes/0.backup Assets/<某处>/_recover.unity
```
然后：
```csharp
EditorSceneManager.OpenScene("Assets/<某处>/_recover.unity", OpenSceneMode.Single);
// → 跑骨架自检确认这份是干净的
EditorSceneManager.SaveScene(activeScene, "Assets/<真实路径>.unity");  // ForceText 会存成文本
EditorSceneManager.OpenScene("Assets/<真实路径>.unity", OpenSceneMode.Single);
```
救完**删掉 `_recover.unity` 和它的 .meta**，别留在交付目录里。

**前提**：那次进 Play 的时间戳要早于损坏时刻。先 `ls -la Temp/__Backupscenes/` 看时间。

### ③ 用户手调的东西没了怎么办

不要指望「撤销 N 步」—— 步数按自己的操作数封顶都可能撤掉别人的活。
更好的是按**已知世界坐标**做判据、对上了就停，或者用 `RevertAllDownToGroup`。


**「撤到判据满足为止」的 Undo 循环会连用户的活一起撤掉**（实测撤 300 步撤掉了未保存的美甲）—— 步数要按自己实际做过的 `RecordObject` 次数封顶，别按判据封顶。

## 其它已知的「悄悄改坏场景」的调用

| 调用 | 后果 | 替代 |
|---|---|---|
| `clip.SampleAnimation(humanoidAvatar, t)` | 骨架塌 | 见上 |
| 循环调 `AvatarProcessor.ProcessAvatar` | 吃十几 GB、卡死编辑器；场景里堆一堆 `(Clone)` | 一次就够；每次前先清克隆体 |
| 进 Play 后被脚本重编译打断 | Play 退出时的场景还原可能不完整（配饰全开、骨架停在动画姿势） | 进 Play 前先把脚本改完编译完；退出后跑骨架自检 |
| 直接改 `Assets/<厂商>/**` 里的 prefab 资产 | 厂商包重导入被覆盖，且污染别的工程 | 改**场景实例**上的组件 |
| 烘焙卡死时删掉正在执行的脚本源码 | **不会停下它**，反而排一次域重载；主线程被占着，重载永远轮不到 → 看起来像彻底卡死 | 只能杀进程（「Hold on」进度条**没有取消按钮**） |
| `DestroyImmediate(clone)` | 只删场景物体，**不删落盘到 `Packages/nadena.dev.ndmf/__Generated/<克隆名>/` 的生成资产** | 每次烘焙后手动清那个目录 |

## 报「X 没生效」之前的自检清单

配合 [观测口径](观测口径.md) 一起用：

1. 这个观测是在**运行时**取的吗？编辑期烘焙不跑 PhysBone / Animator / Parameter Driver。
2. **PlayableGraph 是不是有效的**？GestureManager 要在 Inspector 里点一下头像才接管。
   探针里如果写着 `PlayableGraph 无效`，那次的一切「没生效」都不算数。
3. 粒子系统在编辑期**根本不跑**，除非在 Hierarchy 里选中它。「没看到粒子」在编辑期不是证据。
4. 有没有第二个层在抢写同一条属性？扫全工程的 `.anim`，按路径 + attribute 比对。
5. 观测脚本自己有没有 bug？先拿**一正一反两个已知样本**反查一遍。
