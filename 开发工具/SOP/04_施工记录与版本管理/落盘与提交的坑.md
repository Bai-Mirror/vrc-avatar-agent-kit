# 落盘与提交的坑

这页收「写记录 / 提交时反复踩到的具体事故」，每条都带触发时刻与可查问句。

## 用脚本追加记录时，别用 `%` 做字符串格式化（2026-09-21）

**触发时刻**：在 bash heredoc 里用 python 往 `_施工记录.md` 追加一段 markdown，里面带百分号
（`5.47%`、`p99` 表格、`100%` 之类）。

`"...%s..." % ts` 会把正文里的每个 `%` 都当成格式符 → `TypeError: not enough arguments for format string`。
**后果比报错本身严重**：那一轮我把写入和 `ws_git.py commit` 写在同一条命令里，
**写入失败、提交照跑**，于是提交信息描述了一段盘上根本不存在的记录。

**做法**：用占位符替换 `body.replace("@TS@", ts)`，或 f-string（但 f-string 里的 `{}` 同理要小心）。
**并且写入与提交分两步**：先写、`grep` 确认落盘，再提交。
> **可查问句**：我这条命令是不是「生成内容 + 提交」连在一起？中间有没有一句校验落盘的？


## 新建**目录**时，目录自身的 `.meta` 也要提交（2026-09-21，第三次栽在 .meta 上）

**触发时刻**：往 `Assets/` 下新建一层或多层目录放新资产。

前两次是文件的 `.meta` 漏了（`Foo_heels50.anim.meta`、`CommC_Fix60V.cs.meta`），
这次是**目录的** `.meta`：建了 `Assets/Nymiro/MeteorLens/`，里层的 `MeteorLens.meta` 和
`MeteorLens.shader.meta` 都提交了，**最外层的 `Assets/Nymiro.meta` 漏了**。
Unity 给**每个目录**也生成 `.meta`；少了它，别人拉下来那层目录会被重新发号 guid。

**做法**：提交新资产前跑一次
```bash
git status --porcelain <工程> | grep '\.meta$'
```
把列出来的**全部**带上，特别注意路径里**每一层新建目录**都要有自己的 `.meta`。
> **可查问句**：我这次新建了几层目录？每一层的 `.meta` 都在暂存区里吗？

## 任务书里让 DSH 按「目录」提交，会把并发任务正在写的文件一起卷进去（09-22 H-06）

**触发**：同时派了两个以上 DSH，且它们会写同一个目录（例：`开发工具/通用工具/部件图鉴/` 里一个改查档脚本、另一个改拍照工具）。
**问**：我写的 `ws_git.py commit -- <路径>` 里有没有目录？这个目录此刻有没有别的任务在写？
**做法**：任务书的提交行**只点名文件**，不点目录；确需点目录时写明「提交前 `git status -- <目录>`，不是你改的文件别带」。09-22 DSH 按目录提交把拍照任务 30 秒前写入的 `PartAtlasCapture.cs` 带进了 `32b19400`，它自查后 `reset --soft` 重提为 `db0fe8c2`。

- **09-22 复犯**：改总账的 python heredoc 有缩进错误没执行，后面用 `;` 接的 `ws_git.py commit` 照跑，只提交了流水账，提交信息却写「H-03 验收完成」（edf68893，812a6578 补正）。**编辑命令与提交之间一律用 `&&`**，编辑脚本末尾 `print` 一个确认值，提交前看到它。

## 点名提交也会卷走别人暂存的文件——ws_git 的实现坑（09-22 已修）

**触发**：并行派工时，`ws_git.py commit -m … -- <我的文件>` 的提交里多出别人的文件。
**原因**：旧实现是「`git add -- <点名路径>` → `git commit`（整个暂存区）」；DSH 已 `git add` 的文件就在暂存区里，被一起提交（09-22 49384441 带走 L5-4c 两个文件）。上面那条「按目录提交」只是同一个坑的一种触发。
**修法**（ws_git 09-22）：点名时只取点名路径里已暂存的文件，用 `git commit -- <这些文件>`（--only 语义），别人暂存的留在暂存区；点名了被忽略的 png 只警告不中止；`index.lock` 被占时重试 10 次。
**可查问句**：`git show --stat HEAD` 里有没有不是自己点名的文件？有就在施工记录注明「某提交顺带收了谁的哪几个文件」，不要 reset 别人的工作。

## heredoc 不加引号时，正文里的反引号会被 shell 执行（09-22）
**触发**：`cat >> 记录.md <<EOF`（不带引号，为了插 `$T` 时间）写的正文里有 `` `路径` `` 这类反引号代码。
**后果**：反引号被当命令替换执行，文字被吞掉（09-22 工程A 记录里 `TimerMat`、`Advanced/AvatarHight` 两个名字消失，屏幕上只报「未找到命令」）。
**做法**：一律 `<<'EOF'`（带引号，原样写入），时间戳先写占位再用 `sed` 换成 `date +%H:%M` 的实测值；或者用 python 写文件。写完 `tail` 回读一眼。

## `git mv` 之后点名旧路径，`ws_git.py commit` 会整个中止（09-22 W4）
**触发**：任务里先 `git mv` 搬了文件（W4 把 `_派工/*` 合并进新目录），提交时把旧路径也写进 `ws_git.py commit -- …`。
**现象**：`git add -A -- <路径>` 对盘上已不存在的旧路径报「路径规格未匹配」中止，只提交了先前已暂存的文件（`c0429fdc` 只带 5 个新文件）；DSH 补第二次提交（`1a9c67fe`）才凑齐，期间别的并行提交已落、不能 rebase 合并。
**做法**：mv 场景只点名**新路径**，旧路径的删除已由 `git mv` 暂存、会随 `--only` 一起带上；提交前 `git status --porcelain -- <旧目录> <新目录>` 看 `R`/`D` 行都在暂存区。
> **可查问句**：我点名的路径里，有没有此刻盘上已不存在的？
