# 05 · 多模型评审规程　🔍

> **作者 2026-09-01 明确要求提高多模型评审的优先级。**
> 这不是「有余力就做」的加分项，是**每个细致任务和每次阶段性提交的必经关口**。

## 为什么必须送出去：**主对话会被自己的上下文锚定**（作者 2026-09-06 第四次强调）

> 「过往任务中主对话经常会因为**上下文锚定**而给出乐观评估结果，但是实际上是无法通过我的审查的，
> 而 Gemini 是**另一条订阅池**，并且 Flash 的准确性和速度都比较优秀。」

这改变了三件事：

**① 送审的理由不是「多个模型更准」，是「我被锚定了」。**
在自己上下文里复述过的结论会越复述越确信，而**复述次数与正确率无关**。
所以判据不是「这个结论难不难」，是「**我复述过几遍**」——复述过就必须送出去。

**② 范围不限于视觉结论。** 锚定不挑对象：技术根因、需求判读、方案取舍都在内。

**③ Gemini 是另一条订阅池**，与主对话额度独立 —— 这条关口**用得起**。
「省配额」是针对**三模型/五模型交叉**说的，不是跳过单模型证伪的理由。

### ⚠ 「跑过 agy_panel」≠「过了关口」

原来的漂移判据是「连续三次工具调用没有 agy_panel」。**2026-09-06 实测它给出假阴性**：
那一轮调用了 agy_panel 好几次，但**全是在调试工具本身**（查 gemini 为什么超时），
一次都没把结论送去证伪。判据不触发，照样漂了一整轮。

> **修正后的自查问法**：最近一次 agy 调用，它的**输入是「我的结论」还是「工具是否正常」**？
> 是后者就等于没查过。

### 证伪任务要这样设计，不要问「你觉得怎么样」

问感受只会收到附和。正确形状：

- 把结论**编号列出来**（C1、C2…），要求**逐条**给 `支持 / 矛盾 / 看不出` 三选一
- **「矛盾」必须指出哪张图、哪个部位**；看不清一律 `看不出`，**不许为了给答案而猜**
- 明写「**禁止附和。你的价值在于指出错的那几条。**」
- 明写「只依据实际附上的图，没附的图一个字都不要写」
- 留一个开放槽：「图里还有什么与这套结论不符、但上面没问到的」

## 选对工具：脚本别混、MCP 工具也别混

`agy_panel.py` 与 `agy-task.py` 是两个**脚本**，用途不同；
MCP 的 `agy_review`（**只找毛病**）与 `agy_ask`（解读／比较／权衡）是两个**工具**，问错了不会报错、只会答非所问。
两组的分工、踩坑实例与可查问句 → **[05 · 选对评审工具](05_多模型评审规程/选对工具.md)**

## ⚠ 评审报告必须写明**用了哪个工具、哪个模型**

`agy-task.py` 的默认模型是 **`gemini-3.8-flash-low`**（09-17 起；原 3.5 已下线），
本规程默认编成是 **`gemini-3.7-flash-high`** —— **不是同一个东西。**

2026-09-07 实测出的问题：一路子代理用 `agy-task.py`（报称 `gemini-3.8-flash-low`）做了一次
承重判定，而同一晚别的轮次用的是 `agy_panel.py --fast`（3.7-flash-high）。
**跨轮次比较判定时，如果模型不同，比较本身就是混淆的。**

**规矩**：
1. 派评审任务时**在任务书里指定工具与模型**
2. 要求**在回报里写明实际用了哪个**
3. **跨轮次比较判定之前，先确认两轮同工具同模型** ——
   否则「同一比较给出不同判定」可能只是换了模型

## 三档编成

| 场合 | 编成 | 说明 |
|---|---|---|
| **日常每一步**（改完一件配饰、调完一处配色、渲完一批图） | **`--fast` 单模型快评** | gemini-3.7-flash-high。秒级、便宜，**用得越勤越值** |
| **大节点**（一个 SOP 阶段做完、准备交付） | **3 模型交叉** | claude-opus-4-6-thinking + gemini-3.7-flash-high + DeepSeek 视觉 |
| **结果不明确**（3 模型互相矛盾 / 只有 1 家指认 / 判不出对错） | **扩大到 5 模型** | 再加 gemini-3.1-pro-high + gpt-oss-120b-medium（`--wide`） |

```bash
# 日常快评（主力，应该占绝大多数调用）
python 开发工具/通用工具/agy_panel.py --task t.md --images ... --fast

# 大节点：3 模型交叉
python 开发工具/通用工具/agy_panel.py --task t.md --images ...

# 结果不明确：5 模型
python 开发工具/通用工具/agy_panel.py --task t.md --images ... --wide
```

### 编成取舍：为什么主力是单模型快评

**为什么主力是单模型（作者 2026-09-01 定）**：早期定「≥2 模型一致才采信」，是因为单模型
会以置信度 1.0 虚报不存在的缺陷。但 3.7-flash 的幻觉率已经明显下降，而**评审的价值主要
来自频次，不是来自编成规模** —— 一步一评能抓到的东西，比十步做完再上三模型多得多。
所以：日常每一步都 `--fast`，把交叉编成省给大节点。

`--fast` 会自动把一致性门槛降到 1（只有一家评审时，「≥2 一致」是个永远满足不了的门槛，
会把全部指认塞进「待核」，读起来像「零条采信」，**极易误读成通过**）。
代价是要**自己逐条复核**：实测 3.7-flash 仍会认错对象 ——
把耳饰上的一只金属圈指认成「光环残件未同步位移」，方向对（那里确实有个突兀的黑环），
归属错。**它指的位置比它给的结论可信。**

## 喂图的粒度：这是最容易做错、代价最大的一环

**2026-09-01 的教训**：我把 360px 的全身四分之三缩略图喂给三个模型做配饰验收，
三轮下来没有任何一个模型指出「头饰装位不对」「光环该偏在一侧」「兽耳没埋进头里」。
**不是模型不行 —— 是那个尺寸下这些细节根本不存在于图里。**

规矩：

| 要评什么 | 喂什么 |
|---|---|
| 整体调性、衣橱统一性、配色关系 | 全身四分之三，≥600px |
| **单件配饰装得对不对** | **该配饰的特写**，配饰在画面里占 ≥1/3，且**至少三个视角** |
| 穿模 | 冲突部位的特写，正交视角，两侧各一张 |
| 是否套住/贴合这类可闭式判定的 | **别喂图**，写成脚本断言 |

**判据**：把要评的东西在图上量一下，**它占不到画面 1/4 就别指望模型看得见**。

## 证伪任务怎么设计 → [子页](05_多模型评审规程/证伪任务设计.md)

四条技法，动手写任务前先翻：

| 技法 | 一句话 |
|---|---|
| **拿反向变体对比，不要拿中性基准对比** | 同一条键、更小的值，换个比较对象就从「看不出」变成「明显」 |
| **塞一条已知答案的对照声明** | 让评审有第三种结局：通过 / 指出问题 / **判据本身不可信** |
| **用差异图自动定位要评的区域** | 别自己看图指裁切坐标，那是最容易错的一环 |
| **别拿「量出来的数」冒充判据** | 量化判据必须带对照样本；退化情形要显式拒答，不许强行排名 |

⚠ **「vs 零 判看不出」不能推出「这条键做不出效果」** —— 我据此差点把整套候选方案推倒重来。

### 「≥1/4」这条线的取舍

**阈值怎么来的**：实测，不是拍脑袋。眼睛占画面宽 **15%** 时，
同一个模型对三组候选给出的判定**互相矛盾**，且与像素差冲突；
裁到 **44%** 后判定收敛、与像素差一致。1/4 是这两点之间取的保守线。

**往两边偏各自会怎样**：
- **太小** → 模型不是"看错"，是那些细节**根本不在图里**，它会转而评论背景、姿势、光照
- **太大** → 只喂特写会丢掉「这东西放在整体里合不合适」，而且模型开始挑**放大产生的边缘发虚**
  → **特写必须配一张整体图同发**，并在提示词里写明「边缘发虚是放大所致，不是缺陷」

**达不到 1/4 怎么办**（按顺序试，不要硬送）：
1. 用 `通用工具/img_tools.py diff-crop` 裁到该区域再放大 —— 裁完**自检两两仍不同**，否则等于换个方式喂空图
2. 仍达不到 → **重渲更近的机位**
3. 机位也做不到（被遮挡）→ 说明这个东西**在这组图上根本评不了**，
   把它从本轮评审里摘出去并写明，不要留着假装评过

## 提示词要点

- 明写「**只评价实际附上的图**」。DeepSeek 会对没给它的图凭空编评价（实测发 2 张评了 8 张）。
- 不要在任务里列「有哪些图」的清单，模型会照着清单编。
- **题面抬头按图种写**（三联图 / 单图 / 平铺商品图各一套，不共用）：套错整批判错（09-22 H-05 Vend 批，见 [视觉分工与取证](50_服装发型装配/部件理解与菜单编排/视觉分工与取证.md) 第四节）。
- 明写哪些是**有意为之的验收条件**（T-pose、深灰背景、只穿内衣），否则会收到一堆噪声。
- 要求「陈述哪里错了」，禁止「建议考虑…」。
- **附上作者的展示图当参照**，让模型比对「作者的设计意图 vs 现在的样子」——
  这比让它凭空判断「装得对不对」有效得多。

## 读结果

- **按被指认的对象再归并一次**。token 重叠聚类会把同一个问题的不同措辞拆成多条「待核」；
  三条都指向同一件配饰，那就是三个模型都说它错。
- 单模型指认里确实有幻觉，但**别直接丢**，自己复核。
- **零条一致 ≠ 通过**。先问：是真没问题，还是我喂的图让它们看不见问题。
