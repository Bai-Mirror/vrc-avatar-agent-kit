# 40 · 贴图与配色　🎨 审美卡口（可下放 Gemini 验收）

**目的**：把需求问卷里的色彩描述，落成可复跑的配方与可挑的候选。
**产出**：`配方.py`（参数集中在文件头）、候选对比图、`配色决策.md`
**卡口规则**：Agent 出候选 → `agy_panel` 交叉审 → **≥2 模型无 blocker 即通过**，有分歧才上报用户。

## 为什么审美能下放

作者 2026-09-01 明确：**信任 Gemini 的审美**，配色 gate 可按需求完善度下放。
前提是需求问卷把方向写清楚了（色调 / 撞色 / 各部位颜色 / 风格偏好）。
**捏脸不在此列，那是硬卡口**（[30](30_捏脸.md)）。

## 确定化步骤

### 步骤 1 · 确认环境可用　🤖

**前置**
- [ ] 需求问卷已写清 色调 / 撞色 / 各部位颜色 / 风格偏好（缺一项先回问，不猜）
- [ ] [20](20_素材清点导入.md) 已导入贴图包

**执行**
1. 按 [02](02_环境准备与人工介入.md) 确认环境可用（只有步骤 4 要 Unity；步骤 2~3 离线，等环境时先做）

**后置判据**

| 期望 | 怎么读 |
|---|---|
| 02 的步骤 1~4 全过 | 02 各步后置判据 |

**STOP**
- 02 判到「该找人」→ 按 02 第三节求助，同时先做步骤 2~3

---

### 步骤 2 · 量图集，分清底图与叠加层，查共用材质　🤖

**前置**
- [ ] 问卷里每条颜色需求都对上一个来源：改 `_Color` / 素体贴图包里的某张图 / 按掩膜改色

**执行**
1. 先量图集，再动手：每张替换贴图算 alpha 不透明占比，判断它是「整图重绘」还是「只画自己那块、其余透明」的覆盖图
2. 占比与素体原图相当 → 整张底图，换 `_MainTex`；明显更低 → 叠加层，优先离线合成进底图；厂商说明书指定槽位的照做
3. 遍历渲染器 `sharedMaterials`，列出每个材质被哪些网格共用

**后置判据**

| 期望 | 怎么读 |
|---|---|
| 每张替换贴图都有「占比 + 类型」记录 | 图集清单 |
| 要改的材质共用网格数 = 1，否则覆盖图只挂到具体网格的槽 | 第 3 条的清单 |
| 问卷点名的眼睛 / 头发颜色各有来源 | 需求 ↔ 来源对照表 |

**STOP**
- 某条颜色需求找不到来源 → 报出来，这是一条已下单需求整个没做
- 想直接改共用材质 → 停，会改坏不相干部件

---

### 步骤 3 · 合成脚本化并回读自检　🤖

**前置**
- [ ] 步骤 2 的图集清单已落盘

**执行**
1. 写 `配方.py`，参数集中在文件头常量，改一个数能重跑；离线合成用 `eye_composite.py`（命令见子页）
2. 带相对运算的一律幂等：状态文件记已处理项，先 `dry-run` 出明细，再 apply **只跑一次**
3. 回读自检；`配方.py` 入库（图集是二进制不进 git，配方丢了就没法复现）

**后置判据**

| 期望 | 怎么读 |
|---|---|
| 重跑 `配方.py` 输出哈希不变 | 跑两次比哈希 |
| 异色瞳左右取样色 ≠（掩膜用眼色层自己的 alpha） | 脚本回读输出 |
| 渐变上下段亮度差 > 0 且方向与需求一致 | 脚本回读输出 |
| `git ls-files` 命中 `配方.py` | git |

**STOP**
- 两半同色 / 上下不分高低 → 方向或掩膜错了
- 第二次 apply 漂移 → 脚本不幂等，先修

---

### 步骤 4 · 出候选并同机位渲染　🎨

**前置**
- [ ] 步骤 3 通过；改色走非破坏性路线：复制厂商材质改 `_Color`，台账记原材质 GUID（见子页）

**执行**
1. 每个维度出 3–5 档，规则逐件列（不用 `"*"` 通配），每条从原件起算
2. `AvatarPortrait.cs` 同机位、同布光渲每档
3. 回读校验 + 骨架高度自检

**后置判据**

| 期望 | 怎么读 |
|---|---|
| 档数 ∈ [3, 5]；所有候选图的机位规格 JSON 相同 | `AvatarPortrait.cs` 输出的 JSON 逐字段比 |
| 台账行数 = 被替换的槽数 | 台账文件 |
| 空材质槽 = 0；Head/Foot 骨世界 y 之差不变 | 遍历 `sharedMaterials` 数 null；骨骼世界坐标 |

**STOP**
- 机位不一致 → 重渲，不能拿来比
- 规则表出现 `("Outfit_XXX", "*", tint)` 这种通配 → 拆成按件

---

### 步骤 5 · 交叉审　🤖

**前置**
- [ ] 候选图齐；`配色审查.md` 写好（要点见下）

**执行**
1. `agy_panel.py --images 候选图... --task 配色审查.md`，候选合批一次问完

**后置判据**

| 期望 | 怎么读 |
|---|---|
| 某一档 ≥2 模型无 blocker → 通过 | 输出 json 逐模型结论 |
| 每档都有分数、理由、偏离了需求的哪一条 | 输出 json |

**STOP**
- 没有一档拿到 ≥2 模型无 blocker → 上报用户拍板
- 单模型指认 → 降级为待核，自己复核，不直接丢也不直接信

---

### 步骤 6 · 落定、写决策、重跑菜单生成　🤖

**前置**
- [ ] 步骤 5 有一档通过，或用户已拍板

**执行**
1. 选中档应用到工程（同步骤 4 的非破坏性路线）
2. 写 `配色决策.md`：选了哪档、为什么、被否掉的是什么
3. **重跑菜单生成**（`菜单架构/MenuGen.cs`，[60](60_菜单与动画层.md)）——配色层材质曲线从场景当前材质采集，不重跑会被旧曲线盖回去
4. 回读校验 + 骨架高度自检

**后置判据**

| 期望 | 怎么读 |
|---|---|
| `配色决策.md` 存在且三项都有 | 文件 |
| 目标渲染器的材质在自己的目录下，不是厂商原件 | 遍历渲染器读 `sharedMaterials` 资产路径 |
| 生成的动画层材质曲线指向新材质 | 生成 `.anim` 的 `m_PPtrCurves` |
| 空材质槽 = 0；骨架高度不变 | 同步骤 4 |

**STOP**
- 材质曲线仍指向旧材质 → 菜单生成没重跑成功
- 还原时台账指向已删资产 → 洋红，见子页「三条硬规矩」

### 许可与可迁移性（触发：选配色路线之前／来源是厂商件时）

- **源 PSD/CLIP 集中登记**（F §8）：有分层源文件的优先改源文件（见子页）；登记它来自哪个包、哪张图，别散在各工程里。
- **shader GUID 必须能解析**：字体/付费 shader 的引用解析不到就是洋红，交付前用 GUID 反查（[20](20_素材清点导入.md)）。Patreon shader、模板带来的私有 shader、付费贴图**逐单查来源、不进交付**（K #3/#4、F §6）。
- **lilToon 跨大版本会单向迁移材质，先备份**（F §2）：迁移不可逆，备份当前材质数组/`.mat` 后再升。
- **先例**：H2-Eku `Eye change/` 是**脚本化改色**的可行样本（B §40）。
- **达不到怎么办**：来源查不清的贴图不用于交付，或让用户拍板；不要拿「看起来一样」当来源证据。

## 出候选

给一个维度出 3–5 档并排渲染（同机位、同布光 —— 用 `AvatarPortrait.cs`），而不是自己拍板一个。
实测：睫毛出了 5 档（RGB 216 → 126），选中的是中间那档；直接猜大概率返工。

**候选图必须同机位。** A/B 对比不同机位就没有可比性。

## 交叉审的提示词要点

写进 `--task` 文件里：
- 说清需求原文（色调 / 撞色 / 各部位颜色 / 风格偏好），让模型有判据
- 让它**逐候选打分并说明理由**，而不是笼统说哪个好
- 要求指出「哪一档偏离了需求的哪一条」
- 明说禁止编造、禁止软化

配额有限（Pro 订阅），**候选合批一次问完**，别一档一次。
