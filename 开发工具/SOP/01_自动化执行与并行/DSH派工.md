# DSH 派工规程

> **默认把活交给 DSH。**（作者 2026-09-08 定）Claude 只做五件事（下表），其余一律派。
> 本页是派工前必读。工具在 `开发工具/通用工具/dsh_task.js`（派工）与 `dsh_session.js`（复盘）。
> **北京工作日 09-12、14-18 高峰期同一脚本自动改走 Codex**（09-23）→ [Codex派工](Codex派工.md)。

## 一、分工边界

**Claude 只做这五件，其余全派 DSH：**

| 留给 Claude | 为什么不能派 |
|---|---|
| **流程大纲把控** | 要跨阶段权衡、要改计划本身；DSH 一次只看一个任务 |
| **审美评估** | 没有闭式判据，要的是取舍和落点 |
| **复杂兜底** | DSH STOP 或结论自相矛盾时的排障 |
| **维护 SOP** | 规程要写取舍，不只写规则 |
| **迭代和更新 DSH** | **让 DSH 改自己的工具链有搞坏自己的风险**（作者 2026-09-09 定）。范围：`~/.dsh` 下的配置与 patch、`dsh_task.js` / `dsh_session.js` / `agy_mcp_server.js`、MCP 接线、钩子、技能。必要时可在 Claude 内派 Opus 子代理做，但不给 DSH |

**判断句**：这个任务的产出，能不能被某次工具调用直接印证？能 → 派 DSH。
不能、且需要跨证据综合判断 → 留 Claude。

⚠ **不确定时倾向于派。** 代价不对称：派错了多花几分钟和一点 DeepSeek 额度（便宜），
不派而自己做则烧掉 Claude 额度（贵，且是硬约束）。

### ⚠ 一般工具开发与调试**要派**；**DSH 自己的工具链不派**

**要派**：项目侧的分析脚本 —— 解析 `.anim` / `.prefab` / `.meta`、算判据、出清单。
这类不在留给 Claude 的五件事里。

**不派**：DSH 自己那一套（`~/.dsh` 配置与 patch、`dsh_task.js` / `dsh_session.js` /
`agy_mcp_server.js`、MCP 接线、钩子、技能）。**理由不是它做不好，是它在改自己赖以运行的东西** ——
改坏了连报错都可能传不回来。这类归 Claude（必要时派 Claude 内的 Opus 子代理）。

**改工程也派，Claude 验收并记录**（作者 09-22）：派工带 `--record <工程>`，DSH 自己写施工记录、提交，脚本用 git 核对留痕；
Claude 的验收清单、豁免六类与闸口行为 → **[改工程派工与验收](改工程派工与验收.md)**。
「上下文都在我脑子里、交代成本高」**不是**合法理由。

结构性闸口：`.claude/hooks/delegate-check.js`（PreToolUse，Write/Edit/Bash/Unity/Blender，自上次派工起第 3 次直接改工程 deny）+ `stop-gate.js`。
阶段收尾用 `dsh_session.js stats` 对一次派工比。
**反面教材、四种理由的取舍、自检怎么做** → [派工边界与自检](派工边界与自检.md)

## 三、怎么派

```bash
node 开发工具/通用工具/dsh_task.js \
  --model flash --images "路径1,路径2" \
  --cwd "$PWD" --task-file 任务书.md [--timeout 3600] [--record <工程> | --no-record] [--lock unity|blender] \
  [--json 结果.json] [--brief <速查档>] [--doc <写回文档>]
```
流水账缺省写 `_DSH流水账.md`（`--no-journal` 关）；带 `--lock` 必须表态 `--record`/`--no-record`，否则拒绝派工。
未给timeout时，任务书>2000字或≥3个列表项取3600秒，否则900秒；多步仍显式给3600，重派先接半成品。

**余额（作者09-23追加）**：派前/每批后跑 `python3 开发工具/通用工具/dsh_balance.py`。退出0才新增任务；余额低于储备线（`DSH_RESERVE_CNY`，在 kit.env 或 `--reserve-cny` 配置）即停派，低余额由主理接必要小任务，大批工作等用户决定。查询失败也暂停新增；不合并币种、不用旧环境密钥。

### 省钱的两条硬规矩（作者 2026-09-09 定）

**① 同一批材料上的多个问题，合并进一次任务书。**
跨会话不共享上下文；同一材料拆成4次就要重复摄入4次（脚部任务实测）。

**② 用 `--brief` 指向工程速查档，别让它重扫原始文件。**
速查档用已核结论代替重复扫描。`--brief` 要求优先查档，仅缺项读原始资产并回报「缺X，补读Y」。
**每个工程维护一份 `_工程速查.md`，做完一轮就更新它。**

**产物落点**：DSH 的最终回答走 **stdout**（核验块走 stderr，两者分开，便于脚本取用）；
`--json` 会把「回答 + 核验结论 + 工具调用清单 + 会话目录」一并落成结构化文件。
**要它产出文件就在任务书里写死绝对路径**，别指望从 stdout 里捞 —— 它只能写进 workspace 内。

| 退出码 | 含义 | **下一步做什么** |
|---|---|---|
| `0` | 跑完且核验通过 | 采信，但结论仍按第六节的铁律复核 |
| `1` | 派前快照失败或DSH失败 | 查JSON/problems与stderr；快照非零/超时/截断/落盘失败不得派工，先修原因，不盲重跑 |
| **`2`** | **跑完了但核验没过** | **不要盲目重跑。**先读 `--json` 的 `problems`：<br>· 模型不符 → 去 `~/.dsh/settings.yaml` 删掉 `agent-default-model` 段<br>· 图没读 → 查路径是否存在、是否走了 shim（见坑③）<br>· 收尾非 completed → 读会话日志看它卡在哪，再缩小范围重派 |

### 3.1 ⚠ 长任务书一律走 `--task-file`，别用 `--task` 内联
任务书里的**反引号**会被 bash 当命令替换执行掉——内容从提示词里消失，它照样交一份像样的答案（实测内联 4/6 对，文件 6/6）。
**超过三行、或含反引号/引号/`$`/`!` 的任务书，一律先写成 .md 再 `--task-file`。** 参数没完整送到，比它做错更难发现。

## 三之二、任务书最小结构（六条，缺一条就会出问题）

[子代理提示词](子代理提示词.md) 的八段结构同样适用，但派 DSH 至少要有这六条：

1. **一句话说清这一路负责什么**、在流程哪一步、前置做完没有。
2. **已验证的事实**（写「直接用，别重验」）。⚠ 这一段收益最大、风险也最大 ——
   里面每个数字必须是你亲自验过的；**写错的数字它会照单执行，不会质疑**。
3. **可验证的判据**：怎么算做完了。判据要能被某次工具调用直接印证。
4. **回读要求**：凡是生成/修改了资产，写明「改完回读校验并把读到的值报回来」。
   跨工具的资产（Blender 导出给 Unity 用的 FBX）**在源工具里往返核对不算验收**——2026-09-19 乳贴副本在 Blender 里 0.000 mm，进 Unity 蒙皮偏 71 mm。任务书写明「以 Unity 里 `BakeMesh` 对原件的世界坐标差为准，由 Claude 验」；能在 Unity 里直接做的（给网格加帧）就别绕 Blender。
5. **工具缺失回退**：明写「如果工具列表里没有 X，直接回报 `NO-X-TOOLS`，不要猜」——
   MCP 配的是 `failOnStartupError: false`，连不上时工具会**静默消失**，
   这条能把「工具没挂上」和「它偷懒没调」区分开。
6. **产物路径写绝对路径**，且必须在 workspace 内（沙箱见下）。

> ⚠ **DSH 跑在 `workspace-write` 沙箱里**：`workspaceRoot` 就是 `--cwd` 传的那个目录，
> **它写不到 workspace 之外**（包括 `~/.dsh`）。所以「改 DSH 配置 / 加 MCP / 删 settings 段」
> 这类动作**只能 Claude 侧做，不能派给 DSH**。确需放宽用 `DSH_PERMISSION_MODE` 环境变量，
> 但那等于拆掉护栏，先想清楚。

## 五、交接锁：Unity / Blender 同一时刻只能一方持有

Claude 侧和 DSH 侧连的是**同一个** Unity 编辑器和**同一个** Blender 插件 socket。
只读并发实测没炸（两侧同时 `get_objects_summary` 正常），**但写操作必须独占**。

- `--lock unity` / `--lock blender` 会写 `~/.dsh/handoff.lock`，被别人持有时直接拒绝派工。
- Claude 自己要动 Unity/Blender 前，也先读这个文件。
- 锁只保护「谁在写」，不保证对方状态干净 —— **交接后第一件事是重新观测，别信交接前的读数**。

## 六、复盘：从会话日志取证，不听它的自述

```bash
node 开发工具/通用工具/dsh_session.js list          # 列会话：模型/轮数/工具/收尾
node 开发工具/通用工具/dsh_session.js show latest --reasoning
node 开发工具/通用工具/dsh_session.js grep "read_image"
node 开发工具/通用工具/dsh_session.js stats
```

日志里有 `user/message`、`assistant/message`、**`reasoning`（思考过程）**、
`tool/call`、`tool/result`、`request/header`（真实模型与 effort）。

**验收铁律**：凡是「它没做那个动作就得不出的结论」，一律不采信 ——
判别方法就是看它的 `tool/call` 撑不撑得起这个结论。
它报「我做完了、没问题」时才要重点复核。

**它报「你给的 X 有问题」时，按这个顺序办**（不是照它改，也不是当耳旁风）：
① 先假定它对 —— 它没理由编一个让自己更麻烦的结论；
② **自己去验那一条**（读文件、跑脚本、取数），别只看它的措辞；
③ 验证成立就先改任务书里那个错，再缩小范围重派；不成立就在任务书里写死正确值，
   并把这次误判记进 [问题定位/排障记录规程](../问题定位/排障记录规程.md)。

> ⚠ `stats` 的「疑似失败」是宽口径正则，多报不漏报，逐条复核再下结论。
