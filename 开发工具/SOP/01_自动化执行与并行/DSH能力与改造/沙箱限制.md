# DSH 沙箱限制（bwrap）

DSH 每条命令跑在 `bwrap --unshare-pid --die-with-parent --dev /dev --tmpfs /tmp` 里（`@deepseek-ai/dsh-sandbox-local` 的 `lib/index.js`）。三个后果：

## 1 · DSH 起的后台进程活不过它的会话（09-22 E-通用-01）
**触发**：任务书让 DSH `nohup setsid … &` 启动数小时的批处理（Unity 批量导入等）后立即返回。
**事实**：DSH 每条命令跑在 `bwrap --unshare-pid --die-with-parent` 里，会话一结束整组进程被杀；它挂在自己后台任务里续命也一样（09-22 导入队列 20:13 起跑，DSH 收尾后队列与 Unity 批处理一起消失，`queue.txt` 停在「开始 H10-Sio」）。
**做法**：长时批处理由 DSH **写好脚本、做完前置**，启动这一步由 Claude 在自己会话里 `run_in_background` 跑（声明 `--exempt 兜底`）；验收看 `queue.txt`／日志。可查问句：DSH 回报「已启动」后，`pgrep -fa <脚本名>` 还在吗？

## 2 · DSH 沙箱里没有 GPU（09-22 A-23 第 2 轮）
`bwrap --dev /dev` 给的是最小 /dev，没有 `/dev/nvidia*`/`/dev/dri` ⇒ DSH 起的批处理 Unity 落到**软件 Vulkan**（lilToon 超 32 纹理参数、洋红）；Blender EEVEE 也是软件渲（小物体能出图但慢、打 radeonsi 告警）。**要可信的渲图/GPU 活**：DSH 写好脚本和一行启动命令，由 Claude 在沙箱外 `run_in_background` 跑（同「长时批处理」一条）。可查问句：渲图里有没有大片 `(255,0,255)`？日志里有没有 `failed to load driver`？

## 3 · bash 里的 `/tmp` 是每条命令新挂的空目录（09-18 本机(Linux) 实测、09-23 舌钉链 L5-5c DSH 报）
- 机制：沙箱给每条 bash 命令挂一个新的 `--tmpfs /tmp` ⇒ 它既是**私有的**（看不到宿主 `/tmp`），又在**命令结束后清空**。DSH 的 read/write 工具不走 bash 沙箱，读写的是宿主 `/tmp`——两边看到的不是同一个目录。
- 现象：① DSH 一条 bash 写进 `/tmp/x.json`，下一条命令读不到；② 任务书让它处理宿主 `/tmp/...` 下的文件（例：Claude 的 scratchpad `/tmp/claude-1000/...`），read 工具读得到，bash 里 `diff`/`python` 却找不到——它会自己「重建一份再比」，报告照样写 PASS。
- 可查问句：「任务书里要 DSH 用 bash 处理的文件，是不是都在工作区（`--cwd`）里面？」
- 做法：输入与中间产物都放工作区 `_dsh_tmp_<任务>/`（已被 `.gitignore` 的 `/_dsh_tmp*/` 忽略），用完删；任务书里别叫 DSH 把跨命令要用的文件放 `/tmp`。核验时 Claude 在沙箱外自己重跑一次关键命令，别只看它贴的输出。
- 另：「被覆盖的旧产物」要显式备份——`--backup` 备份的应是 `--out` 旧稿，不是输入源；旧稿已在 git 里时不用另存（L5-5c 的备份与上一提交逐字节相同，已删）。
