# 改工程派工与验收

> ← [DSH 派工](DSH派工.md)。作者 2026-09-22 定：**改工程也派 DSH，Claude 验收并记录**；并要求把它固化进流程，不靠提醒。
> 来由：工程B删素体发型一整轮（改控制器、删物体、拆厂商层、回收参数、改交付说明、写施工记录）全是 Claude 用
> `execute_code` 和 Bash 里的 python/sed 自己做的；旧闸口只盯「写 `开发工具/通用工具/`」，一次都没触发。

## 触发时刻与可查问句

**触发**：下一步要让工程里某个文件或某个 Unity 对象的状态**变样**——改资产/场景/菜单/动画层/材质、删物体、改交付文档、
跑构建/测试菜单、进 Play 取证。
**问句**：这一步的结果能不能被一次工具调用印证（回读值、git diff、报告里的一行）？能 → 写任务书派。

只读的排查、回读、grep、看报告 **不算**，照常自己做（那就是验收）。

## 派工写法

```bash
node 开发工具/通用工具/dsh_task.js --model flash --cwd "$PWD" \
  --record <工程目录> [--lock unity] --task-file <任务书.md> --timeout 3600
```

- **`--record <工程目录>`**：任务书末尾自动附加留痕硬要求——追加该工程 `_施工记录.md`（标题带「（DSH）」，
  四段：做了什么/怎么验/结果/未决）、`ws_git.py commit` 只点名改过的路径、回复末尾报 `已提交: <哈希>`；
  跑完脚本用 git 核对：派工开始后有含施工记录的提交、工程下无遗留未提交改动。缺一项判 FAIL（退出码 2），核验块多一行「留痕」。
- **基线 Diff 验收（作者 09-23 拍板，B3）**：改工程的派工加 `--snapshot-cmd "<只读命令>"`（可重复），`dsh_task.js` 在派工前后各跑一次、存 `_dsh_tmp_snapshots/<时刻>/`、核验块印差异行数；`--record` 却没给快照命令会警告。命令由 Claude 定（例：`python3 开发工具/通用工具/dump_vrc_menu.py <工程>`、`grep -c blendShape <clip>`、`sha256sum <资产>`），DSH 碰不到它。前后**无差异**而 DSH 自报有改动 → FAIL；差异不在预期字段 → 验收第 3 步逐个看。
- **带 `--lock` 却没有 `--record` / `--no-record` 的派工直接被拒**：动编辑器就得先表态改不改工程。纯只读排查写 `--no-record`。`--record` 只认有 `_施工记录.md`（带下划线）的工程目录；长程任务目录（如舌钉链的 `施工记录.md`）会被拒「不像工程目录」，改用 `--no-record`，在任务书里写明由 DSH 自己追加记录并点名提交（09-22 L5-4b 撞过）。
- **流水账缺省开启**，写工作区根 `_DSH流水账.md`（`--no-journal` 关）。⛔ 09-22 前的旧版把 `--journal` 后面的参数当路径，
  `--journal --json x` 写进了一个叫「--json」的文件，09-19 之后三条流水账都落错了地方（已迁回）。

### 任务书里 Claude 要写死的几样（在 [DSH派工 三之二](DSH派工.md) 六条之外）

1. **动手前的状态读数**（场景是否 dirty、关键值现在是多少）——它交接后第一件事是重新观测，给它对照基准。
2. **重活怎么触发**：完整构建、NDMF/VRCFury预处理按 [内存预算](../02_环境准备与人工介入/B850_Linux环境/内存预算与并发.md) 用 `unity_run.sh --project <工程> --batch --method <入口>`，不在交互编辑器里跑。其它必须留在编辑器且可能超过20秒的测量/渲图，才用 `delayCall`、请求标识、单飞锁与完成文件；不能借此绕过构建限制。“第三次必崩”已被首次构建也崩溃的证据推翻。
3. **不许碰的东西**：点名「不要进 Play / 不要退 Unity / 不要动没点名的资产」。
4. **装配、编/改菜单、建部件图鉴类任务**：带上 [DSH 执行要点](../50_服装发型装配/部件理解与菜单编排/DSH执行要点.md) 第一节的固定行（按商品号查档、缺档怎么办、盲标、ATLAS-DIR-NOT-EMPTY）。
5. **失败时停在哪**：判据不过就**别修**、把原文贴回来——修法要 Claude 判断的，别让它自己发挥。

快照必须执行成功且落盘：前快照失败不派工；后快照失败不参与业务差异、验收失败。JSON `snapshots.executions`记录退出码/信号/错误，错误文本不算变化，行序和重复行不得丢。

## Claude 的验收（这是 Claude 的活，每次都做）

| # | 查什么 | 怎么查 |
|---|---|---|
| 1 | 核验块 | 退出码 0、「留痕 ✓ 提交 <哈希>」；退出码 2 先读 `--json` 的 `problems` |
| 2 | 改动范围 | `git show --stat <哈希>`：只有预期路径；多出来的逐个看 |
| 3 | 值真的落盘 | 自己用一次**只读**调用回读关键值（资产字段、`CalcTotalCost()`、场景对象状态）或 grep 文件，不信它的自述 |
| 4 | 报告与引文 | 它贴的读数去报告/日志原文里逐字对 |
| 5 | 施工记录 | DSH 那条的四段齐全、读数与第 3、4 步一致 |
| 6 | 快照 Diff 与产出**内容**对得上它的**元数据** | 产出是数据文件（权重、参数表、清单）时，抽一个字段跟「上一版」和「按新算法重算」各比一次：等于上一版就是没写回。09-23 舌钉链：`舌头权重_参考.json` 的 `algorithm`/`checks` 写盒形核 w6，`weights` 却 494/494 等于 v1（脚本算了 `W2` 没写回），L5-5 验收只看了元数据，下游扫掠与渲图都用了旧权重，到 L6-A 回归才查出 |

验完在 DSH 那条下面追加一行 `> 验收（Claude，HH:MM）：通过 / 不通过——<证据一句>`，再 `ws_git.py commit`。
不通过：写清差在哪，重派（写明「接着半成品做」）或按兜底处理，**不要默默自己补完**。

## 结构性闸口（钩子，不靠自觉）

- **`.claude/hooks/delegate-check.js`**（PreToolUse：Write/Edit/Bash/Unity MCP/Blender 执行代码）：
  判定 Claude 在直接改工程或写项目侧工具时，自上次派 DSH 起第 1、2 次提醒，**第 3 次起 deny**。
  Bash 逐条看写证据（重定向目标、写命令参数、解释器里的写文件 API）落在哪；heredoc 数据正文（任务书、施工记录文字）不算；
  Claude 自己的地盘（SOP、CLAUDE.md、`.claude/`、`_长程任务_*`、流水账、各工程 `_施工记录.md`、`/tmp`）不算。
- **派工清零**：`rules-inject.js` 看到 Bash 跑了 `dsh_task.js` 就把计数清零。
- **`stop-gate.js`**：收尾时本会话有新的直接改动 → 挡一次，要求在施工记录写明为什么没派、剩下同类改动派出去。
  未提交检查跳过：带 `--record` 的工程目录，以及**任何 DSH 派工在跑时、它启动后才改动的文件**（09-22：闸口逼 Claude 对 DSH 在写的素材说明目录做「进行中存档」，卷走 DSH 的在写文件、提交信息张冠李戴）。Claude 别对 DSH 在写的目录做整目录提交。

### 合法例外：先声明，再动手

```bash
node .claude/hooks/delegate-check.js --exempt <类别> "<理由>"
```

只认六类，20 分钟有效，逐条留档 `~/.cache/vrc-rules/exempt.log`：

| 类别 | 例子 |
|---|---|
| 不可逆 | 删存档、覆盖交付包——本来就要先问用户，问完由 Claude 亲手做 |
| 红线 | 密钥、客户素材只读区附近的操作 |
| 用户确认 | 要和用户来回确认、边问边改的小调整 |
| 维护SOP | 改规程本身（通常不会触发，SOP 目录已放行） |
| 迭代DSH | 改 DSH 自己的工具链（`dsh_task.js` 等已放行；这里指它们在工程里的副本） |
| 兜底 | DSH 退出码 1/2 或 STOP 后的排障；**理由里写会话或退出码** |

「上下文都在我脑子里」「就改一行」「派工来回太慢」**不是**合法理由。
Unity 崩溃后重启、清 `Temp/UnityLockfile` 属于环境恢复，按兜底声明。

## 取舍

- **为什么第 3 次才拦**：前两次提醒给「确实只差一行、马上要派」的情形留口子；实测一轮改工程动辄十几次直接改动，三次足以把它拦在开头。
- **为什么豁免 20 分钟而不是按次**：兜底排障往往连续几步，按次声明会把理由写成流水账；时间窗 + 逐条留档 + 收尾写进施工记录，事后可审。
- **误报的代价**：多声明一次豁免；**漏报的代价**：又一轮 Claude 额度烧在执行活上。所以宁可 Bash 判得宽一点。

## DSH 自验只验它自己的假设（09-22 H-07）
**触发**：DSH 回报「全组合 N 组、差异 0、PASS」这类自验。
**事实**：H-07 第 2 轮 DSH 自验 382 组全过，Claude 另起独立核查（多个只读子代理从 YAML/源码取证＋每条 FAIL 再派人尝试推翻）仍查实 5 个缺陷——全在 DSH 自验的**前提之外**：真实构建链改了 WD（它按 WD=False 模拟）、轮盘中间值与远端量化（它只测整档值）、4 槽以上渲染器（生成器循环写死 3 槽、自检只覆盖一件衣服）、MA 实际取哪个字段当菜单名。
**做法**：菜单/动画层、配色这类「组合多、靠推理验」的交付，验收时换视角核：①构建链真实语义（VRCFury/MA/NDMF 会改什么）；②边界与中间值（轮盘中间、k/127 量化）；③覆盖面（每件、每槽，不抽样）；④工具实际读哪个字段（读插件源码）。独立核查结论要能被第二个人复核（给路径:行）。
