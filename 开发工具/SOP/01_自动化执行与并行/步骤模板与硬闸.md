# 面向非顶级模型的步骤模板

这页解决的问题：**弱模型的失败模式不是「不会做」，是在没有判据的地方自己发挥。**
所以步骤要写成不留自由发挥空间的形状。写任何一页 SOP 的步骤表之前先读这页。

弱模型的失败模式不是「不会做」，是**在没有判据的地方自己发挥**。
所以步骤要写成下面这个形状 —— 每一格都不留自由发挥的空间：

```markdown
### 步骤 N · <动词开头的短语>

**前置**（任一不满足就停下报告，不要试图补救）
- [ ] <可查的条件，写清怎么查>

**执行**（照抄，不要改参数）
1. <精确调用：菜单路径 / 脚本名 / 参数值>

**后置判据**（数字或布尔，不是观感）
| 期望 | 怎么读 |
|---|---|
| <X == N> | 跑 <Y>，看 <报告文件> 的 <哪一行> |

**STOP —— 出现以下任一，停下交回人**
- <条件>
```

### 规则必须带**取舍**，否则换个模型就用不了

作者 2026-09-06：「希望你可以将一些**内化的取舍**也说明出来，
以便于保证这些文档在**不同 AI 模型**手上使用时的通用性，**避免内化能力对执行的影响**。」

**问题的形状**：写规范的人（能力强、有上下文）会把大量判断留在脑子里，
只把**结论**写进文档。结论在正常情况下够用，**但边界情况下不够** ——
而边界正是不同模型差异最大的地方。读者到了边界只有两条路：**僵住**，或者**自己发挥**。

#### 每条规则要补的四件事

| 要素 | 不写会怎样 |
|---|---|
| **① 阈值是怎么来的** | 读者不知道能不能动它，于是要么死守、要么随意改 |
| **② 两个方向各自的失败模式** | 只知道「别太大」，不知道太小会怎样，于是一路压到 0 |
| **③ 达不到时怎么办** | 条件不满足就卡死，或者假装满足了继续走 |
| **④ 需要判断时，判断要哪些信息** | 弱模型没有那些信息，只能编 |

#### 反例与正例（都出自本规程）

**反例**：「被评对象占不到画面 1/4 就等于没喂」——
只有阈值。**为什么是 1/4？做不到怎么办？** 读者到了「只能做到 1/5」时无路可走。
补上之后：*1/4 是实测线（15% 时判定互相矛盾、44% 时收敛）；
做不到就用 `img_tools.py diff-crop` 裁到该区域再放大；裁完必须自检两两仍不同，
否则等于换个方式喂空图。*

**正例**：本单给探针代理写 STOP 时，规则与**理由**一起写了 ——
「对照组那一条必须判『支持』；**如果连它都判错，说明这套观测口径不可信**，立刻 STOP」。
后来它遇到了我没预料到的边界（待判项判「看不出」而非「降低」），
**正确判断出字面未触发、但仍如实上报**。
它 navigate 对了，靠的是**理解意图**，不是匹配字面。

> **判据**：把规则里的数字换成另一个数字，读者能不能自己判断这样改对不对？
> 不能，就说明取舍没写出来。

#### 写「留给判断」的地方要指明判断依据

有些取舍确实无法预先定死。那就**明确写出这是判断点**，并列出判断要看的东西：

```markdown
**这里要判断**：<判断什么>
**看这些**：<信息 1> / <信息 2>
**倾向**：默认选 <X>，除非 <条件>
**判错的代价**：选 X 错了会 <后果>；选 Y 错了会 <后果>
```

比「凭经验决定」有用得多 —— **弱模型没有你的经验，但它能读表**。

### ⚠ 写判据本身也要验：**恒真的假判据比没有判据更危险**

判据写下去之前，先确认**它真的能读到那个数**，而且**在错误情况下真的会不通过**。

**实测反例**：某版步骤表写了「默认平台 RGBA32 张数 == 0，读 `.meta` 的 `textureFormat`」。
看着很确定，但 `.meta` 里那个字段绝大多数是 `-1`（Automatic）——
**一张 `RGBA32` 都不会出现**，这条判据**恒为通过**。
它不会报错，只会让人以为查过了。

**规矩**：

- 写完一条判据，问自己：**「什么情况下它会不通过？」** 答不上来就是假判据
- 条件允许时拿**一正一反两个已知样本**反查一遍（见 [20 的实施坑](../20_素材清点导入/实施坑.md)）
- **没验证过的判据要标出来**，例如「⚠ 未在工程中验证」。
  确定化步骤表的读者会照单执行，**不标就等于骗人**
- 判据里引用某个工具的输出行时，先确认**那个工具真的会打印那一行**

### 模板之外的四条硬闸

这四条是实际栽过的，**弱模型比强模型更容易踩**，要写进每个涉及的步骤：

**① 量交付态，不量源场景。**
构建管线会合并渲染器、改写包围盒与遮罩、给动画层重新编号。
凡是「构建期可能被改写」的属性，判据必须在烘焙克隆体上取，
并把「量的是谁」打印出来。

**② 一次只落一个改动。**
两个未验证的改动叠在一起，出问题时无法归因，只能全撤重来。

**③ 「没用」不等于「无害」。**
发现改动无效时不要留着。无害是需要证据的论断，说不出理由就撤，
撤要用按属性精确回退（`PrefabUtility.RevertPropertyOverride`），不要用撤销栈。

**④ 观感结论不自己下。**
「我看了图觉得可以」不构成完成。要么换成闭式判据，要么过第三方评审。
而且要先确认**观测通道本身**能还原目标现象 ——
离屏渲染渲不出抓屏类特效，编辑期不模拟动骨，这类图当判据是坏的。

### 派哪一档模型 → [子代理分派](子代理分派.md)

分派的轴**不是模型强弱**，是「这个任务里有没有**工具看不见的推理**」：

| 任务性质 | 派谁 |
|---|---|
| **枚举型** —— 每条结论都能被某次工具调用直接印证 | **Haiku**（便宜一个数量级；**必须写死禁止哪类判断**） |
| **推理型** —— 要跨文件比对、判等价/兼容/根因 | **Sonnet** |
| **审美型** —— 没有闭式判据，要的是取舍和落点 | **Fable** |
| **排障** —— 别路卡住、判据自相矛盾、三层套一层 | **Opus**（派不派见子页） |

**两条最容易漏的**：
- **子代理不会等后台任务**（3/3 复现）—— 任务描述里要写死「起完轮询等它退出再读结果」，
  且**主代理必须自己复核终态**
- **报告里凡是「我没做那个动作就得不出的结论」，一律不采信** ——
  判别法：看它的工具调用能不能支撑这个结论

怎么推「该禁哪些判断」、Opus 子代理的三个条件、代价不对称的分析 → **[子页](子代理分派.md)**

### 给弱模型的通用收尾动作

每个会改工程的步骤，结束前固定三件事：

1. **回读校验**（不是看日志说"完成"，是把改后的值读回来比对）
2. **骨架高度自检**（改完场景先自检再存盘）
3. **说清哪些验了、哪些没验** —— 没验的要明说，不要含糊过去
