# 50 · 服装与发型装配　🤖

**目的**：把服装/发型/配饰挂上素体，骨架对齐、不穿模、结构可脚本遍历。
**产出**：场景层级 + `装配报告.md`（每件挂了什么组件、蒙皮网格数）

> ## ⚠ 排在 [30 捏脸](30_捏脸.md) 之后，不要并行（本条正本）
>
> **捏脸换 FBX 会作废本阶段与 [40 配色](40_贴图配色.md) 的一部分成果**：换 FBX 会重置场景里渲染器的材质数组（`sharedMaterials`），
> `ArmatureLockMode.BaseToMerge` 还会让外套骨架错位（症状与修法见下文[换 FBX 之后必然错位](#换-fbx-之后必然错位)）。
>
> 所以：**30 完成后再开 50**，否则每套衣服都要拆装重来、配色也要重施加。
> 例外：只改顶点、不动骨架的捏脸不受影响 —— 但那是少数，默认按会作废来排期。
> **30a 进行期间不要动场景** —— 人可能正在手调，意外的场景状态第一解释是「人改的」。
> 排期见 [01 · 自动化执行与并行](01_自动化执行与并行.md)。

## 铁律：先看预制体自带什么，再决定动不动手

厂商预制体的装配方式各不相同 —— 有的自带 **MA MergeArmature**，有的是 **MA BoneProxy 挂 Head**，
有的两者都有，有的什么都没有（要手挂）。

> **实测教训**：给一套自带 BoneProxy 的发型加了 MergeArmature，结果**映射 0 根骨**。

**做法**：装配脚本先 `GetComponentsInChildren<Component>` 探测组件类型名并打印，再据此决定。
参考实现 `工程A/Assets/Editor/AvatarGen/SetupA.cs` 的 `Probe()`。

## 换 FBX 之后必然错位

`ArmatureLockMode.BaseToMerge` 会把外套骨架同步到素体骨架 →
表现是**外套 GameObject 在但完全不渲染**。拆装一次即恢复，然后重新施加配色。
只改顶点不动骨架时不受影响。

## 收缩键：执行流程与两族取舍

MA Shape Changer 挂衣服部件（跟着衣服走）而不是留在厂商换装动画里、「穿模与收缩键」的可执行检查流程、以及**姿态类随便用／删除类要先量鞋的包覆范围**这条取舍与它的判据、证据 →

## 结构约定（AI 可维护性优先）

挂点按**分组**建空物体，组内命名 `<组>_<标签>`：

```
Kaguya-工程A/
├─ _Outfit/   Outfit_MMN_黑  Outfit_MMN_黑粉撞色  Outfit_ANEMONE_黑  …
├─ _Hair/     Hair_GoldenHour  Hair_SweetyHair
├─ _Acc/      Acc_光环_金  Acc_头饰_金  Acc_耳尾1  …
└─ _Gimmick/  Gimmick_SPS
```

这样 [60 菜单](60_菜单与动画层.md) 可以直接按组遍历生成，不用维护第二份名单。
组内互斥（一次一套）由菜单层保证，配饰组可叠加。

## 验收（逐项，不抽查）

| 项 | 判据 |
|---|---|
| 骨架 | 人形主干零缺失；MergeArmature 映射骨数 > 0 |
| 渲染 | 每件单独打开时能看见（不是「物体在但不渲染」） |
| 收缩键 | 上表 6 步走完，且**每套都有截图证据** |
| 配饰位置 | **每个配饰逐个截图确认装位与大小**，不能只看层级里挂对了 |
| 组合 | **每件衣服 × 每个配饰 × 各开关组合全部截图**，无穿模、无装错位才算过 |
| 遗漏 | `MeshFilter` 全量扫一遍，确认骨架内挂件都归了组 |
| 用上了 | 每件都有**包外引用**（GUID 反查），没有的就是没接线 |

## 脚型与收缩键：归「真正包住那部位的那件」

鞋只是套在袜子外面，而且鞋和袜通常是**两个独立的部件开关** ——
把脚型键挂在鞋上，用户一关鞋脚型回中性，而袜子是刚性网格跟不动 → **脚从袜子里顶出来**。
走手写动画层时同理：**绝不能写在整套切换层里**（症状：脱了鞋脚还踮着）。

判据（逐件算盖住那部分骨的顶点占比，⚠ 按骨名比不按 Transform 物件比：MergeArmature 是构建期的，编辑期按物件比一件都命中不了）、
「袜那档默认值不是『无』」、三种场景的实测法与假阴性 →
**[50 · 脚型与收缩键归属](50_服装发型装配/脚型与收缩键归属.md)**
