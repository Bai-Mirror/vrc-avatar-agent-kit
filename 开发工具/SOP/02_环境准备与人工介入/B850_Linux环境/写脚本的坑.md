# 写脚本撞出来的六个坑（bash 为主；2026-09-21 起 DSH 写交付打包等脚本时实撞）

六条都属于「脚本不报错，但行为跟你想的不一样」，日志一片 PASS。
Blender `bpy`/几何脚本的坑 → [Blender 脚本的坑](Blender脚本的坑.md)；离线 csc 编译的坑 → [改编辑器脚本先离线编译](改编辑器脚本先离线编译.md)。

## 1 · `set -e` 下不要写 `[ 条件 ] && 动作`

条件为假时整条返回 1，`set -e` 直接把函数/脚本干掉。
写打包脚本的 preflight 时就是这么 `exit 1` 的。

```bash
[ -d "$D" ] && echo found        # ✗ 目录不存在时整个脚本退出
if [ -d "$D" ]; then echo found; fi   # ✓
```

## 2 · `set -o pipefail` 下，命令替换里的 grep 无命中会拖垮整个脚本

```bash
x="$(grep -o 'MenuItem("[^"]*"' f.cs | sed 's/.*("//')"   # ✗ 没有 MenuItem 就退出
x="$(grep -o '...' f.cs | sed '...' || true)"              # ✓
```
提取「可能没有」的东西（MenuItem、首个标题行、版本号）一律加 `|| true`。

## 3 · 列 zip 成员不要用 `7z l -ba | awk '{print $NF}'`

归档里的路径**含空格**时 `$NF` 只取到最后一个词，顶层条目数会算错。
本工作区就有 `Assets/! ピンク♡プリン !/` 这种目录名。

```bash
7z l -slt a.zip | awk '/^Path = /{sub(/^Path = /,""); print}'   # ✓
```

## 4 · dry-run 里的 `mkdir` 和文件输出也要受 DRY_RUN 保护

否则「只预演」也会在工程里留下空的交付文件夹，下次判断「有没有做过」时会误判。
**判据是「跑完 dry-run 后 `git status` 应当和跑之前一模一样」**。

> **可查问句**：我这个 dry-run，跑完之后工作树有没有任何变化？
> 有变化就说明它不是 dry-run。

## 5 · `free` 的表头是本地化的（09-22 两次撞到）
本机 locale 是中文，`free -g` 第二行表头是「内存：」不是 `Mem:` ⇒ `awk '/^Mem:/'` 取不到值（导入队列 v2 首启因此误判「可用 0 G」卡住）。写法二选一：脚本开头 `export LC_ALL=C`，或 `free -g | awk 'NR==2 {print $NF}'`；最稳是直接读 `/proc/meminfo` 的 `MemAvailable`。


## 6 · 「只读参照」和「导出目标」必须是两个参数（09-23 舌钉链 L5-7 事故）
- **触发时刻**：写任何「读一个素体/参照文件、再导出一个新文件」的脚本（Blender 导 FBX、Unity 导预制件、7z 重打包）。
- **可查问句**：参照路径和输出路径是不是同一个参数、或能被同一个值填满？输出路径有没有落在工程 `Assets/` 或 `/data` 下？
- **做法**：参照用 `--ref`，输出用 `--out`，脚本开头 `realpath(out)==realpath(ref)` 或 out 落在参照所在目录树里就直接抛错；跑完回读参照 sha256 与跑前一致。任务书里把参照路径标「只读」。
- **来由**：L5-7 首版只有一个 `--fbx`，把 工程A 的素体 FBX（编辑器正开着）覆盖成一个小得多的饰品导出；靠逐字节相同的捏脸备份恢复（先核 sha 再覆盖回去）。编辑器当时没刷新才没导入坏文件——没有备份或碰上刷新就是素体损毁。
- 同次另一坑：`json.dump(obj, open(p,"w"))` 不持句柄，遇不可序列化值写一半就断 → `with open(...)`＋`default=float`。（同次还有一条三角面法线的几何坑，见 [Blender 脚本的坑](Blender脚本的坑.md) 第 3 节。）
