# 改 `Assets/Editor/*.cs` 之后，先离线编译再让 Unity 刷新

## 触发时刻

写完或改完一个编辑器脚本，正要调 `AssetDatabase.Refresh` / `refresh_unity` 的那一刻。

## 为什么

Unity 一旦编译不过，会**弹 `Enter Safe Mode?` 模态框**把编辑器整个卡住。
这时 MCP 打不进去（`No Unity Editor instances found` 或超时），只能让**人**去点按钮——
一个少写 `using` 的低级错误就把用户拽进来一次。2026-09-21 实测：`ParamCost90.cs` 少了
`using System.Collections.Generic;`，用户被弹窗挡住，工作中断。

## 怎么做

```bash
开发工具/通用工具/unity_csc.sh <工程根> [程序集名，默认 Assembly-CSharp-Editor]
```

退出码 0 = 通过，否则原样打印 `error CSxxxx`。不进 Unity、不触发域重载，几秒出结果。

## 关键点：**用工程自己的 `.rsp`，不要手搓 `-r` 列表**

Unity 每次编译都把完整正确的引用集写在
`Library/Bee/artifacts/*.dag/<程序集>.rsp` 里。脚本做的事就是复制这份 rsp、
只换掉 `-out:`，然后喂给 Unity 自带的 Roslyn
（`Editor/Data/NetCoreRuntime/dotnet` + `Editor/Data/DotNetSdkRoslyn/csc.dll`，
带 `-nostdlib -noconfig`）。

手搓引用列表**必踩**这两个（2026-09-21 两次都撞到）：

| 症状 | 原因 |
|---|---|
| `CS0433 类型"MenuItem"同时存在于 UnityEditor 和 UnityEditor.CoreModule` | 单体 `Managed/UnityEditor.dll` 和模块化 `UnityEditor.CoreModule.dll` 同时引用 |
| `CS0518 预定义类型"System.Object"未定义` / `CS0433 StringBuilder 同时存在于 mscorlib 和 netstandard` | `mscorlib` / `netstandard` 少给、给重、或版本对不上 |

## 前提与达不到怎么办

- 这份 rsp 要求工程**至少被 Unity 成功编译过一次**。全新工程或 `Library/` 被清过时找不到 rsp，
  脚本会报「找不到 rsp」并退 2 —— 这时只能让 Unity 编一次，别退回去手搓引用。
- rsp 里的源文件清单是**上次编译时**的。新增文件后第一次跑，新文件不在清单里，
  编不到它。脚本已经把 `Assets/` 行原样保留，新增文件要么先让 Unity 编一次刷新 rsp，
  要么把新文件路径手动追加一行到临时 rsp。

## 自己拼 rsp 时要补换行（09-23 舌钉链 L6-A，2026-09-25 从「写脚本的坑」移来）
`cat refs.rsp >> my.rsp` 后若原文件末尾没换行，下一条 `-out:` 会和上一行 `-additionalfile:` 粘成一行被当成文件名，csc 按默认名把 dll/pdb 写进**工作目录（工程根）**。拼接时每段后 `printf '\n'`；跑完 `git status` 看工程根有没有多出 `*.dll`/`*.pdb`。

## 已经弹出 Safe Mode 了怎么办

1. 先离线编译定位错误（Unity 自己的 `Editor.log` 里也有 `error CS`，`grep -nE "error CS[0-9]+"` 最快）；
2. 改好文件、离线编译通过；
3. 再请用户点 **Ignore**（不是 Enter Safe Mode）—— 文件已经修好，Unity 会自己重编译；
   Safe Mode 会把工程其余部分的导入停掉，反而多一步退出。

## 附：每跑一次 VRChat SDK 构建，就会改写一批贴图 `.meta`

2026-09-21 实测两次，同一形状：**285 个厂商贴图 `.meta` 的 `mipMapMode` 从 0 批量翻成 1**
（mip 滤波 Box → Kaiser），另有 253 个被塞进显式的 `platformSettings` 默认块。没人动过这些文件。

⚠ **归因更正**：第一次撞到时我判成「Unity 崩溃后重启全量重导」，**是错的**。
第二次的时间戳（289 个 `.meta` 与 `ProjectSettings/GraphicsSettings.asset` 同为 12:20）
正是用户在 SDK 面板点上传的那几分钟 —— **触发源是 SDK 构建本身**。
崩溃那次也解释得通：崩之前刚跑完两次完整预处理链。

同一次构建还会改这两个 ProjectSettings：
- `GraphicsSettings.asset` 的 `m_FogStripping: 0 → 1`（SDK 的 `EnvConfig.SetFogSettings`，**不会自己还原**）
- `lilToonSetting.json`（lilToon 的 `VRChatModule`，预处理链 order=100，把没用到的 shader 功能剥掉；
  本例关 48 项留 56 项。**先核再慌**：剥掉的项对照头像实际材质的 `_UseXxx` 开关，
  本例剥了 `EMISSION_2ND` 而两个眼睛材质都是 `_UseEmission2nd: 0`，无影响）

- **可查问句**：跑完一次构建 / 上传之后，`git status` 里有没有成片的 `.meta` 改动？
- **判据**：同一次导入把几百个厂商件**同向**翻同一个字段，就是导入器归一化，不是谁的设置。
  对照 `git grep -h "<字段>:" HEAD -- <Assets>` 看原本的分布（本例 HEAD 里 0 有 949 个、1 只有 2 个）。
- **处置**：逐个 `git checkout` 还原，再跑一次**普通** `AssetDatabase.Refresh()`（不带 `ForceUpdate`）复验
  它会不会又被改回去。本例复验 0 个被改回去。
- **取舍**：`.meta` 那批**每次都还原**——贴图分档这类真优化和这类噪声混在同一批文件里，
  交付 diff 会看不清，也没法证明「客户拿到的贴图设置就是我们调的那套」。
  两个 ProjectSettings 则**按现状提交**（还原了下次构建还会被改回去），
  只把 `m_FogStripping` 记进待办，最后一次构建之后改回 0 再打包。
- ⚠ **还原前先看清有没有真东西混在里面**：同一批改动里可能夹着上传成功写回的
  `blueprintId`（本例面捕根拿到 `avtr_…`）。那是真成果，别跟着一起 checkout 掉。
