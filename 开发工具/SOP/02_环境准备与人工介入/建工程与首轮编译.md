# 建 VCC 工程与首轮编译

这页解决的问题：**从零建一个能编译的 VCC 头像工程**，以及新工程首轮编译必然失败时怎么修。
日常在已有工程里干活不需要这一页。

---

## 一、不开 GUI 建工程（本机(Linux) / Linux）

官方 VCC 没有 Linux 版。本机(Linux) 上用 **ALCOM**（GUI，`/usr/bin/alcom`）和 **vrc-get**（CLI，`~/.local/bin/vrc-get`），
两者共用 `~/.local/share/VRChatCreatorCompanion/`（`settings.json`、`Repos/` 社区源，结构同 VCC）。

**最省事**：ALCOM 界面里按 Avatar 模板建（模板内置），建完再回到命令行装包。

**纯命令行**（⚠ 2026-09-18 整理时写下，**本机(Linux) 上尚未完整实测**，第一次用时补判据）：

1. 从一个能编译的现有工程复制骨架：`ProjectSettings/`、`Packages/manifest.json`、`Packages/vpm-manifest.json`
   （不要复制 `Assets/` 与 `Library/`）
2. 按 `../../_工具链基准.md` 的冻结版本装包：`vrc-get install <包 id> <版本> -p <工程>`，
   再 `vrc-get resolve -p <工程>` 补齐 locked 依赖。**不追最新**（见 [20 · 素材清点导入](../20_素材清点导入.md) 的版本冻结）
3. 把工程路径写进 `~/.local/share/VRChatCreatorCompanion/settings.json` 的 `userProjects`，ALCOM 里才看得到

**后置判据**：`vpm-manifest.json` 的 `locked` 条目数 == `Packages/` 下的 VPM 包目录数。

> 旧Windows机（Windows）时代的做法是复制 `%LOCALAPPDATA%\VRChatCreatorCompanion\VRCTemplates\Avatar` 并从 `Repos/*.zip` 离线解包；
> 本机(Linux) 的 `Repos/` 里只有源清单 JSON，没有包 zip 缓存，这条路不通。

### 需要 Unity MCP 时，包地址照抄

```
com.coplaydev.unity-mcp: https://github.com/CoplayDev/unity-mcp.git?path=/MCPForUnity#v10.1.2
```

写进 `Packages/manifest.json`。子路径是 `/MCPForUnity`，**别凭记忆写别的**。
交付前要从 manifest 删掉这一行。

⚠ **往 `Packages/` 里加包之后必须重启 Unity。**
刷新资源与解析包都不够 —— `packages-lock.json` 会更新，
但 `Library/ScriptAssemblies/` 里不会出现该包的 dll。**判据是看 dll 在不在，别看 lock 文件。**

## 二、启动 Unity 的判据

启动命令与图形会话要求见 [本机(Linux) Linux 环境](B850_Linux环境.md)。Linux 下路径整串加引号即可，
没有 Windows `Start-Process` 拆空格的坑。

### 判「Unity 是不是真在干活」

**看 `Library/` 有没有在长，不要看进程是否存活。**
强杀批处理实例后会残留 `Temp/UnityLockfile`，下次打开前确认没有 Unity 进程再删它。

### 判「编译是不是真的成功」

**看 `Library/ScriptAssemblies/Assembly-CSharp-Editor.dll` 在不在、时间戳是否晚于源码。**
不要数 `Editor.log` 里的 `error CS` 行数 ——
全新工程首轮编译失败、后续轮成功是常态，日志里两轮的错误混在一起，
按日志判会连续误判。
⚠ 这条只对**自己的脚本**成立：厂商自带 asmdef 的程序集编译失败时，`Assembly-CSharp-Editor.dll` 照样会是新的，
要另查该程序集自己的 dll 在不在（迁移验收的做法：拿旧机器的 `*.csproj` 名单逐个对 `Library/ScriptAssemblies/*.dll`）。

## 三、全新工程首轮编译的三个坑

新建工程批量导入第三方包后，首轮编译几乎必然失败。三个已知成因：

**① 缺 SRP core。**
有些工具用 `CommandBufferPool`（在 `com.unity.render-pipelines.core` 里），
而 VCC 模板是内置管线、没这个包 → 几十个 CS0103 → 直接触发 Safe Mode。
往 `Packages/manifest.json` 加 `"com.unity.render-pipelines.core": "14.0.11"` 即可，
**不会切换渲染管线**（那要在 Graphics 里指定管线资产）。

**② `VRC_SDK_VRCSDK3` 死锁。**
很多脚本把 `using VRC.SDK3.Avatars.Components;` 包在 `#if VRC_SDK_VRCSDK3` 里，
而这个宏是 SDK 在**首次成功编译后**才写进 Player Settings 的 ——
编译失败 → 宏没定义 → 更多脚本编译失败。
手动往 `ProjectSettings/ProjectSettings.asset` 的 `scriptingDefineSymbols` 加
`Standalone: VRC_SDK_VRCSDK3` 打破死锁。

**③ lilToon 2.x 的编辑器程序集是 `autoReferenced: false`。**
`Assembly-CSharp-Editor` 看不到 `lilToonInspector`，
按老形态写的第三方 `CustomInspector.cs` 会全部 CS0246。
把该包 `*.asmdef` 的 `autoReferenced` 改成 true 可一次解决，
但**这是对 VPM 包的本地改动，重装会还原** —— 要记进工程说明。

## 四、拆 `.unitypackage` 不需要 Unity

就是个 gzip tar，每个资源是 `<guid>/pathname` + `<guid>/asset` + `<guid>/asset.meta`。
两遍流式读（先收 pathname，再落盘）即可还原到 `Assets/`，**原始 GUID 一字不动**。

比在 Unity 里拖文件夹安全（拖文件夹会改掉文件夹 `.meta` 的 GUID），
也能精确排除条目。

注意：若包内**没有文件夹条目**，文件夹 GUID 会由 Unity 新生成 ——
用官方导入对话框结果一样，这是包本身的问题，不是做法的问题。
