## AAO 实际会做的三件事，以及各自怎么验

2026-09-07 工程C 实测（996,612 → 922,682 面，671.0 → 160.7 MB）。

### ① 删除「永远关着」的渲染器

本单删掉素体自带的 `Cloth_*` `Hair_*` `Other_ear/tail` 共 **89,072 面**。

**验它安全的判据**（不是渲图，渲图只看得到默认那一档）：

```bash
grep -rl "<被删物件名>" Assets/_Work/_60菜单/       # 任何 .anim/.controller/.asset
```

**没有任何 clip 引用 = 它永远是关的 = 删得对。**
只有 probe 文本日志提到不算数 —— 那不是动画资产。

⚠ **反过来，如果有 clip 引用却还是被删了，那是真缺陷**，要查 AAO 的 trace 为什么没看到。

### ② UV 重打包 + 单色区域降成 1×1

会在 `Packages/nadena.dev.ndmf/__Generated/**` 生成
`xxx (AAO UV Packed).asset`（2048² → 512×1024 这个量级）和
`AAO Monotone RGBA(...).asset`（1×1，用于采样区域恒定的贴图）。

**这是贴图内存下降的主要来源，不是压缩格式。** 本单 −76% 里绝大部分来自这里。

**贴图清单里会看到材质的贴图指到 `__Generated/`** —— 正常，不是坏了。
**但这些是每次构建重生成的，不要跟着交付包走。**

### ③ 合并蒙皮网格

生成 `$$AAO_AUTO_MERGE_SKINNED_MESH_N`。AAO 只合并**activeness 动画完全相同**的网格，
所以它不会把两个独立开关的物件并到一起。

### ⚠ 前后对比表里，「贴图内存 before」要引对那一次

工具改过 import 设置再复位的话，日志里会有**多个 before 读数**。
**引最后一次（复位后）的**。本单日志依次是 649.3 → 671.0 → 160.7，
子代理回报表引了 649.3（作废的那次），真值是 671.0。
