# 参数审计与语义冲突：两条「判据看不见」的证据

> 从 [`60_菜单与动画层.md`](../60_菜单与动画层.md) 拆出的子页。接手自「硬约束」的运行模式审计实测与步骤 3 的语义冲突警告；硬约束表与步骤判据仍留主页。

**参数审计必须在运行模式下跑** —— 编辑期看不到 MA / VRCFury / MenuInstaller 构建期生成的那部分。
> 实测（Milfy）：编辑期 24 个参数 108 位，**构建后 92 个 177 位**。

**参数预算**：VRCFury 会按需压缩参数，清死参数的真实收益是**同步变快**，不是多出等量空位（机制与实测地板见 [VRCFury 参数压缩](VRCFury参数压缩.md)：只有「菜单绑定的同步参数」能压，压不动的那部分才是真预算）；**Triturbo 面捕参数是位分解的**，比 8 位 float 省。
> ⚠ **判据别写成「有没有穿模」。** 头顶最常见的缺陷是**语义冲突** ——
> 一颗头上同时挂着两副耳朵，几何上不打架、渲图上「未见穿模」，看着就是错的。
> 2026-09-08 工程B_Milfy：66 格组合渲图全判「未见穿模」，
> 实际默认态就是「辣妹猫耳＋素体熊耳」两副，另有两个发型自带的兽耳完全没进任何开关。

## 拆层 / 删物体后回收参数：「这层用了哪些参数」要扫全口子

**触发时刻**：删掉一套物体、拆掉只为它服务的动画层，要判断哪些同步参数跟着变成死参数。
**可查问句**：这个参数除了转移条件，还有没有被当作 Motion Time / Speed / Mirror / Cycle Offset、BlendTree（含嵌套）或 Parameter Driver 读写？

- 状态机里的口子：转移条件；`AnimatorState.timeParameter` / `speedParameter` / `mirrorParameter` / `cycleOffsetParameter`（各有 `*ParameterActive` 开关）；BlendTree 递归的 `blendParameter(Y)`；`VRCAvatarParameterDriver`。场景里还有 PhysBone 与 Contact Receiver 的 `parameter`。
- **最便宜的兜底是全文 grep**：拆之前 `git show HEAD:<controller> | grep <参数名>`（`m_TimeParameter: X` 一眼可见）；拆之后再 grep 全 `Assets` 的 `.controller/.asset/.unity/.prefab/.anim`，只剩参数声明、不可达菜单、未挂的厂商参数表，才算死。
- **最后一道关看构建后的同步清单**（`ParamCost90` 报告逐条列出），死参数会以原价出现在里面。
- 取舍：菜单已不可达的参数 VRCFury 压不了（见上），按原价计费，回收是全额收益；仍挂在菜单上的死参数只省同步时间。

> 实测（2026-09-22 工程B删素体发型）：按「转移条件 + BlendTree」扫只找到 `FHSharp` / `HairNoSide` 两个 Bool（2 位，构建后 254→252 与之吻合）。
> 构建后清单里还剩 `FHLength` / `TWLength` / `TWVolume` 三个 Float——它们是被拆三层的 **Motion Time** 参数，漏了 24 位。
