# 结构惯例：机制是硬的，聚类是软的

> 从 [`60_菜单与动画层.md`](../60_菜单与动画层.md) 拆出的子页。接手自同名一节；步骤 2 的「按结构惯例与硬约束写菜单结构」现在读这一页。

## 结构惯例：机制是硬的，聚类是软的

**硬的（不能改）**
- 切**整套服装**和**发型**一律 `RadialPuppet`（203）+ Float 参数，**不用一堆 Toggle**
- **只有部件开关用 Toggle**，且**按身体部位聚合**（外套 / 上衣 / 裙·裤 / 内衣 / 袜子 / 鞋子 …），
  不是「一套衣服一组」—— 同一时刻只穿一套，另一套的网格本来就被根物体关着
- **同一位置有 ≥2 个饰品，就从 Toggle 改 RadialPuppet**：0=关，1=饰品1，2=饰品2…
  只有一个的才继续用 Toggle
- **戒指要两个控件**：一个管开关，另一个是「戴哪根手指」轮盘 `0–7`
  （左小/左无名/左中/左食/右食/右中/右无名/右小，**不含拇指**），
  位置轮盘**不管开关**；**每根手指的位置与缩放单独微调**，不能一套变换套八根
- 每菜单 **≤8 控件**，超了用「下一页 ▶」分页
- 插件用自带 `MenuInstaller` 的 **`installTargetMenu`** 塞进你的子菜单，**不改插件预制体**
- 厂商菜单**引用不复制**

**软的（按每台模型重划）**
分几个区、每区叫什么、哪些归一组 —— 看内容定，**以简洁明了为准**。
参考：工程G用 `换装/外观/动作/素体`；也可以是 `服装/功能/玩具/头像`。
照搬别的工程的分组反而可能不合适。

**先看厂商菜单够不够用，别默认自建。**

## 实测样本

**一个厂商参数常同时管网格、骨骼姿势、形态键**（[60 一句话铁律](../60_菜单与动画层.md#一句话铁律)的三个实例）：

| 厂商参数 | 它一个参数管着 | 只写网格的后果 |
|---|---|---|
| `Outfit_Cap` | 帽子网格 + 鱼骨发饰 + 猫耳网格与 KemoEar 骨骼姿势 | 耳朵开着，但骨骼还折在头里 |
| `Outfit_Vest` | 马甲网格 + 上衣的两个 spine 收缩形态键 | 关了外套，上衣还是缺一截、露肚子 |
| `Outfit_Bag` | 包 + 名牌 + 骨架里的鱼玩具 | 鱼玩具留在原地飘着 |

**介入强度也是软的**（实地扒三个旧工程得出）：

| 工程 | 做法 |
|---|---|
| 工程G | 自建根菜单，厂商菜单引用进来 |
| 工程F | **最小介入** —— 只往厂商菜单加一个 `Clothes` 轮盘 |
| 工程E | 直接用厂商 IKUSIA 菜单 |
