# 60 · 属性归属与写法

> ← [60 · 菜单与动画层](../60_菜单与动画层.md)　姊妹页：[层序与压制](层序与压制.md)

这页解决的问题：**同一个属性（或厂商参数）被两个地方管**时会怎么坏、
一个层该用哪种写法去写它、以及「根物体」「容器」「派生形态」这三类最容易漏掉归属的东西。

[层序与压制](层序与压制.md) 讲的是「层怎么排、冲突压哪一侧」；
这页讲的是**在选定的那一层里，到底该写什么、不该写什么**。

## 铁律：一条属性只能有一个层管

把一件东西从 A 层挪到 B 层时，**必须同时从 A 层的表里删掉**。
只加不删的后果分两种，而且症状完全不同：

| 被两处写的是 | 胜负规则 | 症状 |
|---|---|---|
| **动画曲线**（`m_IsActive` / `blendShape.*`） | **按层序**，后面的层盖前面的 | 稳定复现：那个开关「怎么点都没反应」 |
| **参数**（`VRCAvatarParameterDriver` Set） | **按事件顺序**，谁后进状态谁算数 | 时有时无：「切一圈回来，刚关掉的东西自己回来了」 |

第二种是本页最值钱的一条，单独展开。

### Driver 是「进状态写一次」，不是每帧写

#### 触发
**写「进某档时顺手把某个厂商参数设成常量」之前。**

#### 问
**「这个参数还有没有别的层在写？」**

有就不能写常量。Driver 只在**进入状态那一帧**写一次，所以两个层各自 Set 同一个参数时，
**层序完全不起作用** —— 这跟动画曲线的规则正好相反，极容易记混。

#### 答错了怎么办
想表达「这一档下该参数等于另一个开关的值」，用 **`ChangeType.Copy` + `convertRange`**，别用 Set：

```csharp
new VRC_AvatarParameterDriver.Parameter {
    type = VRC_AvatarParameterDriver.ChangeType.Copy,
    name = "Crown_OFF", source = "RJ_S_Hed",
    convertRange = true, sourceMin=0, sourceMax=1, destMin=1, destMax=0,  // 取反
}
```
Copy 每次进状态都重算，所以无论从哪一档切回来，值都等于开关的当前值。

#### 判据
**编辑期证明不了，组合渲图也照不出来**（渲图模拟的是 clip，不是事件顺序）。
唯一可查的是：**读控制器，数一遍「有几个层写这个参数」**。>1 就要改成 Copy 或收归一处。

#### 证据（2026-09-08 工程B_Milfy）
整套层 0 档无条件写 `Crown_OFF/Cardigan_OFF/Bottoms_OFF/Slippers_OFF = false`，
而这四个参数同时被四个部位开关层驱动 →
「头饰关着 → 随便切一套衣服 → 再切回 0 档 → 皇冠自己回来了」。

## 四种写法，按「这一档是不是它的所有者」选

WD=OFF 下「这一层没写」＝**从前面的层原样透传**，所以「不写」也是一种表达。

| 写法 | 自己档/ON | 其余档/OFF | 什么时候用 |
|---|---|---|---|
| **所有者** | 写 true | 写 false | 默认。这一层就是这条属性的主 |
| **压制** | —（Empty 无曲线） | 写 false | 「某开关开着期间按住别人的东西」，见 [层序与压制](层序与压制.md) |
| **只压不放 SupMine** | **不写** | 写 false | 「它归这一档，但**显隐另有主**」 |
| **只放不压 SupBlock** | 写 false | **不写** | 「它不归这一档，但归**其余所有档**」 |

### 后两种什么时候非用不可

**SupMine** —— 这一档想让它出现，但它出不出现还取决于**别的开关**。
硬写 true 会做出「没有本体的浮空零件」。

> 证据（2026-09-08 工程B_Milfy）：垂耳兔的垂耳长在夹克兜帽上，
> 由厂商 `LEM/Jacket` 与「上衣」开关管。头部轮盘在「服装头部饰品」档硬写
> `Jacket_Ear = true`，就会出现**关掉上衣却还挂着一对浮空垂耳**。
> 改成这一档不写、其余档写 false：轮盘只能压，不能放。

**SupBlock** —— 厂商用一个参数在两件之间**二选一**，你只想在某一档让位。

> 证据：LEM 的 `Skirt` ↔ `Skirt_Jacket` 由厂商 `LEM/Jacket` 二选一。
> 我方「裙·裤」ON 态把两条都写 true → **同时穿两条裙**。
> 改成 ON 不写（让厂商挑）、OFF 才写 false（两条一起收）。

> → [用 SupMine / SupBlock 的代价与所有权审计](属性归属与写法/压制写法的代价与审计.md) —— 把「谁是主」分散到两处之后必须做所有权审计，含 Relative 路径前缀与 WD=ON 两个坑。

## 最容易漏的四类归属

### 一 · 根物体（容器）也要有主

#### 触发
**写「某个部位/档位管哪些物体」的表时，对每一条路径。**

#### 问
**「它的父物体归谁管？」** 答不出来就是没有主。

#### 答错了怎么办
表里把根物体一并写上，子网格也照写不误 —— 两级都确定才不依赖场景的历史状态。

#### 判据
**闭式判据集体查不出来这一类**：它们只看被写的那条路径本身，不看祖先。
子物体写成 true、祖先关着，`activeInHierarchy` 仍是 false。
唯一能自动拦住的是生成器里的**祖先自检**：

> 凡是默认态要写 true 的路径，逐级往上查祖先；
> 有祖先关着**且不归任何层管**就抛错，不生成。

#### 证据（2026-09-08 工程B_Milfy）
辣妹耳尾接进头部轮盘第 1 档，生成回读全过、2496 格组合遍历全过、所有权审计也全过 ——
**渲图里就是不出来**。`_Acc/WhitePink`（两个网格的父物体）当时是关着的，没有任何一层写它。

### 二 · 容器门控：一套衣服里切两个变体实例

反过来说，**容器是个好东西**。要在一套衣服里切两份实例（如兜帽上/下）时：

```
_Outfit/<容器>              ← 整套轮盘管这一层
  ├ <实例A>                 ← 部位层 / 饰品轮盘管容器里的子物体
  └ <实例B>
```

容器关着时子物体是什么状态都无所谓，所以后面的层可以**自由写子物体**，
不会在别的整套档位下把这套衣服放出来。
没有容器的话，「非某档就显示实例 B」这条规则会在所有整套档位下生效。

### 三 · 派生形态跟着**触发它的部件**走，不跟着整套走

脚型键、防穿模收缩键这类「因为穿了某件才需要」的形态，
**归那件所在的部位开关**，不归整套切换层。

写在整套层里等于「一套衣服一个固定脚型」：脱了鞋脚还踮着、凉鞋里塞着一只平脚。

#### 做法
形态是 `(整套档, 部件开关…)` 的函数，一个层的条件里要同时用到多个参数。
不要铺 `档数 × 2^n` 个状态 —— 做成**少数几个结果态 ＋ 多条带多重条件的 AnyState 转移**：
每套衣服往里连 1~3 条转移即可。

⚠ 一条转移里的多个条件是**与**，写不出**或**。要「鞋开 **或** 袜开」就得写两条转移。

#### 优先级
`鞋开 → 鞋的形态　｜　鞋关+袜开 → 袜的形态　｜　都关 → 全部归 0`

⚠ **「袜的形态」的默认值不是「无」**。鞋套在袜外面，袜子多半是**照着踮脚姿态建模的刚性网格**；
鞋一关就把脚型归中性，脚会从袜子里顶出来。
详见 [50 · 脚型键挂在「袜子」上，不是「鞋」上](../50_服装发型装配.md)。
两张表都要**实测**，别照抄。

### 四 · 显隐也可以是派生的：它归「布尔组合」，就不能再留在原部位表里

上面第三条讲的是**形态键**跟着部件走。同一个道理适用于**显隐**：
有些件的「该不该出现」不是一个部位说了算，而是几个部位的布尔组合。

> 证据（2026-09-09 工程C 工程C）：Violet Nocturne 的 `Straps`（材质名就叫 `Anklet`，
> 是缠在脚踝的绑带）被归在「上衣」。于是脱了鞋袜、光着脚，脚踝上还挂着两圈丝带。
> 需求是：鞋**或**袜任一开着就显示，两个都关才隐藏。

#### 做法
新开**一层**做它的所有者，两态 On/Off 都写 `m_IsActive`，
条件按上面那条写：`鞋 If → On`、`袜 If → On`、`鞋 IfNot 且 袜 IfNot → Off`。

⚠ **必须同时把它从原部位的对象表里删掉**，只加新层不删旧的 = 两个写者，
后面的层盖前面的，症状是「有时对有时不对」，逐条查规则查不出来。
删了之后记得把它补进生成器的 `Excluded` 白名单，否则覆盖率自检会判它漏网。

#### 代价往哪边不对称
移出去之后，**原来那个部位开关就管不着它了** —— 上衣关掉，脚踝绑带照样在。
这是有意的（它本来就是腿部件），但**要写进交付备忘**，
否则客户按「关上衣应该全没了」的直觉来验，会当成新 bug。

反过来若舍不得这条、想两边都要（既跟鞋袜走、又受上衣压），
那就退回**乙类压制层**：件仍归上衣所有，另加一层在「鞋袜双关」时压 0。
代价是它永远关不掉上衣那一层的 0 —— 上衣关 + 鞋开时绑带**不会**出现。
**两种都对，选哪个取决于这件在语义上属于谁**，别靠感觉，问一句
「把上衣脱光只穿鞋，这东西该在吗」。

#### 判据
不要靠渲图看（一两圈细绑带在图里区分不了「对」和「差一点」）。
判据是**权威产物**：把四格真值表按「层序叠加 clip 曲线」算出来，
再全工程 `grep` 那条路径的 `m_IsActive`，**写者必须只有一个**。
