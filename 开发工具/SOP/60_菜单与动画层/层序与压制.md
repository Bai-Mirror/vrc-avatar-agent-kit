# 60 · 层序与压制

> ← [60 · 菜单与动画层](../60_菜单与动画层.md)

这页解决的问题：走路线 B（手写 AnimatorController 层）时层怎么排、配饰一开就穿模怎么压、
轮盘扩档后压制范围为什么错、「衣服关掉就恢复成 X」和「整套自带内衣」这类需求该落在哪一层。

> ⚠ **前提检查（2026-09-22 H-07 查实）：本页的「空 clip＝从前层透传」只在构建后 WD 真的是 OFF 时成立。**
> 可查问句：头像根上有没有 VRCFury `FixWriteDefaults`（`grep -n "class: FixWriteDefaults" <场景>`，`mode: 0`＝Auto）？
> Auto 在 FX 普通状态 >10 时按 on/off 多数票定，**厂商 FX、PCS、Realkiss 等大多是 WD on，票数上几乎必然判 ON**，然后把全部 FX 状态（包括我们手写的 WD=OFF 层）改成 ON、不补空状态（`FixWriteDefaultsService.cs:159-223`；工程A 09-18 日志「FX:595 on|99 off → ON」）。
> WD on 下，按 Unity 语义一层里被本层任一状态写过、当前状态没写的属性**可能**写回默认值并盖掉前层；但 09-22 工程A 在真实构建（VRCFury 判 ON、AAO 优化后）Play 实测 4 例（档 0 关外套/开嘴部/关内裤、档 3 猫耳压制）**都没复现失灵**——AAO 会合并/改写层，实际语义要实测，**不能凭推理断言坏、也不能凭推理断言好**。
> **取舍**：不要赌 WD 值——**一个属性只让一层写，这层每个状态都显式写满它拥有的属性**，多条件用同层多状态＋转移条件表达；这样 WD on/off 结果相同。静态等价模拟要按 WD on、WD off 两种语义各跑一遍。

## 层序是设计的一部分（走 B 时）

```
部位开关  →  整套切换  →  发型  →  配饰冲突压制  →  派生状态
```
- 选素体默认时：整套层不写素体网格 → **部位开关的值透传** ✓
- 选外挂服装时：整套层写素体网格 = false → **覆盖部位开关** ✓
- 外挂服装自己的网格由根物体门控，部位开关自由生效 ✓

## 配饰冲突压制层（开配饰要按需关掉会穿模的衣服子内容）

戴上头饰要收掉帽子、戴上腕饰要收掉长袖口、戴戒指要收掉手套 —— 这类冲突**必须处理**，
否则一开配饰就穿模。

**语义要分清，这里和「切换时顺手关掉 B」不是一回事：**

| | 「切换 A 时顺手关掉 B」 | **「配饰开着期间压制 B」** |
|---|---|---|
| 语义 | 关一次，用户之后还能再开 | 配饰开着就一直压，配饰一关自动恢复 |
| 做法 | `VRCAvatarParameterDriver` 改 B 的参数 | **单独一层写 B 的网格属性** |
| 写错的后果 | 在 clip 里写 B 的属性 → B 永久打不开 | 用 Driver → 用户手动开回来就又穿模了 |

**压制层的正确写法**（关键在「配饰关闭时那个状态必须什么都不写」）：

```
层：Acc_头饰_Suppress   （排在 部位开关层 与 整套层 之后）
  ├─ Empty      默认状态，clip 无任何曲线   ← WD=OFF 下，未写的属性从前面的层原样透传
  └─ Suppress   条件 A2_Headdress == true，clip 写 kaguya_cloth/beret.m_IsActive = 0
```

**判据**：关掉配饰后那件衣服子内容能自己回来 = 对；回不来 = 你把它写死在别的层了。

**冲突表要靠截图填，不能靠猜。** 先按「同部位」列出嫌疑对（头部：光环/头饰 × 帽子/发型；
手腕：腕饰 × 长袖；手指：戒指 × 手套；背部：翅膀/挂件 × 外套），
再逐个组合截图确认哪些真的穿模，把确认的写进冲突表，重新生成，再复验。

### ⚠ 一对冲突只能压**一个方向**，压两次会互相压没

同一对冲突写成两条方向相反的压制层，是很隐蔽的一类 bug：

```
规则甲：选了配饰 X → 关掉衣服件 Y
规则乙：开了衣服件 Y → 关掉配饰 X
```

单独看都对，**同时成立时互相把对方压没** —— 用户看到的是「这个位置什么都没有」，
而不是「某一个没显示」。因为不是任何单条规则出错，逐条检查规则也查不出来。

**规矩**：
- 先定一条**全局优先级链**（例如：头饰 > 服装头部小件 > 耳朵），冲突一律按链子压，
  **只压低优先级那一侧**。
- 冲突表里出现「A 压 B」和「B 压 A」两条，就是错的，不管它们是不是同一批加的。
- 表里的每一条都要能说出**它在优先级链上的位置**；说不出来的那条就是多余的。

**验收要遍历「组合」，不是遍历「单项」。**
判据可以写成闭式的：跑遍 `服装档位 × 冲突开关` 的全组合，
对每一格断言「这个身体位置上至少有一件是开的」，
零死锁格才算过。这个断言必须用**真动画数据**驱动（`Apply` 参数跑一遍动画层），
手动开关物体证明不了动画层会怎么写。

⚠ 判「死锁」时注意**故意的全关档**：例如兜帽档要求「不戴耳机、没有耳朵」，两边皆空是**设计**不是 bug；判据要把兜帽本身算进该档，否则误报。

## 压制层要「区间」而不是「阈值」的场合

轮盘从 2 档扩到 4 档之后，原来的 `param > 1/2` 会把**后面所有档**一起压掉。
本工程实例：耳尾扩成四档后，「压制衣服自带猫耳」这条从只压第 2 档（新耳尾）
变成连第 3 档（关闭）一起压 —— 用户把耳尾关掉时，衣服自带的猫耳反而用不了了。

区间压制要注意：**一条转移里的多个条件是「与」关系，写不出「或」**，
所以「离开区间」需要**两条**转移（低于下界一条、高于上界一条）。

## 「按遮挡状态」而不是「按选了哪套衣服」的层

有一类需求的门不是轮盘，是**某个部位有没有被盖住**：
胸围大小、乳头显隐、袜子下的脚型……客户的原话往往是
「衣服关掉的时候就恢复成 X」，那就不该把它接在整套轮盘上。

写法（WD=OFF，上层写了就盖住下层）：**一层两态**

```
「胸围」层
  ├ 裸  ：空/写默认值 + nipple 开
  └ 着装：写限制值 + nipple 关
  门 = A2_Coat / A2_Top / A2_Und 三个部件开关的**或**
```

- 进「着装」要**三条转移**，每条一个条件——一条转移内的条件是**与**关系，写不出「或」
- 回「裸」一条转移三个条件就够
- 需要按衣服细分时，「着装」态挂 motion-time（`timeParameterActive`）读整套轮盘；
  不需要细分就用普通 clip。`timeParameterActive` 是**按状态**设的，同一层里两种状态可以并存

### 尺寸类需求：先问清「默认值」还是「最大值」

有一单绕了一圈：先按「素体胸部默认调到最大」做了一整套**按服装退让**的机制
（实测各服装支持到哪一档、生成 34 条衣服侧曲线），
最后问清真实需求是**基线（全 0）就够、不额外加大**——全 0 就是厂商建模时的默认体型，
每套衣服都是照它做的，天然适配，退让机制整个不需要。

**判据先量清楚再问**：素体出厂停在 `Breast_small=100`（比基线还小 9.9%），
所以「设为 0」相对原状态**已经是放大**。把这个数摆出来，客户一句话就能定，
不用先做一套机制再拆掉。

### 衣服侧的键也要压住

厂商换装动画常把 `Breast_small` 之类写成 100（MMN 的 Jersey/Maid 出厂就是），
只压素体、不压衣服，切衣服时会缩回去。层里把两边一起写。

## 「这套衣服自带内衣」也要落进整套层

第三方整套里有自带胸衣/内裤的（实测 Kitty 那套），穿上它必须把**素体自带的内衣**关掉，
否则素体那份会从髋侧顶出来一圈。

做法不是加一个新开关，而是在**整套层**里给这几件加一条「只在某几档关」的曲线：
默认全档开（它本来就该在），只有点名的那一档写 0。这样：

- 不占参数位；
- 不跟「内衣」部位开关打架（部位开关在整套层之上，用户想全关照样能关）。

同理适用于：自带袜子的整套 vs 素体长袜、自带鞋的整套 vs 素体乐福鞋 —— 凡是
**同部位两层都在**的，都要在整套层里点名关掉素体那份。判据是逐套渲染时看有没有
「两层布料互相穿插」。
