# 生成器实现坑 · 层与回读判据

> ← [生成器实现坑（索引）](../生成器实现坑.md)　上级：[60 · 菜单与动画层](../../60_菜单与动画层.md)

这页解决的问题：**生成完之后**怎么判「真的做对了」—— 轮盘两档不同、追加层权重、空 clip + WD=ON、BoneProxy 逃出服装根。

## 生成完轮盘，**必须回读校验「任意两档效果不同」**

### 触发
**当你刚生成完一组多档 clip（轮盘 / N 选一开关）时。**

### 问
**「把每档 clip 归约成 `{(path, attribute, 值集合)}`，两两比一下，有没有两档是一样的？
这个轮盘要管的每个物件，是不是在**每一档**里都出现了？」**

```bash
grep -E "path:|attribute:|value:" EarTail_1.anim      # 这档到底写了什么
grep -rl "U_kemomimi" Assets/_Work/_60菜单/            # 这个物件被任何菜单资产提到过吗
```

### 答错了怎么办
补写缺的曲线。**同时检查该物件的父链** —— clip 写 1 但父节点被别的层关掉，依然不显示。

### 为什么这条判据是必须的
多档开关最常见的坏法是**某档漏写曲线**，于是它和另一档效果相同。
这种坏法**资产非空、能存、能播、编译零错误**，
而且**文件 md5 不同**（clip 名不一样），所以**按文件哈希比对查不出来**。

### ⚠ 别用渲染组合矩阵代替这条

渲染矩阵只能看到**效果**，而效果是多因叠加的。
「档位没接线」和「容器被服装关掉」会产出**完全相同的图**，图区分不了这两个假说。

**2026-09-07 工程C 实证**：耳尾轮盘「猫耳尾」档是空档
（`EarTail_0`/`EarTail_1` 效果集合完全相同，`U_kemomimi`/`U_tail` 三档里一次都没出现）。
70 回归跑了 **30 格组合矩阵**、80 又做了一次**构建期烘焙复验**，
**两路都没查出来**，还各自给出了「挂在服装子树下」这个自洽但错误的根因 ——
照那个根因去修（挪容器），档位**依然是死的**。

而 `grep` 一次 clip，**两秒**。

**取舍**：回读校验便宜到可以无条件做，没有「什么时候不值得」的情形。
渲染矩阵仍然要跑，但它的作用是**查你没预料到的**（穿模、层级冲突、材质错乱），
**不是**回答「这个开关接没接线」。

⚠ 「任意两档不同」应写成「**没有两档在所有外部条件下都相同**」：条件档（依赖别的参数）相同可能是正常设计，只有**无条件**相同的才是缺陷。

## 追加动画层：`AddLayer` 建出来的层 `defaultWeight = 0`

### 触发
**往一个已经存在的 AnimatorController 里追加一层时** ——
补丁脚本、轮盘扩档、加压制层。主生成器一般写对了，**补丁脚本是重灾区**
（它天生比主生成器少走一遍检查）。

### 问
**「这一层的 `defaultWeight` 是几？」**

`AnimatorController.AddLayer(string)` 建出来就是 **0**。
权重 0 的层：**状态机照常求值、`VRCAvatarParameterDriver` 照常触发、转移照常发生，
只有曲线写不出去。** 症状是「参数面板一切正常，物体不动」——
和「排在后面的层无条件写了同一个属性」**症状完全一样**，很容易查错方向。

**MA 只救第一层**：`AnimatorCombiner` 把每个被合并控制器的**第 0 层**强制成权重 1，
其余层原样带过去。所以源工程里第 N(>0) 层的那个 0 会一路带到构建后。

### 答错了怎么办

```csharp
var ls = ac.layers;                 // ⚠ 必须整个数组回写，改副本无效
for (int i = 0; i < ls.Length; i++) ls[i].defaultWeight = 1f;
ac.layers = ls;
foreach (var l in ac.layers)        // 回读断言
    if (l.defaultWeight != 1f && !有意为0名单.Contains(l.name))
        throw new Exception("层权重为 0：" + l.name);
```

### 取舍：不能一律置 1

| 情况 | 权重 0 是不是缺陷 |
|---|---|
| 厂商控制器的**第 0 层** | 否 —— Unity 序列化惯例，运行时当 1 用 |
| 非 0 层，且**有 `VRCAnimatorLayerControl` 拨它** | 否 —— 这是「按需接管」的正常做法 |
| 非 0 层，**没人拨** | **是缺陷** |

所以判据要先扫一遍全工程的 `VRCAnimatorLayerControl`，把被拨的层名列进白名单，
再对剩下的断言。**代价不对称**：漏判 → 整档菜单是死的、要到真机才发现；
误判置 1 → 那一层无条件生效、可能压掉别的层，同样严重。**两边都要查，不能靠默认。**

### 证据（2026-09-08 工程C）
`CommC_StickerRadialPatch.cs:213` 调 `ac.AddLayer("Acc Sticker")` 后没设权重
→ 贴纸四档轮盘整档是死的。同工程 `SetupC_60Menu.cs:297` 与
`CommC_EarTailPatch.cs:306` 都显式写了 `= 1f`，**只有补丁脚本漏了**。

⚠ **连带后果**：70 阶段的组合矩阵、80 阶段的构建期复验都跑在这个补丁之前。
**改过动画层之后，之前的组合遍历结论全部作废，必须重跑。**

## 空 clip + WD=ON：厂商把「默认值」定义成了**你场景里的当前状态**

### 触发
**看到厂商的某个开关层，"开"档挂的是 `Dummy.anim` / `Empty.anim`（0 条曲线）且 WD=ON 时。**

### 问
**「这一层还原的那些属性，在我场景里现在是什么值？」**

WD=ON 遇到没写的属性，还原的是**构建那一刻场景里的值**，不是厂商设计值。
于是同一个参数、结构完全相同的两层，会因为场景状态不同而**表现不一致**。

### 答错了怎么办
别去改场景（脆，任何人手滑就静默失效）。
在**自己那一层**（合并在厂商层之后，压得住）显式写一条曲线；
其余档不写，WD=OFF 下由厂商层透传，行为仍然正确。

### 证据（2026-09-08 工程C）
耳尾轮盘档 0 的 Driver 写 `Ear=0, Tail=0`（都=显示），厂商 `Ear`/`Tail` 两层结构一模一样，
结果**素体耳显示、素体尾不显示** —— 因为场景里 `Other_ear.activeSelf=True`、
`Other_tail.activeSelf=False`。

## BoneProxy 会把件搬出服装根 —— 换装关不掉它

### 触发
**某件服装里有子物体挂了 `ModularAvatarBoneProxy`（头饰、抱持件、gimmick 锚点）。**

### 问
**「烘焙之后它还是那个服装根的子孙吗？换装 clip 关得掉它吗？」**

### 答错了怎么办
BoneProxy 构建期把它**搬到目标骨下**（`_Outfit/X/HeadDress` → `Armature/.../Head/HeadDress`）。
换装 clip 只写服装根的 `m_IsActive` → **搬走的那件永远显示**，穿别的衣服照样戴着。

修法：在**每一个**换装 clip 里显式写它的 `m_IsActive`（写源路径即可，NDMF 会重映射）。
只写「本套 = 1」不够，其余每套都要写 0。

### 为什么会一直没被发现
**BoneProxy 编辑期不生效** —— 编辑期它还在服装根下，手动开关、编辑期渲图、
甚至组合矩阵遍历（如果按源层级判定）**全都正常**。只有烘焙后才暴露。

### 判据（不看图，两条都要）
1. 烘焙体里，每个带 BoneProxy 且**自己或子孙有渲染器**的服装件，
   它的最终父链里还有没有原服装根；
2. 合并后控制器里，有没有曲线控制它（或它新父链上某一层）的 `m_IsActive`。

**两条都否 = 逃逸，永远显示。** 没有渲染器的（gimmick 锚点、PhysBone 挂点、
发型的 armature 根）逃逸了也无视觉影响，不用管 —— 判据要先按渲染器筛，否则一堆假阳性。

### 证据（2026-09-08 工程C）
LUNALICE 的头饰组（几个渲染器：头饰、蝴蝶结、猫耳）被搬到
头骨下面。换到 WinterCozyKnit 时黑蕾丝发箍与珍珠吊坠仍在头上，
且穿透贝雷帽。**交叉评审模型在不知道设计意图的情况下独立指认了这条**
（「未卸载/隐藏 01 套装特有的黑色蕾丝猫耳发箍及珍珠吊坠」）。

⚠ 修完必须**重新烘焙 + 重渲**才算验证 —— 而且渲图脚本要用**真动画数据**摆状态。
手动 `SetActive` 服装根，正好复现不了这个缺陷（因为缺陷就在「关根关不掉它」）。

## 两个 2026-09-18 撞到的收件与取值坑（工程A）

### 厂商 ON clip 会顺带开「备选件」
- **触发**：按厂商 ON/OFF clip 的路径把物体收进开关组时。
- **问**：「clip 里的每条路径，在厂商预制体里默认 `m_IsActive` 是不是都为 1？」默认关的是备选件（例 `outer_breast_big_open`，说明书要求二选一）。
- **取舍**：备选件不进组（`VENDOR_ALT` 排除表），保持预制体默认关；要用再单独做切换。收进来会把两件几乎重合的网格同时激活（实测 70% 顶点相距 ≤0.5 mm）。

### 轮盘档位取值要用精确的 i/n
- **触发**：审查或回读时给 Motion Time 轮盘设值。
- **问**：「这个值是不是 ≥ 该档的起点 i/n？」`0.2857 < 2/7` 会落进上一档（常量切线）。
- **取舍**：审查取档中点 `(i+0.5)/n`；文档档位表写分数不写四位小数。
- **边界 = 关键帧时间 ÷ clip 的 `m_StopTime`**（2026-09-19 验收 BD）：工程A `Dial_发型.anim` 的 `m_StopTime=1.0166667`（不是 1），参数 0.3333 映射到 clip 时间 0.339，已过 1/3 处的关键帧 → 落在 GoldenHour 档，不是第 0 档；真实边界约 0.3279。别按 i/n 心算，先读 clip 的 `m_StopTime` 与关键帧时间。
- **末档与 1.0（B-补-16 口径，2026-09-19）**：clip `m_LoopTime: 1` 时参数 1.0 回绕成第 0 档——工程E 某厂商 Motion Time 动画的末键落在 1.0，末档因此永远选不到（修法：副本改等分、关循环，见 工程E 施工记录 09-19）。审查与依赖编译器一律：档 i 取 `(i+0.5)/n`，末档区间写成 `[lo, 1]`（不循环）或 `[lo, 1)`（循环）；**不用 1.0 做档值**。新接手的厂商 Motion Time 轮盘先查 `m_LoopTime`。
