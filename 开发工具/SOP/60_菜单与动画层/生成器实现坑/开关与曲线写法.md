# 生成器实现坑 · 开关与曲线写法

> ← [生成器实现坑（索引）](../生成器实现坑.md)　上级：[60 · 菜单与动画层](../../60_菜单与动画层.md)

这页解决的问题：生成的 clip / 曲线**写得对但不生效或效果不对** —— 取值、绑定名、父物体、厂商参数、粒子、换外观档位。

> 「生成器必踩的六个坑」的 ②~⑤ 在本页，① ⑥ 在 [落盘与幂等](落盘与幂等.md)。

### ② 验收图必须由**真动画数据**驱动，不能手动 SetActive

手动摆出来的图只能证明「我以为的状态长这样」，**证明不了动画层真会这样输出**。
下面的 ③④ 两条都是换成真数据之后才暴露的，手动预览下永远看不见。

做法：读生成的 controller → 按参数值决定每层停在哪个状态 → 逐层把 clip 的曲线应用上去。
本工程所有层都是 Override、权重 1、WD=OFF，所以「按层序依次应用」等价于运行时。
参考实现 `A2State.cs`。三条走不通的路也记在那个文件头里
（`animator.SetFloat` 够不到 FX 参数、`playableGraph` 无效、`AnimationMode` 采样会被回滚）。

### ③ 轮盘「关」档的取值**不是 0**

第 i 档占 `[i/N, (i+1)/N)`，程序里取区间中点 `(i+0.5)/N`。三档轮盘的「关」是 **0.167**。
压制层阈值写 `0.01` 的后果：配饰明明关着，压制层一直 Hide，**把衣服上的帽子/手套永久压死**。
阈值一律写 `1f / 档数`，别写常数。

### ④ 只有一个关键帧的 clip，`clip.length` 是 **0**

部位开关、压制层的 clip 全是单帧。任何 `if (clip.length <= 0) continue;` 的代码都会整层跳过。
生成时给单帧 clip 补一个 `t = 1/60` 的尾帧，读取时也别拿 length 当门槛。

### ⑤ 父物体也要开

厂商服装挂在 `kaguya_cloth/` 下。只写子件的 `m_IsActive`、父物体关着，整套衣服都不显示。
凡是「一组件共用一个空物体作父」的，父物体必须进同一条曲线表。


## 手指肌肉的曲线绑定名：写错照样存得下，运行时静默失效

人形 clip 的肌肉曲线绑定名，手臂用 `Left Arm Down-Up`（同 `HumanTrait.MuscleName`），
但**手指是 `LeftHand.Index.1 Stretched` / `LeftHand.Index.Spread`**，不是 `Left Index 1 Stretched`
（全部 40 条以 SDK 自带的 `proxy_hands_fist.anim` 为准）。

**通用变换规则**（拿到任意肌肉名都能推）：

```
<Side> <Finger> <剩余>   →   <Side>Hand.<Finger>.<剩余>
例：Left Index 1 Stretched → LeftHand.Index.1 Stretched
    Right Thumb Spread    → RightHand.Thumb.Spread
```

`<Finger>` ∈ `Thumb / Index / Middle / Ring / Little`，`<Side>` ∈ `Left / Right`。
**只有手指要做这个变换**，手臂、身体、头部的肌肉名与 `HumanTrait.MuscleName` 一致，原样用。
写错的名字 `SetEditorCurve` 照收、`GetCurveBindings` 照数，**只有运行时不生效**且不报错 ——
上面 ① 的回读校验挡不住它，回读用的是同一个错名字。

**判据**：Play 下 `GetHumanPose` 读出的手指肌肉 40 条恒为 0.000、同一份 clip 的手臂正常。

## 要改厂商自己的参数：用 VRC Avatar Parameter Driver，别复刻它的动画

素体/服装包常把一个功能做成「**一个 Float 参数 + 一棵混合树**」。
本工程的例子：輝夜的尾巴条数是 `kaguya tail Count`，混合树 9 个阈值 0.1～0.9，
各挂 `tail_control/1/`～`/9/` 下的 clip（**目录名就是条数，不用猜**）。

想让自己的轮盘顺带切它，有两条路：

* ❌ 自己复刻那些 clip —— 它们用**路径哈希**寻址，复刻不出来。
* ✅ 单开一层，每档一个状态，状态上挂 `VRCAvatarParameterDriver`，进入时 `Set` 那个参数。

```csharp
var st = sm.AddState("尾数_九尾");
var d = st.AddStateMachineBehaviour<VRCAvatarParameterDriver>();
d.parameters.Add(new VRC_AvatarParameterDriver.Parameter {
    type = VRC_AvatarParameterDriver.ChangeType.Set, name = "kaguya tail Count", value = 0.9f });
var tr = sm.AddAnyStateTransition(st);
tr.hasExitTime = false; tr.duration = 0f;
tr.canTransitionToSelf = false;          // ⚠ 不加这句会每帧重进、每帧写参数
tr.AddCondition(AnimatorConditionMode.Greater, slot / (float)n, param);
tr.AddCondition(AnimatorConditionMode.Less, (slot + 1) / (float)n, param);
```

两个坑：

* `canTransitionToSelf = false` 必须加。否则条件成立期间每帧重进状态、每帧写参数，
  用户手动调过的值会被一直按回去。
* **编辑期预览模拟不了 Parameter Driver**（它只在运行期执行）。
  所以这类档位在离屏渲染图上**看起来完全一样**，那是预期的 —— 只能进 Play 模式验。
  拍对比图的工具里要把这句写进注释，否则下次看到「两档一模一样」又要查半天。

## 粒子特效的开关：切渲染器，不切物体（2026-09-03 实测）

**`ParticleSystem.playOnAwake` 只在 Awake 触发一次，不是每次 OnEnable。**

所以用 `m_IsActive` 开关一个粒子物体：第一次激活能播，**关掉再开就永远不播了**
—— 系统停在 Stopped 状态，没有任何东西会再让它 Play。
表现是「轮盘拨到那一档，物体激活了，但一颗粒子都没有」。

正确做法：**物体常开，动画只切 `ParticleSystemRenderer.m_Enabled`。**

```csharp
// classID 199 = ParticleSystemRenderer
EditorCurveBinding.FloatCurve(PathOf(r.transform), typeof(ParticleSystemRenderer), "m_Enabled")
```

一组粒子往往有多个渲染器（厂商常留一个不发射的根容器 + 若干真正的发射子物体），
**全部都要写曲线**，不然根容器那层会漏。

副作用要跟用户讲清楚：**Hierarchy 里这些物体的名字会一直是白的（常激活）**，
这是有意为之，不是漏关。粒子在渲染器关着时仍在模拟，代价是常驻，
把 `cullingMode` 设成 `AlwaysSimulate` 保证行为一致。

### 配套：编辑期看不到粒子是正常的

**编辑模式下粒子系统根本不跑**，除非你在 Hierarchy 里选中它
（那时 Scene 视图的「Particle Effect」预览面板会调 `Simulate` 推进它）。
所以「物体是激活的但看不到粒子」在编辑期**证明不了任何事**。

要在编辑期看效果，写个工具绕开「选中」这个前提：

```csharp
foreach (var ps in group.GetComponentsInChildren<ParticleSystem>(true)) ps.Clear(true);
group.GetComponent<ParticleSystem>().Simulate(6f, true, true, false);   // 推到稳态
// 然后渲图
```

**判亮度/可见性不要靠观感**：同机位拍「渲染器关 / 开」两张做像素差，
差集就是粒子真正画出来的像素，能把「淡」和「没有」区分开。
参考实现：工程A 的 `PsPreview.cs`。

厂商同一套特效的不同图案，**贴图本身的平均亮度可能差 3 倍以上**
（实测 8.4 / 17.3 / 28.1），再乘各自色调倍率，同一个轮盘的几档观感能差 5 倍。
拉齐的手段优先选 `startSize`（保住图案和颜色），不要为了拉亮度去换图案 ——
换了会破坏「哪一档配哪个图案」的主题一致性，Gemini 会当场抓出来。

## 换外观的档位：**材质引用能动画化，贴图引用不能**

### 触发
**菜单要切的是"同一个网格的不同外观"** —— 换色、换花纹、换质感。
（要切的是"不同物件"就不属于这里，走 `m_IsActive`。）

### 问
**「厂商这套外观差异，差在材质**属性**、材质**引用**，还是**贴图**引用？」**

三种的可动画性完全不同：

| 差在哪 | 能不能动画化 | 曲线绑定 |
|---|---|---|
| 材质**属性**（颜色、浮点、向量） | ✅ | `material._Color2nd.r` 之类的 float 曲线 |
| 材质**引用**（换整份 `.mat`） | ✅ **PPtr 曲线** | `m_Materials.Array.data[N]`，`SetObjectReferenceCurve` |
| **贴图**引用（换 `_MainTex`） | ❌ **做不到** | —— |

所以「档位之间差的是贴图」时，**唯一的路是把贴图差异打包进 N 份材质，改成换材质引用**。

```csharp
var b = EditorCurveBinding.PPtrCurve(meshPath, typeof(SkinnedMeshRenderer),
                                     "m_Materials.Array.data[" + slot + "]");
AnimationUtility.SetObjectReferenceCurve(clip, b, new[]{
    new ObjectReferenceKeyframe{ time = 0f,      value = mat },
    new ObjectReferenceKeyframe{ time = 1f/60f,  value = mat } });   // ⚠ 单帧 clip 仍要补尾帧
```

### 顺带：**材质槽可以扩容，同一个网格画两遍**

厂商做"整块身体半透明化"这类效果的常见手法，不是改身体材质，而是
**把身体网格的材质槽从 1 扩到 2**：槽 0 = 带遮罩的皮肤，槽 1 = 一层玻璃/覆盖壳。
换颜色 = 换槽 1 的材质引用。

两层各写各的曲线，互不干扰，**比"一份材质里塞两套参数"干净得多**：

```
槽 0 ← 形态层（关 / 半 / 全）      三份皮肤材质
槽 1 ← 颜色层（六色 + 一份"空壳"）  空壳 = alpha 0 的同款材质，用于"形态关"时让第二遍不画东西
```

⚠ **"关"档不能只写槽 0** —— 槽 1 还留着上次那份玻璃就会继续画。
要么写一份 alpha 0 的空壳材质进去，要么把两个槽放进同一层。

⚠ **网格优化器（AAO）会合并网格、可能重排材质槽**，
所以扩容后的槽序**必须在烘焙体上复查**，别只信源场景。

### 答错了怎么办
先跑一遍「六份材质之间到底差哪些属性」的差异全表
（见 [素材与材质排查 · 九](../../问题定位/素材与材质排查.md)）。
差异**只在浮点/颜色** → 走属性动画，材质份数不变；
差异**包含贴图** → 只能走换材质引用。

### 证据（2026-09-08 工程C · Aquaglass 腿部玻璃）
我先按「属性动画」实现了六色轮盘，结果六档里有**两对是死档** ——
`water/Blue` 的 `_Color` 完全相同（差别在法线波纹贴图），`purple/white` 同理（差别在 matcap）。
改成「换整份 `glass_*.mat` 到槽 1」之后六档才真的两两可分。
