# 60 · 互斥机制：目录、失效场景与必查项

> ← [60 · 菜单与动画层](../60_菜单与动画层.md)。触发：本单有多套/多件同部位衣服、要选互斥工具时；或验收时怀疑「工具装了没接线」。

本页解决的问题：**衣服之间「不能同穿」该怎么接、装了互斥工具为什么没生效、验收时怎么查出来。**
判据先看厂商自己的分组（[03 第四节](../03_装配与冲突通则.md)），下面是历史工程的目录与实测失效场景（C §一、K #6、本文核）。

## 机制目录

| 机制 | 怎么认 | 历史出现 | 典型失效场景 |
|---|---|---|---|
| **ClothGroup**（VRCFury） | 菜单里有 `ClothGroup` / `inverseToggleGroup` 字段 | Milfy（6 组） | 6 组同时选两套没验过；工具只装在**备份 prefab** 里；`inverseToggleGroup` 全空，靠共享 int + advanced toggle |
| **3bitInt** | Int 参数分档（8 档） | Manuka（4 组×8 档）、H6-Shinano（3 个 Int） | 生效控制器与原版/Mod 并存，改错那份；3bitInt 引用的 Int 参数不在活跃头像参数表里 |
| 单个 Float 驱动时间轴轮盘 | 一个 Float 加常量切线 | 早期-作者、H8-Shinano | **停在两档之间**；外装开时默认五件是否隐藏没读 |
| RadialPuppet 控服装 | 轮盘 `RadialPuppet` | H3-Eku、H9-Sio | 层机制未回链；轮盘中间值 |
| ObjectToggle 显式写反向列表 | 反向条目表 | P1 | 新加衣服**忘回填反向条目** |
| 各自独立开关（无互斥） | 每件一个 Bool | H1-Eku、Sio×2、Rurune、H7-Shinano 外装 | **两件同开疑似穿模**，双写身体键 |

## 必查项（四项，都可静态查）

1. **MA MenuItem 必查**：只看 `VRCExpressionsMenu` 会误判「缺项/参数悬空」——**连同 MA MenuItem 一起解析**。厂商子菜单挂没挂进实际菜单树、构建后参数名带 `__MA/AutoParam/…` 后缀，都以构建后（`T4 菜单导出`）为准。
2. **ClothGroup 必须在正式场景**：工具只存在于备份 prefab / 被停用的根，等于**没接线**；确认它引用的是活跃根下的对象。
3. **死参数**：clip 曲线路径解析不到（AAO 删/改名后常见）→ 烘焙克隆上做「参数→层→clip 曲线路径」解析，**0 条可解析即死参数**（Milfy `trace_param.txt` 判出 5 处）。
4. **层默认权重 0 必查**：烘焙后逐层读 `m_DefaultWeight`，对照全部 LayerControl，列出**权重 0 且无人抬权**的层及控件（H3-Eku `Breast` 就是这一型：菜单有控件，拨了没反应）。

## 达不到怎么办

- 同部位默认态下开着的来源数 **> 1** 就是接错了：先按 [03 第五节](../03_装配与冲突通则.md) 判「装饰还是变体」，再选机制，**别靠感觉**。
- 互斥工具装了但没接线：**不要用运行时逻辑补**，回接线本身；补不上就在交付说明里写「该互斥未生效」。
- 轮盘中间值：至少验 `1/4 / 1/2 / 3/4` 三档（见 [70](../70_回归测试.md)）；停在中点时两套同时半开就是缺陷。
