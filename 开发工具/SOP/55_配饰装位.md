# 55 · 配饰装位　🤖

> 配饰＝光环、头饰、耳尾、腕饰、戒指、项链这类**自带独立骨架、要钉到人形骨上**的小件。
> 与 [50 服装发型](50_服装发型装配.md) 分开，是因为它们的装法、验收方式、菜单形态都不同。

## 铁律一：位姿是**算**出来的，不是填出来的

手填欧拉角在这一步是反模式，理由是硬的：

- **人形骨的局部坐标轴由素体作者随手定**，八根手指骨互不相同。手填必然是八组
  magic number，且换个素体全部报废。
- 实测：戒指填 `Vector3.zero` 是平躺在手背上，填 `(0,0,90)` 只是换个方向躺着 ——
  两次都「看起来像在调」，其实都在瞎猜。

表里只留「套在哪段骨上、套在这段的百分之几处」+ 两个默认 1.0 的微调系数，
其余全部从几何推。参考实现：`AccMountA2.cs` 的 `FitBand` / `LimbWidth` / `HandBack`。

## 铁律二：观感不能替代判据，但判据过了也要有一张能看懂的图

戒指那一轮，俯视图里环的下半圈埋在手指里，只剩上半圈露出来像「立着一根丝」——
我据此**连着两轮**报告「没套住」。真相是数值判据：偏心 0.00 mm、夹角 0.0°，早就套住了。

所以两样都要：

- **可证判据**（自动跑）：肢体轴线到孔心的距离 < 内半径，且轴线与孔轴夹角 < 12°。
- **能看懂的图**（人看）：见下面「验收视角」。

## 铁律三：不用 MA BoneProxy —— 编辑期不生效

实测 MA 1.18.1：**BoneProxy 在编辑期完全不生效**，只有 NDMF 构建（进 Play / 上传）
时才把物体吸到骨骼上。编辑期物体一直停在原点。

后果很严重：**「逐个截图验收装位」彻底做不了**（离屏渲染走的就是编辑期），
第一版光环因此渲染在脚底下，看图的人会以为是位置算错了。

→ 改成**直接父子挂到骨骼 Transform 下**（`<人形骨>/Mount_<名>/<配饰>`），所见即所得。
代价是动到了素体预制体实例的骨架层级 —— 可接受，AI 侧可维护性优先于预制体纯净度。

两个配套注意：

- 幂等重跑时要**全树**找 `Mount_*`（挂点已经不在 `_Acc` 下了），
  并把非副本的配饰先移回 `_Acc` 再删挂点，否则一重跑就把配饰删了。
- 第一版留下的 BoneProxy **残留组件必须清掉**，否则构建期它会把物体再挪一次，
  跟直接父子挂载打架。

## 也不用 MergeArmature

配饰各自带独立骨架（`Armature_halo` / `armature.tail` / `アーマチュア`），
骨名与人形骨完全不同，MergeArmature 会映射 **0 根骨**。

一个根里含多套骨架的（耳 + 尾），要**分别挂**到各自的人形骨上
（`armature.ear`→Head、`armature.tail`→Hips），缩放写在 armature 本身。

---

> → [「骨段 <0.5 m」判据要分两步](55_配饰装位/骨段长度判据两步.md) —— 先量 ≥0.5 m 的骨段、再逐条查在不在 PhysBone 模拟链里；「不甩飞」≠「位置对」，另用世界坐标判；不开 Unity 读 PhysBone 根的字段名。

## 铁律四：**定位参照 ≠ 父骨**——父骨只能选不会自己转的骨

**触发**：给脸上/头上的配饰选挂点骨时。**问句**：这根骨会不会被视线、面捕、表情、口型驱动转动？会 → 只能拿它**算位置**，不能当**父骨**。
眼球骨 `eye.L/R`（VRChat 视线与面捕会转）、下巴 `Jaw`、舌头骨、耳朵/头发动骨都属于「会自己转」；目元贴纸、泪痣、脸颊贴纸的父骨应是 **Head**。
> 实测（工程A，09-22 作者报「目元贴片骨骼绑错」）：`NewAccA2.cs` 以 `LeftEye` 为锚点，在 `eye.L` 下建 `NAMount_Acc_目元_*`、还删了厂商挂 Head 的 BoneProxy，
> 贴纸随眼珠在脸上滑。改法：用眼骨算出世界位姿后 `SetParent(Head, worldPositionStays:true)`；挂点路径变了，**引用它的动画路径要同步改**。

### 步骤 3 · 落一件装位并复跑　🤖

**前置**
- [ ] **一次只落一件**，上一件没过判据不开始下一件

**执行**
1. 运行 `AccMountA2.cs` 的菜单项 `配饰装位`（各类件的挂法见子页）
2. 参数不动**再跑一次**
3. 回读校验 + 骨架高度自检；改动无效用 `PrefabUtility.RevertPropertyOverride` 精确回退，不用撤销栈

**后置判据**

| 期望 | 怎么读 |
|---|---|
| 环状件：偏心 < 内半径 且 夹角 < 12° | 装位报告该件行 |
| `c.parent == mount` 为 true；BoneProxy 数 == 0 | 挂完断言；按组件全树查 |
| 每段骨到父骨距离 ≤ 30cm | 逐根量，报告打最大值 |
| 两次报告逐行相同、世界坐标差 == 0 | diff 两份报告 |
| `|eye.L.y − 基线| < 0.02` | 自检输出行 |

**STOP**
- 报告出现 `找不到环状结构` / `骨长估算`；断言失败；骨段 > 30cm
- 第二次跑错位 → 拆挂点用了 `worldPositionStays: false`，改脚本后重来
- 对象已反复改脏 → 删掉从预制体重新实例化

**前置**
- [ ] 观测通道能还原目标现象：离屏渲染走编辑期，不模拟动骨（[观测口径](问题定位/观测口径.md)）

**后置判据**

| 期望 | 怎么读 |
|---|---|

## 戒指的手指轮盘（用户惯例）

- 一个轮盘切**戴哪根手指**：0–7 = 左小、左无名、左中、左食、右食、右中、右无名、右小
  （不含拇指）。**这个轮盘不管开关**，默认 6 = 右手无名指。
- 八根手指各一份副本，各自 `FitBand`，轮盘切的是「哪份激活」。
- 同一位置有 ≥2 件饰品（两种光环、两条项链…）→ **从 Toggle 转轮盘**：
  0=关，1=饰品1，2=饰品2…详见 [60 菜单与动画层](60_菜单与动画层.md)。

## 验收视角（`AccShots.cs`）

以配饰**自身包围盒**定框 —— AvatarPortrait 的手部特写是以**骨骼**定框的，配饰偏一点就跑出画外。

| 视角 | 看什么 |
|---|---|
| **顺轴** | 顺着肢体看过去，环有没有套住肢体截面，一眼可判 |
| 侧视 | 环与肢体的贴合度、装饰朝向。**要选背离手掌中心那一侧**，否则相邻手指挡个正着 |
| 俯视 | 整体观感 |
| **solo** | 素体全隐，只留这一件。埋在头发/衣服里的件（头饰实测三张全是头发）非它不可 |
