# 60 · 菜单与动画层　🤖

**目的**：让换装可控、参数不超预算、结构可脚本遍历。
**产出**：菜单资产 + 动画层 + `菜单结构.md`
**这是出 bug 最密集的一段。**

## 一句话铁律

**凡是厂商已经有参数层的东西，一律驱动参数，不要动网格。**
同一个错误在一单里犯过三次：

> → 三个实例（一个厂商参数同时管网格/骨骼姿势/形态键）与三工程介入强度对照 → [结构惯例 · 实测样本](60_菜单与动画层/结构惯例.md#实测样本)。

**只关网格永远是安全的**（网格关掉后骨骼折成什么样都无所谓）；
出问题的方向只有一个 —— **网格开着但骨骼没摆正**。

## 第二条铁律：一条属性只能有一个层管

挪层时**必须同时从原来那层的表里删掉**。被两处写的胜负规则**分两种，而且相反**：

| 被两处写的 | 胜负 | 症状 |
|---|---|---|
| 动画曲线 | **按层序**，后盖前 | 稳定：开关「怎么点都没反应」 |
| 参数（Driver Set） | **按事件顺序**，谁后进状态谁算数 | 时有时无：「切一圈回来它自己回来了」 |

第二种编辑期与组合渲图都证明不了，只能**读控制器数「有几个层写这个参数」**。
修法与四种写法 → [属性归属与写法](60_菜单与动画层/属性归属与写法.md)。

## 两条实现路线，按素体情况选

| | A. MA 反应式组件（Object Toggle + Menu Item） | B. 手写 AnimatorController 层（`菜单架构/MenuGen.cs`） |
|---|---|---|
| 形态 | 每个开关一个组件，声明式 | 生成 controller + clip + 菜单资产 |
| 适用 | **素体干净、服装自带 MA 且互不干涉** | **要与厂商已有参数层交互、需要精确控制层序** |
| 优点 | 生成和回读都简单，结构可直接遍历 | 层序完全可控，能用 ParameterDriver 同步厂商参数 |
| 代价 | 层序由 MA 决定，与厂商层抢同名属性时不好压 | 代码量大，改素体要重填三张表 |

**判据**：先看素体和服装自带哪些参数层（[50 的 Probe](50_服装发型装配.md)）。
厂商参数层与你要控制的东西**有重叠**就走 B，**完全不重叠**走 A。

## 硬约束

| 项 | 上限 |
|---|---|
| 每个菜单控件数 | **8** |
| 参数预算 | **256 bit**（Int/Float 各 8、Bool 1）。超了不等于要砍功能——VRCFury 会压，见 [VRCFury 参数压缩](60_菜单与动画层/VRCFury参数压缩.md) |
| ControlType | 101 按钮 / 102 开关 / 103 子菜单 / 203 旋钮 |

插件自带的 MenuInstaller 用 `installTargetMenu` 塞进自己的子菜单，**别改插件预制体**。

> → [参数审计与语义冲突](60_菜单与动画层/参数审计与语义冲突.md)：编辑期看不到构建期生成的参数（24/108 → 92/177）；头顶常见缺陷是语义冲突（Milfy 两副耳），判据别写成「有没有穿模」。

## 确定化步骤

### 步骤 1 · 探参数层，定路线　🤖

**前置**
- [ ] 按 [02](02_环境准备与人工介入.md) 确认环境可用
- [ ] [50](50_服装发型装配.md) 已通过

**执行**
1. 跑 50 的 `Probe()`，列出厂商参数层及各自管的物体/形态键
2. 与本单要控制的物体求交集，交集条数与路线写在 `菜单结构.md` 第一行

**后置判据**

| 期望 | 怎么读 |
|---|---|
| 交集 == 0 → 路线 A；> 0 → 路线 B | `菜单结构.md` 第一行 |

**STOP**
- `Probe()` 报错或某件读不出参数层 → 交回人

### 步骤 2 · 出菜单结构候选　🎨 出候选后需拍板

**前置**
- [ ] 步骤 1 已写明路线
- [ ] 各套衣服的部件图鉴已在（缺的标「待补」，[部件理解与菜单编排](50_服装发型装配/部件理解与菜单编排.md)）

**执行**
1. 按[结构惯例](60_菜单与动画层/结构惯例.md)（机制硬、聚类软）与「硬约束」写 `菜单结构.md`：每控件一行——分区、ControlType、参数名/类型、目标物体
2. 只有分区与命名出 2 个候选给人拍板；机制不出候选

**后置判据**

| 期望 | 怎么读 |
|---|---|
| 每菜单控件数 ≤ 8 | 按分区数行 |
| Int/Float 各 8、Bool 1 求和 ≤ 256 | 参数列求和 |
| 整套、发型、同部位 ≥2 饰品：ControlType == 203；戒指：102 + 203（0–7）两行 | 控件列 |

**STOP**
- 位数 > 256 → 交回人裁功能，不自行删控件
- 分区未拍板 → 不进步骤 3

### 步骤 3 · 截图填冲突表　🎨 出候选后需拍板

**前置**
- [ ] 步骤 2 已拍板

**执行**
1. **先按位置枚举「来源」，不是按件列嫌疑对** —— 每个位置（耳/尾/头顶/腕/指/背）
   把**所有**可能占用它的件列全：素体自带、各套衣服自带、**各档发型自带**、外购配饰。
   来源清单让场景枚举 + 逐件 solo 渲图确认它到底是什么，**别按名字猜**
2. 逐组合离屏渲染，穿不穿模送 [05](05_多模型评审规程.md) 评审，不自己下结论
3. 确认的写进冲突表，每条注明优先级链位置

**后置判据**

| 期望 | 怎么读 |
|---|---|
| **每个位置的来源清单，与「场景里落在该位置的件」逐条对得上** | 来源表 vs solo 渲图 |
| 「A 压 B」与「B 压 A」同时出现的对数 == 0 | 冲突表按无序对计数 |
| 优先级链位置空值数 == 0 | 冲突表 |
| **同一位置默认态下开着的来源数 ≤ 1** | 按默认参数求值后数 |

**STOP**
- 评审结论不一致 → 交回人看图

### 步骤 4 · 生成资产并回读　🤖

**前置**
- [ ] 步骤 3 冲突表已定
- [ ] 只落这一个改动；上一个无效的已用 `PrefabUtility.RevertPropertyOverride` 回退，不用撤销栈

**执行**
1. A：加 MA Object Toggle + Menu Item；B：填 `菜单架构/MenuGen.cs` 三张表，执行它注册的菜单项
2. 核对：压制阈值 == `1f / 档数`；单帧 clip 补 `t = 1/60` 尾帧；父物体进曲线表
3. 回读校验 + 骨架高度自检（[场景损坏与恢复](问题定位/场景损坏与恢复.md)），再存盘

**后置判据**

| 期望 | 怎么读 |
|---|---|
| 每个 clip `GetCurveBindings(...).Length == want` | 生成器回读行 |
| 每个菜单资产 > 330 字节 | 文件系统 |
| `eye.L` 世界 y 与基线差 < 0.02 | 自检输出行 |

**STOP**
- 回读条数不等 → 不重跑，先查 [生成器实现坑](60_菜单与动画层/生成器实现坑.md) ①
- 自检不过 → 不存盘

### 步骤 5 · 烘焙后量交付态　🤖

**前置**
- [ ] 步骤 4 通过并已存盘

**执行**
1. NDMF 手动烘焙，判据全读**合并后**控制器，不读源工程
2. 进 Play 跑 `ParamAudit.cs`
3. 用真动画数据（`A2State.cs`）跑 `服装档位 × 冲突开关` 全组合
4. 清掉 `<名字>(Clone)`，再跑骨架高度自检

**后置判据**

| 期望 | 怎么读 |
|---|---|
| 构建后位数 ≤ 256；无菜单或无动画层的参数 == 0 | `ParamAudit.cs` 输出 |
| 「该部位一件都没开」的死锁格 == 0 | 组合遍历输出 |
| `VRCAnimatorLayerControl` 指向的层名与合并后控制器一致 | 合并后控制器层列表 |
| `VRCAvatarDescriptor` == 1；`eye.L` 差 < 0.02 | 组件计数；自检输出行 |

**STOP**
- 死锁格 > 0 → 回步骤 3 查压制方向，不改生成器
- 位数 > 256 → 回步骤 2
- Parameter Driver 档位在离屏图上一模一样 = 预期，只能 Play 验

## 验收

```
ParamAudit.cs（Play 模式下）  → 参数数 / 位数 / 每个参数有没有菜单、有没有动画层
逐资产回读                    → 字节数 > 空菜单基线
逐组合遍历                    → 见 70 回归测试
```

**不开 Unity 也能读菜单树**：查「菜单长什么样」「控件挂哪个参数」直接解析 `.asset` YAML，快且可跨工程比对。
⚠ 缩进坑：控件在 **2 空格**、`subParameters` 条目在 **4 空格**，按 `\s*` 切会切出幽灵控件；先按缩进层级分组再切。

## 症状 → 该查哪里

开关怎么点都没反应（最常见：后面的层无条件写同一属性）、位置一件都不显示、网格在但形状不对 →
分诊表正本在 [03 · 症状 → 该查哪里](03_装配与冲突通则.md#三症状--该查哪里)。

> **效果面上有开关、游戏里没反应** → 两类必查：层默认权重为 0 且无人抬权（H3-Eku `Breast`），
> clip 路径被 AAO 删/改名后解析不到（死参数）。四项必查（MA MenuItem、`ClothGroup` 是否在正式场景、
> `3bitInt` 等互斥机制、死参数）→ [互斥机制](60_菜单与动画层/互斥机制.md)。
