#### 为什么冻结：依赖图本身不给选择空间

**三个包同时把 `com.vrchat.avatars` 卡在 3.11 以下**（从各包 `locked` 段的 `dependencies` 直接读的）：
`com.anatawa12.avatar-optimizer` `>=3.7.0 <3.11.0`、`dev.vrlabs.av3manager` `3.2 - 3.10`、
`vrchat.blackstartx.gesture-manager` `>=3.10.4 < 3.11.X`。SDK 升到 3.11 会**同时**打断这三个，
而 SDK 现在就停在 3.10.4 这个天花板上 —— 「用最新 SDK」目前是**空选项**，不是取舍。

其余可升的只是补丁级（核对当天：MA 1.18.1→1.18.7、NDMF 1.14.3→1.14.8、AAO 1.9.16→1.9.18、
VRCFury 1.1414.0→1.1426.0、LLC 2.12.3→2.13.0）。取舍：
- **升** → 收益是「可能修了没遇到的 bug」（推测）；代价是硬闸「一次只落一个改动」失效（[步骤模板与硬闸](01_自动化执行与并行/步骤模板与硬闸.md)）—— 工具链和素材同时变，出问题无法归因（确定，且发生在付费单中途）
- **不升** → 代价是「可能有的修复」晚拿到 —— 到核对那天为止只是推测的损失
- 所以**默认冻结，单子进行中一律不升**；代价的不对称在「中途升级」那一侧

#### 什么时候重核：按事件，不按日历

① 上传被 SDK 拒（游戏更新的硬信号，别靠猜） ② 某个包的 bug **直接卡住流程** ③ 新素材包声明要求更高版本
④ **一单交付完的空档**（例行，代价最低）。重核结论回写基准表；
交付说明里写一句「工程已锁定版本，除非遇到问题不建议升级」（[90](90_交付打包.md)）。

#### 核对时的三个坑

- 预发布版号后缀不统一，除 `-alpha/-beta/-rc/-pre` 还有 **`-pr6`**。判「是不是预发布」一律看**有没有连字符**，
  别枚举后缀 —— 漏一个就把预发布报成最新版（gesture-manager `3.9.9-pr6` 被误报过）
- VCC `Repos/` 下同一个源有多份带哈希的历史快照，要取**并集**，只读最新一份会漏版本
- 16 个 `Packages/` 目录 = 建档点名的 14 个 + 隐式依赖 `com.vrchat.base`、`jp.lilxyzw.avatar-utils`，别把这 2 个当漏项

### 步骤 2 · 解包导素材　🤖

**前置**
- [ ] 步骤 1 通过

**执行**
1. 用解包工具直接解 `.unitypackage`（**不要用 Unity 的导入对话框，也不要拖文件夹**）
2. 工具行为：跳过内容相同的重复项；报告内容不同的冲突项（**保留旧的，让人判**）；
   排除 `.exe/.bat/.cmd/.ps1`

**后置判据**

| 期望 | 怎么读 |
|---|---|
| 冲突项数 == 0，或每条都有处置记录 | 解包报告 |
| 剩余未解开的 `.zip`/`.unitypackage` 数 == 0 | `find` 一遍素材目录 |

**STOP**
- 出现内容不同的同路径冲突 → 交人判，不要自己选一个覆盖

> **为什么不拖文件夹**：`.meta` 没跟着时 Unity 会给文件夹**重新生成 GUID**。
> 硬编码 `AssetDatabase.GUIDToAssetPath("<guid>")` 定位自己目录的插件会解析失败
> → `Instantiate(null)` → 构建时弹模态框中断。
> 症状极具迷惑性：Console 不报缺资源，报错点在插件自己的代码里，**看起来像插件 bug**。

> ⚠ **同商品的几个分包会共用文件夹/材质 GUID**，导入第二个包时 Unity 会搬走第一个包的文件、
> 并静默丢掉同路径资产。**导入动作必须串行**，不能并发。

### 步骤 3 · 完整性五查（只读，几分钟）　🤖

**前置**
- [ ] 步骤 2 通过

**执行**

| 查什么 | 怎么查 |
|---|---|
| 有没有没解开的包 | `find 素材 -name '*.zip' -o -name '*.unitypackage'` |
| 有没有漏公共/材质包 | 文件名含 `material` / `shader` / `common` / `core` / `dlc` |
| 材质是不是变体缺父级 | 数材质文件行数 |
| **一 GUID 多路径（撞车）** | `python 开发工具/通用工具/guid_uniqueness_audit.py <工程>` |
| 断链 GUID | 同上加 `--refs`。索引**必须含 `Assets/` + `Packages/` + `Library/PackageCache/`** |

**后置判据**

| 期望 | 怎么读 |
|---|---|
| 未解开的包 == 0 | 上表第一行 |
| 完整 lilToon 材质 **700+ 行**；只有几十行的是**父级缺失的变体** | 行数统计 |
| **一 GUID 多路径 == 0**（硬判据，非 0 必须修） | 审计工具「判据一」 |
| 断链 GUID 扣掉假阳性后 == 0 | 审计工具「判据二」 + 下面的甄别规则 |

> → [GUID 撞车与修法](20_素材清点导入/GUID撞车与修法.md) —— 厂商升版挪位保留 GUID、配饰包自带 lilToon 兜底副本两起实测；共用资产边界是「厂商」不是「商品」；修法要回源包取原 GUID。

**假阳性甄别**（这些不是缺陷，不要修）
- 落在 lilToon 可选槽的：`_OutlineTex` `_BumpMap` `_EmissionBlendMask`
  `_ReflectionColorTex` `_GlitterColorTex` —— 对应 `_UseXxx` 开关**关着时是惰性的**
- `0000000000000000f000000000000000` 是 Unity 内置资源
- ⚠ lilToon 的功能开关是 **`_UseXxx`，不是 `_XxxBlend`** ——
  `_MatCapBlend: 1` 但 `_UseMatCap: 0` 时那层根本不生效

### 步骤 4 · 建素材应用表　🤖

**前置**
- [ ] 步骤 3 通过

**执行**
1. 跑应用表生成工具，产出 `_素材应用表.md`
2. 前六列机器生成；**最后一列「用途 / 不用的原因」手写**，重跑按商品号回填不会被冲掉

**后置判据**

| 期望 | 怎么读 |
|---|---|
| 表的行数 == 素材包里的商品数 | 两个数对比 |
| **判据先过反查**：确定用了的 > 0、确定没用的 == 0 | 见 [实施坑](20_素材清点导入/实施坑.md) 第二节 |

**STOP**
- 反查两头对不上 → 判据是坏的，**先修判据再出数**，不要拿这张表做决定

- 生成命令：`python 开发工具/通用工具/pack_usage.py <工程目录> <素材包目录>`。
- 区分**「未导入」和「导入了但 0 引用」**：「未导入」可能是包本身缺文件（有的 Booth 目录里只有商品图、没有本体），**「导入了但 0 引用」才是真漏用**。

### 「不用」必须写原因，且只有三类合格

1. 不支持这个素体（**列出包里有哪些素体版**）
2. 与已装的东西功能重叠（**点名是哪个**）
3. 客户明确不要

写不出原因，就是漏了。

> 为什么要有这张表：素材包动辄二十几个商品，做到一半根本记不住哪个上了、哪个没上、
> 哪个是**故意**没上。交付前才回头数，就会出现「客户买了但压根没用」——
> 实测漏过一个 203 张贴图的眼睛包，而问卷里白纸黑字写着眼睛颜色要求。
