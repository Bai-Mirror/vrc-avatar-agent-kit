# 04 · 施工记录与版本管理　🤖

> **每个工程一份 `_施工记录.md` + 工作区 git。** 作者 2026-09-18 定，属强制准则 6。
> 目的：任何时候接手都能回答「这个工程做到哪、每一步怎么验的、哪一步改坏了能退回去」，不靠模型记性。

## 一、施工记录

**位置**：`<工程根>/_施工记录.md`，一个工程一份。**只追加，不改旧条目**（写错了就追加一条更正）。唯一例外是文件顶部的**状态头**（`<!-- 状态头:BEGIN/END -->` 之间：阶段/最近一步/下一步/未决/不许动），可整块改写，由 `log_step.py` 维护 → [收尾蒸馏与状态头](04_施工记录与版本管理/收尾蒸馏与状态头.md)。

**什么时候写**：每完成一步就写，不攒到收工 ——
改了工程文件、改了素材、跑了测试或审计、用户拍板或手动改了东西、DSH 交回一次派工。

**谁写**：

| 谁动的手 | 谁写 |
|---|---|
| Claude 直接改 | Claude |
| DSH 改工程 | 派工带 `--record <工程>`：DSH 自己追加一条并 `ws_git.py` 提交（09-22 起）；Claude 验收后用 `log_step.py` 追加一条「验收」 |
| 用户在 Unity/Blender 里手动改 | Claude 记一条「用户手动」，写清用户说了什么、改了哪里（不知道就写「未知，待确认」） |

**怎么写**：`python3 开发工具/通用工具/log_step.py <工程> --title "55 狐耳缩放改为 k=0.92" --by Claude --did … --verify … --result ✓ --open 无 [--distill "教训"] [--stage/--next/--pending 更新状态头] [--commit "[简称] 一句话" --paths …]`；`--show` 读状态头与最近 3 条。手写时照下面格式：

```markdown
## 2026-09-18 21:40 · 55 狐耳缩放改为 k=0.92
- 执行：Claude / DSH（会话 session-xxxx）/ 用户手动
- 改了：`Assets/_Work/工程C.unity` 里 `Acc_FoxEar` 的 localScale；`装位报告.md`
- 怎么验：<工具 / 判据 / 读到的数值>，例：DumpBounds 读 AABB 0.305×0.164×0.128 m；agy_panel --fast 0 条指认
- 结果：✓ / ✗ / 未验证（原因）
- 未决：<待拍板、遗留问题；没有写「无」>
```

**判据**：「怎么验」一栏必须是工具输出里读得到的东西；写不出来就把结果写成「未验证」。
**与其他文档的关系**：审计报告、装配报告、状态全表这些是专题产物；施工记录是**时间线索引**，在条目里链接它们，不重抄内容。

## 二、git

- **Unity 新建资产：`.meta` 必须和资产一起提交**（2026-09-20 踩过）：新建 `.anim` 后只提交了 `.anim`，而控制器是按 `.meta` 里的 GUID 引用它的 —— 别人拉下来 Unity 会重算 GUID，引用直接变空。**可查问句**：我这次新建了资产吗？`git status` 里那个同名 `.meta` 提交了没有？（`ws_git.py commit` 给路径时，给**目录**比给单个文件安全；给单文件就得自己把 `.meta` 也列上。）

工作区根 `~/vrc-processing` 是一个 git 仓库（本地，无远端）。

| 进库 | 不进库 |
|---|---|
| `CLAUDE.md`、根目录文档、`.claude/`（钩子）、`开发工具/` 全部文本 | `<客户素材目录>/`、`_下载暂存/`、`_二次创作/`、选材图鉴、定妆照图片 |
| 工程的 `Assets/` `ProjectSettings/` 文本资产（`.unity` `.prefab` `.anim` `.controller` `.mat` `.asset` `.meta` `.cs`）、`Packages/*.json`、工程根的 md/txt/json | `Library/ Temp/ Logs/ obj/ UserSettings/`、`*.csproj *.sln`、VPM 包目录、`ZZZ_GeneratedAssets/`、`Triturbo/*/Generated/`、`_backup/` |
| | 二进制（FBX、贴图、PSD、blend、音频、dll、压缩包）、**单个 > 5 MB 的文件** |

**提交只走一个入口**：

```bash
python3 开发工具/通用工具/ws_git.py commit -m "[工程C] 55 狐耳缩放改为 k=0.92"
```

它会刷新 > 5 MB 的排除表、扫一遍待提交内容里的 API key、再提交。`ws_git.py status` 按工程汇总未提交改动。
提交信息用 `[工程简称] <阶段号> <一句话>`，和施工记录条目标题对得上。**一步一提交**，别把几步混成一次。

**回退**：`git log --oneline -- <工程>/` 找到提交 → `git checkout <提交> -- <路径>`。
⚠ 回退场景、预制体、动画前先关掉 Unity 或确认用户不在编辑，回退后在 Unity 里刷新；
FBX、贴图不在库里，它们靠各工程自己的还原点目录（如 `_30b还原点/`）。

**取舍**：
- 5 MB 线是量出来的：四个工程文本资产共 2.5 GB，其中 63 个 > 5 MB 的文件占 1.27 GB，几乎全是面捕生成网格、BlendShare 数据和厂商 AFK 动画，都能从包重新生成；剩下约 1 GB 的 YAML 入库。
  调高会让仓库膨胀、`git status` 变慢；调低会漏掉大场景。**如果哪天主场景超过 5 MB 被排除了，要单独处理，别整体调线。**
  **已单独处理（09-22）**：`<工程>/Assets/_Work/<名>.unity`（工程主场景）白名单上限 32 MB（`ws_git.py` 的 `MAIN_SCENE`/`SCENE_LIMIT`，pre-commit 同规则；625cd03f）。起因：工程B拆两个头像后主场景 6.28 MB，被 `refresh_excludes()` `git rm --cached` 移出版本库。**可查问句**：提交输出里有没有主场景出现在「排除的大文件」里？有就说明超了 32 MB 或不在 `_Work/` 下。
- VPM 包不入库：版本已冻结在 `vpm-manifest.json`，`vrc-get resolve` 能还原。代价是对 VPM 包的本地改动（例：lilToon asmdef 的 `autoReferenced`）不受版本管理，**这类改动要写进施工记录**。

- 脚本解析 git 输出（`git log --name-only`、`diff --name-only`）一律自带 `-c core.quotepath=false`：中文路径默认被转成 `\346\...`，不能依赖本仓库的本地配置（AZ 的 replay.py 在干净克隆里匹配不上路径）。

## 三、强制机制（为什么「必须写」不靠自觉）

| 机制 | 在哪 | 做什么 |
|---|---|---|
| 强制准则原文 | `CLAUDE.md` 的「强制准则」段 | 会话开头加载；**改准则只改这一处** |
| 注入钩子 | `.claude/hooks/rules-inject.js` | 每次用户发消息注入一遍准则；连续调用工具每 25 次再注入一遍；记录看图与 agy 调用的时间 |
| 收尾闸口 | `.claude/hooks/stop-gate.js` | 结束回合前挡一次：工程有改动但施工记录没更新 / 改动未提交 / 看图后没送 agy / 回复以问句结尾 |
| 派工闸口 | `.claude/hooks/delegate-check.js` | 写 `开发工具/通用工具/` 时提醒先考虑派 DSH |
| git 兜底 | `开发工具/通用工具/git-hooks/pre-commit` | 拦 > 5 MB 文件与疑似 API key |
| DSH 侧 | `~/.dsh/skills/vrchat-avatar-sop.md` | DSH 读不到 CLAUDE.md，适用的准则抄在它的技能文件里 |

钩子是启发式的：闸口只挡一次（`stop_hook_active`），被挡后按提示补救或在回复里说明例外即可。

- **时间戳只来自时钟**：条目一律用 `log_step.py` 写（它自己取时间、写后回读、`--commit` 一步提交）；手写时先单独跑 `date +%H:%M` 看到数字再抄。四轮共 20 余条「未来时间」事故的经过 → [收尾蒸馏与状态头 §事故](04_施工记录与版本管理/收尾蒸馏与状态头.md)。

- **写记录与提交时的具体事故**（heredoc 里 `%` 格式化把正文撑爆导致写入失败却照样提交、新建目录漏掉目录自身的 `.meta`）另开一页：[落盘与提交的坑](04_施工记录与版本管理/落盘与提交的坑.md)。
