## 结构（硬要求）

```
交付_COMM-<订单号>/
└─ COMM-<订单号>_<客户名>_交付.zip        ← 文件夹里不留任何散件
    ├─ COMM-<订单号>_<客户名>_工程.zip
    ├─ COMM-<订单号>_<客户名>_素材.zip     内含 COMM-..._素材/ + _追加素材（非客户自备）/
    ├─ _追加素材（非客户自备）/             总包这层也放一份（含 来源说明.txt）
    └─ 交付说明.txt
```

- **「整个交付文件夹压成一个 zip」是硬要求** —— 追加素材、说明都不许留在 zip 外面
- `_追加素材/` 在总包层和 `素材.zip` 内各有一份，**这个重复是刻意的**，别为省空间删掉
- 总包必须用 **store**（`7z a -tzip -mx0`）—— 内层已经是 zip，再压纯耗 CPU
- 校验：**总包大小 ≈ 三个成员之和 + 几百字节头**

## 素材包

- 收齐**「客户素材目录之外」的原始 zip** —— 一半素材可能来自 Downloads、别的单的素材目录、或 本机 素材库
- 用**硬链接**集中，不占额外空间
- **客户素材包里只放客户自备的**；自己找的一律进 `_追加素材（非客户自备）/`
- `来源说明.txt` 逐个写：用途 + 对应的 `Assets/` 路径 + 大小（MiB）；没留原始包的只写清单
- **VPM 包不算追加素材**（GoGoLoco、Light Limit Changer 等）—— 随 `Packages/` 走、VCC 自动还原，
  写进「工具链版本」一节就行

## 打包前两项判据（触发：95 终审前）

- **定妆照必须是交付穿搭**：至少拍实际交付的那套；生成记录里查得到服装档位 = 交付穿搭，对不上先补拍（`_定妆照/` 会混多次运行）。详见 [70 回归](70_回归测试.md)「穿衣命中」。
- **能编译 ≠ 没缺陷**：`MissingScript`、`InternalErrorShader` 与断链都不影响编译，却让客户洋红/静默失效。五项判据 + 清理 → [缺失项判据与清理](90_交付打包/缺失项判据与清理.md)。

## 交付说明

两档：
- **当单做完就写完整工作报告** —— 做了什么 / 必须知道的几件事 / 打开工程后
- **事后补归档的只写归档说明** —— 包内容 / 工程里装了什么 / 工具链版本 / 打开工程后，
  **不编造当时的设计意图**

至少要覆盖：
1. 附赠的付费资产是哪些
2. **性能评级为什么是 VeryPoor**（见 [80](80_性能优化.md)）
3. 有哪些功能因取舍而失效
4. **此前给过客户的错误判断的更正**
5. **工程已锁定版本**（照 [`../_工具链基准.md`](../_工具链基准.md)），除非遇到问题不建议升级（理由见 [20](20_素材清点导入.md) 基线工具链）

格式：txt 一律 UTF-8 无 BOM、LF 换行、框线排版。
